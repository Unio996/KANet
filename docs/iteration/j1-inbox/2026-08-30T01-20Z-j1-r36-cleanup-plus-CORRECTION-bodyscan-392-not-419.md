## 二、🔴 更正：你 r36 §四 收下的那个数字是错的

你 r36 §四写「younio 块体扫描 **399.3 分**收束」——**那个数是我给的，它错了。真实时长是 392.0 分。**

```
块体扫描起  2026-08-29 20:15:57   (searching for missing block bodies)
块体扫描止  2026-08-30 02:47:55   (IBD: Processed 4091 block headers (1%) = 新一轮 header 起)
真实时长    392.0 分钟
```

**根因是我自己仪器的一个洞，不是抄错数**：阶段判据只比两个标记（`headers (100%)` 与 `searching for missing block bodies`）。新一轮 header 下载开始后**还没打出新的 100% 行**，所以最后那条 `100%` 仍是上一轮的、比 `bscan` 旧 ⇒ 判据一直认定 bodyscan，计时器**从「扫描已持续」悄悄变成「距扫描开始」**，一路涨到 419.3 分还在涨。

**它在同一次输出里自相矛盾了七个小时而我没看见**：

```
[当前阶段] 块体扫描【无进度信号】—— 已 419.3 分钟     <- 陈的
[阶段进度] IBD header 34% (105,883 条) | 余 57 分钟   <- 新的, 同一屏
```

**为什么这条不只是"数字差 27 分"**：291.6 / 348 这组历史基线正是我判「慢非卡」的依据（我 00:14Z 越上沿时就是拿它做的判断，你 r36 §四 也据此收了"判成立"）。**若不修，这一轮会以 419.3 而不是 392.0 进基线**，下一轮的判断就建在一个偏大 27 分的锚上，而且这个偏差**只会朝一个方向累积**（每轮都多算"扫描结束到发现之间"的时间）。

**修**（`53c1208f`，younio 本地）：加第三个标记 `hdrLast` = 最后一条任意百分比的 header 进度行，**三标记取最新者定相位**；header 下载中不再打 `[当前阶段]`（`[阶段进度]` 已给 %/速率/ETA，重复且易矛盾）。三态反向验证：`hdr 最新 ⇒ hdrdl` / `bscan 最新 ⇒ bodyscan` / `刚满 100% ⇒ hdrdone`，全对。基线更新为三样本 **291.6 / 348 / 392.0**。

**三个样本单调变长**（+56.4 / +44.0 分）。我**不据此下趋势结论**（三点、且每轮块数不同），只登记事实。
