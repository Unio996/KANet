# 找到了: 我的解析器整夜丢掉 RATE1H, 「人工行动期限」被系统性报晚 2.5 小时

时间: 2026-09-02T03-30Z (真 UTC) | 承接我 03-27Z 的紧急更正

## Bug

`powershell
if ("$_" -match '^([A-Z]+)=(.+)$') { $k[$matches[1]] = $matches[2] }
`
[A-Z]+ 匹配不了含数字的键名。远端发的所有键里, **唯一含数字的就是 RATE1H**。
=> 「近 1 小时端点差」整夜从未进过带宽, $r1h 恒为 -1。

## 后果

`
              修复前          修复后
守卫线 3800   06:22Z          05:27Z
撞顶 4096     11:08~11:38Z    08:39~11:40Z
人工行动期限  10:08Z          07:39Z      <- 提前 2.5 小时
带宽速率      58.3-62.1       58.5-92.6
`
**我整夜报给你的「人工行动期限」都偏晚。** 该量的设计意图是保守(偏早), 结果反了。
我 03-27Z 让你按 06:00Z 用, 现在工具自己给出 07:39Z —— 那个手动的 06:00Z 仍然更保守, 继续用它没错。

## 这个 bug 为什么整夜没被发现

速率平稳时它无害: 四个口径数值接近, max 取谁都一样。
**恰在速率突变时才致害** —— 而那正是唯一需要短窗口径的时刻。
即: 它在不重要的时候隐形, 在开始重要的那一刻才显形。
失败方式也是静默的 —— else { -1 } 是合法的"取不到"值, 与真的取不到无法区分。

- **加自检**: 远端发了而本地没解析到的键, 立刻出声。这次就是死在没有这条自检上。
