## 你三问的裁定（作为设计 v0.1 的框架，不是终稿）

1. **值得起票：是。** 你出设计 v0.1，一页纸起，形状按你对照表的四点（合作即 UTXO / 期数链防重领 / 先承诺后揭示 / 不靠索引器）；复用现有件：`ShardLeaf_direct` 自续约 + `validateOutputState`、`rootclose_tmpl_hash` 全模板 pin、`packages/fee-split` 规则哈希承诺、P1 事实声明 + 委员会 attest 作层 1。**不新造原语**——写 `.sil` 前按 CLAUDE.md 接位 SOP 第 5 步先查 silverscript `DECL.md` / `TUTORIAL.md` 确认可用原语，不凭印象判"做不了"。
2. **盐化与揭示**：
   - 每份合作一个 32 字节随机盐；承诺 = `blake2b(domain_tag ‖ 条款规范编码 ‖ salt)`（用链上已有的 blake2b，不引 blake3；`domain_tag` 固定串防跨用途碰撞）。条款规范编码要有确定性序列化规则（字段顺序、整数宽度）写死在设计里。
   - 盐由品牌方与创作者各持一份，console 加密托管第三份（丢盐 = 永远揭示不了 = 钱退回品牌，所以三份）。
   - **揭示时机**：首次释放时揭示条款与盐。与 dotk 不同，我们的 deed 从注资起就归属确定、`reveal` 入口只有合作双方签名能调，所以**没有内存池抢注问题**，揭示只涉及保密期长短；设计里写明"揭示后条款公开"是接受的，若 Owner 要求条款永不公开，改为每期只揭示当期释放额的 Merkle 证明——这条列为开放点，不在 v0.1 做。
3. **第一版必须写死的退出条款**（不可变的代价，全部复用现有 escape / refund / deadline gate 手法）：
   - 期满未领：过 deadline 未释放的期数余额退回品牌方（refund gate）。
   - 标的失效（视频下架 / 账号消失）：委员会 attest 后停止后续释放、余额退回品牌方。
   - 争议期：每期释放前有固定窗口（如 24h），品牌方可凭签名挂起该期，进入委员会裁定。
   - 双方签名提前终止：按已释放期数结清，余额退回。
   - 事实来源缺席：连续 N 期无有效 attest，退回品牌方（防 oracle 消失锁死资金）。
   - 版本线：每个合约版本独立一条线，老金库按老规则走完，升级不回溯（你已写，照录）。
