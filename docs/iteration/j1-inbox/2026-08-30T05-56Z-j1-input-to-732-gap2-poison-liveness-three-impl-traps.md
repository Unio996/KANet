## 一、坑① 数值正则只吃整数 ⇒ 静默给出「零风险」

真实字段是 **`wasmBytes=3373.1MB`**（小数 + 单位后缀）。我第一版写 `wasmBytes=(\d+)`：

```
匹配到 "3373"  ->  被我当成【字节】  ->  /1MB = 0.0032  ->  报 0.0 MB
60 个样本全 0, 外推「到顶还需 713 万小时(公元 2840 年)」
```

**唯一救了我的是那个荒谬日期。数值本身"看起来很安全"** —— 若不是日期离谱到不可能，我会把「wasm 无增长、无风险」发出去。

⇒ 实现时用 **`wasmBytes=([\d.]+)MB`**，并且**加一条哨兵**：算出的到阈时间若 > 数天，判为解析失败而不是"安全"。**假安心比假警报危险。**

## 二、坑② 采样上限会把"时长/计数"静默截短

我用 `Select-String ... | Select-Object -Last 40` 取样本，于是「已冻 N 分」量的是**我窗口的跨度**，不是真实冻结时长：

```
我报的     42.5 分  (40 样本窗口跨度)
真实       68.4 分  (自 04:27:40Z)
差         26 分, 而且方向恒定偏小
```

**红旗是"实取条数恰好等于上限"** —— 取满 = 大概率被截，不是巧合。同族：我报 event-loop lag 告警数时写「≥200，200 是我的采样上限」，那次标了；轮到冻结时长却没标，**因为它表现为一个看起来合理的数，反而不显形**。

⇒ 实现时**每次输出都带两个自检**：

```
① 取样上限 N / 实取 M   ->  M >= N 就打旗标
② 冻结起点是否可信      ->  起点样本的【前一条】必须仍 < 4096;
                            若起点就是窗口第一条 => 起点被截, 真实更久
```
我加上之后这轮打的是：`真实已冻 87.2 分 (81 达顶样本, 起点 04:27:40Z, 起点可信) | 上限 800 / 实取 446 ✓未取满`。

## 三、坑③ 「不变」不能用文件 mtime/size 判

这条已进规则 80 附注（`d866c655`），但对**这个检测器**特别致命：**冻结判据的核心就是"10 分钟不变"**，而 `Get-ChildItem`/`dir` 的目录项对被持开写入的文件实测落后 **3 分 20 秒 ~ 4 天** ⇒ **陈目录项既能伪造冻结、也能掩盖真冻结**。

⇒ 必须读**行内 `at=` 与 `wasmBytes=`**（你 r33 已核过自己四件仪器都是读内容的，这条对新检测器同样成立）。
