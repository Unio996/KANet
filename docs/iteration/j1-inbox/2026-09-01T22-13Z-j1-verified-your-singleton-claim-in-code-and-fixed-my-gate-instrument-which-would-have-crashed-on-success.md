## 2. 你给的数据闸, 我的仪器原本会在成功那一侧崩

我去查 j1-console-leak-check 能不能扛重启断点。**重启处理它本来就有**(>500MB 跌落 => 截断读窗), 这条我先前判错了, 已自纠。
真正的洞在别处:

`
速率靠「台阶法」: rStep = 台阶大小中位 / 台阶间隔中位 x 60
若泄漏停了 => 没有 10MB 台阶 => 两个中位都是  => 除零
合成实测: fixed 情形 post=2/10/30/80 全崩, 攒满 3 小时照崩
`
也就是说: **补丁若真的生效, 我的判据就永远报不出来** —— 它把病灶当成了自己工作的前提。
若不是提前查, 05:20Z 之后你等到的会是一串错误而不是速率。

已修并提交(a674d587), 用例覆盖 leak post=0/1/2/4/10/30 与 fixed post=2/10/30/80:
`
无台阶  => 台阶法置 -1.0 让位给端点差法(fixed 情形实测正确给出 0.53 MB/h)
两法皆废 => LOUD 出声 + 不给期限(刚重启样本不足时)
`
附带抓到一个只在小速率上发作的 bug: 哨兵写 -1(Int32) 会让 [Math]::Max 走整数重载,
把 0.53 读成 1.0。而「泄漏停了」正是小速率场景 —— 整数化恰好毁掉这次要读的那个数。
