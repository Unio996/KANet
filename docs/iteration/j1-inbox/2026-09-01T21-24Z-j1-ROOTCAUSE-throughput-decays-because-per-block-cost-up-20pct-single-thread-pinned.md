# 吞吐在衰减: 每块成本 +20%, 单线程钉死 —— 所有 lag 收敛 ETA 系统性偏乐观

时间: 2026-09-01T21-24Z (真 UTC, 由 Get-Date 生成)
起因: Owner 09-01 驳回 6.6 天 ETA ——「肯定遇到巨大瓶颈, 思路和方法可能搞错了」。这份是归因结论。

## 1. 结论

不是某处卡住。是**每块的处理成本随链变深在上涨, 而干活的只有一个线程**, 所以吞吐单调衰减。
任何假定吞吐恒定的 READY ETA 都偏乐观, 且会随时间继续往后滑 —— 这解释了 ETA 为什么一直在漂。

给出同方向、同量级(+20% 左右)的结论。

用法: 现有 ETA 当作**下界**, 不要当估计值; 换窗口重算时必须带窗口标签。

## 4. 已排除的竞争解释: peers 不是限流因子

心跳行里 `peers=1 (近 20 轮中位 4)` 看着像退化, 实际相反:

- peers=1 (n=360) 吞吐中位 56,336  <- 最高
- peers=4 (n=145) 吞吐中位 55,743

## 5. 顺带修正我自己的一个说法

我此前把「密度模型」讲成对 lag 收敛的**预测**。它不是。
99% 的心跳配对里 `Δblk == Δdaa`, 代入后 `吞吐/密度 - 60 ≡ -Δlag/Δ墙钟x60` 是**恒等式**。
模型零独立预测力; 它唯一的价值是把收敛拆成吞吐与密度两个可分别观测的量 —— 而这次正是靠这个拆分
才看出「占比升到 92% 是分母(吞吐)塌了, 不是分子(密度)涨了」。
另: tick 里的密度探针按构造滞后约 47 分钟, 心跳可直接算零延迟瞬时密度。
