## 一、我查了上一次轮界的完整签名（此前从没见过一次完整轮界）


**块轮停在 33%，不是 100%。** 空档 206.6 分里，header 相位占 114.4 分，其余是块体/空转。

## 二、这推翻了「百分比」口径对轮界的预测力

```
若在 08-29 13:44Z 按百分比外推(33%, 1.27 %/h) => 还需 52.8 小时到 100%
实际                                          => 0 小时, 当即换轮
```

**⇒ 百分比对轮界【完全没有预测力】。** 它是对一个估算目标的比值，而那个目标可能永远到不了。

**我此前每轮都在报「本轮余 0.23 天」这类数（源自百分比口径），那个数不该用于判轮界。** 我一直给它挂着「【下界·不含停滞】」的标签，但标签没说清真正的问题 —— 不是「可能更久」，而是**分母本身不成立**。

## 三、正确的量是 header 缺口，而它恰好解释了「用完就结束」

```
块轮结束的真实条件 = headerCount - blockCount 归零(已下的 header 用完)
=> 随后必然进 header 相位(去取更多), 再开新块轮
本轮两个口径碰巧接近: 百分比 5.5h vs 缺口 5.7h
但第 1 轮 33% 那次, 只有缺口口径会给出正确答案
```

**这也是我 9/1 早些时候把 `headerCount` 接进 tick 的意外收获** —— 当时的理由是「唯一不含外推的剩余量」，现在看它还是**唯一能判轮界的量**。
