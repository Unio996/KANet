## §3 设计：签发口

### §3.1 谁能要挑战（最要紧的一格）

**Track A 内部 = 与注册端点同姿态**：loopback 可达，不进 external-gateway 白名单。

🔴 **但"loopback 即可信"不是本设计新增的假设，是继承的** —— 与 `transfer` / `mnemonic-reveal` 同档
（§10 已把这条记成继承的信任边界）。本设计**不改善也不恶化**它。

⇒ 因此签发口**不做调用方鉴权**（做了也是假的：同机任何能调 Console 的人都过得去），
而是靠**下面三条把"能要挑战"这件事本身变得没有价值**。

### §3.2 挑战里绑什么 —— 🔴 我建议**只绑最小集**，并说明为什么

今天 PoP 的被签字节由 `buildPopPayload({rootFingerprint, identityIndex, relayId, challenge})` 构造，
而 `rootFingerprint` / `identityIndex` / `relayId` 全部来自**提交方的 submission**（服务端对 rootXpub 重算 fp），
**不来自挑战行**。

⇒ 于是**挑战今天是一个纯粹的一次性 nonce，不绑定任何主体**。

**这意味着什么（如实写，不粉饰）**：
- ✅ 它**不削弱**安全性：伪造仍需 identity 私钥签名，挑战不给攻击者任何签名能力。
- 🔴 但它意味着**挑战是可互换的**：为 relay A 签发的挑战，可被控制 relay B 私钥的人用来注册 B。
  ⇒ 「谁要的挑战」与「谁用掉的挑战」**没有关联**，审计上是断的。

**两个选项**：

| | (i) 保持纯 nonce（不绑主体） | (ii) 签发时绑 `relay_id` |
|---|---|---|
| 改动 | 零 schema 改动 | 需加列 + 迁移 + 验证侧核对 |
| 审计 | 🔴 要不到"谁要的挑战" | ✅ 可追 |
| 与 v0.7 §4 一致性 | 弱（那边绑 `broker_address`） | 强 |
| 风险 | 不引入新风险，但**保留一个断的审计链** | 需保证"绑的值 ≠ 生效值"不复发（v0.7 §2-bis B3 踩过） |

🔵 **我建议 (ii)，但不自拍** —— 理由：v0.7 §4 明确要求"用该行落库的字段**原样重建**被签字节，
**不重新猜测/拼凑客户端应该签了什么**"。§6-1 今天正是从 submission 重建的，与那条相反。
🔴 **但 (ii) 会踩到 v0.7 §2-bis B3 那个教训**（绑定值≠生效值），落地时必须让**验证侧从挑战行读 relay_id
并与 submission 比对**，而不是只是"多存一列"。⇒ 🏛 **已终裁（Bettor 2026-08-19）**：当前 scope 用 **(i) 纯 nonce**（零迁移；(ii) 也不修 §10、只加审计且要踩 B3，当前低值）；
**(ii) 绑定 = 北极星前的审计增强**，落地时按 B3 纪律（验证侧必须真去读挑战行比对，不能只是多存一列）。
🔴 我原先倾向 (ii) 的理由是「与 v0.7 一致」——**那是一条一致性论证，而一致性论证不检验前提**（07-26 §五 原话）。
(ii) 同样挡不住 §5-0 那个攻击（攻击者为他想占的 relay_id 申请挑战即可）⇒ 它买到的只有审计线。**我已改站 (i)-当前 / (ii)-北极星，理由换成北极星下这条记录会被外部当真，那时审计线必须接上。**

### §3.3 TTL

沿用 v0.7 §4 的量级判断：**5 分钟**（人工签名留出时间）。
🔵 §6-1 的 schema **已经**是 `expires_at NOT NULL` ⇒ 无迁移需求，只是签发时填值。

### §3.4 过期清理

未消费且已过期的行需要定期清理，否则表无限增长。
🔵 v197 已建的部分索引 `idx_u1_challenge_unused (expires_at) WHERE used_at IS NULL` **正好服务这件事** ——
迁移注释里写的就是「仅巡检不参与正确性」，这就是那个巡检。
🔴 **清理绝不能删【已消费】的行**：那会让"这个挑战存在过没有"变得不可审计（v0.7 §4 同款理由）。

## §4 预注册验收判据（事后不加项）

1. **签发口只在 loopback**：external-gateway 白名单里**不出现**该路由（可 grep 的负面判据 + 阳性对照）。
2. **签发是唯一写入方**：全仓对 `u1_identity_challenge` 的 `INSERT` 只有这一处（grep 计数）。
3. **TTL 真写进去**：签发出的行 `expires_at` = 签发时刻 + 5min（不接受调用方给的时间 —— 服务端派生不透传）。
4. **fail-closed**：表不存在/写入失败 ⇒ 明确失败，**绝不返回一个看起来能用的挑战**。
5. **一次性仍成立**：签发 → 消费 → 重放，第二次必拒（§6-1 E4 已在 live 证过，签发接上后重跑）。
6. **清理不碰已消费行**：造一条已消费 + 一条过期未消费，跑清理 ⇒ 只删后者（阴阳两臂）。
7. **变异清单**：以上每条闸各一格，且**首格是 no-op 探针**（`cc41bcee` 已实装，必须 MISSED 否则整轮作废）。
8. 🔴 **一条否定判据**：文案里**不得**把"签发口建好"写成"外部用户可以注册了" ——
   Track A 的墙仍在，外部无网络路径可达。**能注册 ≠ 对外开放。**

## §5 明列空白（不假装覆盖）

### 🔴🔴 §5-0 本设计与 §10 抢注的关系 —— **不是并列的两个洞，是因果**（NWT 2026-08-19 红队指出，我核过成立，原稿写轻了）

原稿把这条放在空白清单里并列写作「签发口不解决 §10 抢注」。**那读起来像"两个各自未修的洞"，而真实关系是因果的**：

- **今天** `u1_identity_challenge` **生产零写入方**（实核：全仓 `INSERT` 只在测试/验收/E2E 脚本里）
  ⇒ 攻击者**拿不到活挑战** ⇒ `verifyRegistrationPop`（`u1-registration-pop.mjs:88-90`）在
  `CHALLENGE_UNKNOWN`「challenge was not issued by this server」那步就先拒
  ⇒ **§10 那个抢注攻击今天在实操上打不通** —— 不是因为它不成立（它成立，§10 已证），
  是因为**签发口不存在这件事，意外地充当了一道人工闸**。
- **而本设计要做的，恰恰是把那道意外的闸拆掉。** 签发口一旦建成且只要求 loopback 可达（§3.1 明写不做假鉴权），
  任何本机能摸到 Console 的进程即可**全自动、零人工介入**地：取挑战 → 自己生成一套钥 → 占某个 `relay_id` 的槽。

🔴 **必须写清楚的两条推论**：

1. **「把 §10 排在签发口之前」不能关掉这个窗口。**
   §10 自己的 §3 已经证过：relay attestation 对**本机 Console 调用方恒真**（发起 IPC 的是 Console 自己）。
   §10 挡的是**跨 IPC 域的外部提交方**，而这个窗口放进来的恰恰是**本机进程**。
   ⇒ 排期时不得把 §10 当作本窗口的缓解手段。

2. **严重度校准（NWT 与 J2 收敛的读法）**：能摸到 loopback Console 的本机进程，
   **今天已经能 `/api/relay/:id/transfer` 转走任意 relay 的钱、能 `/relays/:id/mnemonic` 取助记词**
   ⇒ 它已有**严格更强**的能力，本窗口**不新增权限档次**，严重度排在 transfer / mnemonic-reveal **之后**。
   🔴 **但有一处真的不同**：转账是**一次性动作**，而注册写下的是一条 `relay_id` 主键的**持久记录**，
   它**活得比那个进程久**，且北极星下会被外部方读作「X 确实控制 X」。
   ⇒ 本窗口的风险不在"能干多大坏事"，在**"留下一条会被别人当真的持久断言"**。

### 🔴🔴 §5-0-bis 部署闸（Bettor 2026-08-19 终裁 · 核心）

> **签发口【设计】现在推进；签发口【部署上线】绑死在 §10 之后。**
> 理由就是上面那条因果：**部署它 = 开 §10 抢注窗**。

**实现层方向（已定）**：签发口应要求 **relay-key-control-at-issuance** ——
即签发挑战这一步本身要求申请方证明其控制所声称 relay 的钥，而不是"谁都能要一条挑战"。

🔵 **注意它与 §10 的分工，别读混**：
- §10 的 attestation 放在**注册提交**那一步 ⇒ 对本机 Console 调用方**恒真**（§10 §3 已证），挡不住本窗口；
- 而放在**签发**这一步的 relay-key-control，改变的是**谁能拿到挑战**这件事本身 ——
  它把"零成本自动化取挑战"变成"必须先证明控钥"。
- ⇒ 两者**不是同一道闸的两个位置**，是两个不同的闸。**先做 §10 不能替代它**（我上一版把这两件事的关系说反了一半，已更正）。

🔴 **因此本稿的状态要写死**：
**scope 已过审（NWT PASS + Bettor 终裁），实现层设计可继续，但任何"部署/上线"字样都不在授权内。**
