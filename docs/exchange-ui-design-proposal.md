# KANet Exchange UI 设计方案

> 状态：建议草案，待讨论
> 日期：2026-04-10
> 基于：旧系统 trading.eta 经验 + Exchange 双边市场特性

---

## 一、设计原则

**1. 引导决策，不只是展示数据**
用户看到报价的第一秒就要知道"这划不划算"，不需要自己去查市价。

**2. 视角分离**
同一笔交易，maker 和 taker 看到不同的信息重点。陌生人的单、我挂的单、我接的单——三种卡片形态。

**3. 进度可见**
接单后每一步都有状态反馈，用户不需要猜系统在干什么。

**4. 借鉴旧系统，不重新发明**
trading.eta 的状态卡片、approval-card、status-dot、时间戳显示——直接复用，保持一致的用户体验。

## 二、页面整体布局

```
┌─────────────────────────────────────────────────────────┐
│  Exchange                          [+ 发布挂单]         │
├─────────────────────────────────────────────────────────┤
│  [市场] [我的挂单] [我的交易] [历史]                     │
├─────────────────────────────────────────────────────────┤
│  市场概览栏                                              │
│  KAS/USDT  $0.0332  ▲0.5%    最近成交: 10 KAS @$0.0330 │
├─────────────────────────────────────────────────────────┤
│  挂单列表 / 交易详情                                     │
└─────────────────────────────────────────────────────────┘
```

**四个 Tab：**

| Tab | 内容 | 主要用户 |
|-----|------|---------|
| 市场 | 所有 open 挂单，按价格排序 | 想买/卖的人 |
| 我的挂单 | 我发布的单（含进行中） | maker |
| 我的交易 | 我接的单（含进行中） | taker |
| 历史 | 已完成/取消/过期 | 复盘 |

## 三、三种 Offer 卡片形态

### 形态 A：市场挂单卡（陌生人的单）

```
┌─────────────────────────────────────────────────────────┐
│  SELL  100 KAS  →  3.32 USDT                           │
│                                                         │
│  单价 $0.0332    ▼ 比市价低 0.3% ✅                    │
│                                                         │
│  接受付款：[BNB] [ETH]                                  │
│  挂单方：kaspa:qq...ab12  ★★★★☆  成交 47 笔            │
│  剩余：23 分钟                                          │
│                                          [接单]         │
└─────────────────────────────────────────────────────────┘
```

**关键信息：**
- 价格比市价高/低的百分比（最重要）
- 挂单方信誉（历史成交笔数 + dispute 率）
- 支持的付款链
- 有效期倒计时

**颜色规则：**
- 比市价低 → 绿色 ✅（对买家有利）
- 比市价高 → 黄色 ⚠（需要考虑）
- 高出超过 2% → 红色（明显不划算）

## 四、接单流程（Modal）

点击"接单"后弹出确认框，借鉴旧系统 approval-card 设计：

```
┌─────────────────────────────────────────────┐
│  确认接单                                    │
│                                             │
│  你将购买：100 KAS                          │
│  你将支付：3.32 USDT                        │
│  参考市价：$0.0332（当前价）                 │
│  你的成本：$0.0332/KAS  ✅ 与市价持平       │
│                                             │
│  选择付款链：                               │
│  [● BNB]  [○ ETH]                          │
│                                             │
│  付款地址：0x9477...fBdb                    │
│  （系统将自动从你的 BNB 钱包付款）           │
│                                             │
│  钱包余额：5.21 USDT  ✅ 余额充足           │
│                                             │
│  ┌─────────────┐  ┌─────────────┐          │
│  │   取消      │  │  确认接单   │          │
│  └─────────────┘  └─────────────┘          │
└─────────────────────────────────────────────┘
```

**关键设计：**
- 显示钱包余额是否充足（不够则禁用确认按钮 + 提示）
- 确认前展示完整信息，没有隐藏条款
- 选链后实时更新付款地址
- "系统将自动付款"明确告知用户不需要手动操作

## 五、市场概览栏

常驻在列表上方，实时数据：

```
┌─────────────────────────────────────────────────────────┐
│  KAS/USDT  $0.0332  ▲0.5%  │  24h 成交: 1,240 KAS     │
│  最优卖价: $0.0330 (-0.6%)  │  最优买价: $0.0334 (+0.6%)│
│  活跃挂单: 8 笔              │  最近成交: 2 分钟前       │
└─────────────────────────────────────────────────────────┘
```

数据来源：
- 实时价格：MEXC/Gate API（已有）
- 成交历史：`chain_events.exchange_completed`（已有）
- 活跃挂单：`exchange_offers WHERE status=open`（已有）

## 六、信誉展示设计

挂单方信誉从 `chain_events` 统计，不需要新表：

```javascript
// 统计逻辑
SELECT
  COUNT(*) FILTER (WHERE event_type = 'exchange_completed') as completed_count,
  COUNT(*) FILTER (WHERE event_type = 'exchange_disputed') as dispute_count,
  SUM(JSON_EXTRACT(payload, '$.give_amount')) as total_volume
FROM chain_events
WHERE agent_address = ?
  AND event_type IN ('exchange_completed', 'exchange_disputed')
```

**UI 展示：**
- 0-5 笔：新用户（无星）
- 6-20 笔：★★★
- 21-50 笔：★★★★
- 50+ 笔：★★★★★
- dispute 率 > 10%：⚠ 警告标记

## 八、待讨论的问题

1. **Tab 设计**：四个 Tab 还是用过滤器？用户量少时四个 Tab 会显得空。

2. **价格比较基准**：用 MEXC 实时价还是 24h 均价？实时价波动大，均价更稳定。

3. **信誉系统起步**：新用户没有历史记录，第一笔交易怎么建立信任？是否显示"新用户"标签？

4. **手机端优先级**：现在先做桌面版，还是移动优先设计？

5. **多资产对**：现在只有 KAS/USDT，将来有 KAS/ETH、USDT/USDC 等，市场概览栏怎么扩展？

6. **发布挂单的 UI**：现在的发布表单够用吗？还是需要重新设计（加市价参考、推荐价格区间等）？

## 九、实现优先级建议

**Phase 1（让人能用）：**
- [ ] 三种卡片形态（A/B/C）
- [ ] 价格比市价高/低显示
- [ ] 接单 Modal（含余额检查）
- [ ] 状态步骤条（借鉴旧系统）

**Phase 2（建立信任）：**
- [ ] 市场概览栏
- [ ] 信誉评分展示
- [ ] 成交历史 Tab

**Phase 3（完善体验）：**
- [ ] 手机端适配
- [ ] 多资产对支持
- [ ] 发布挂单优化（推荐价格）
