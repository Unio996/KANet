## 四、🔴 而真正的问题不是"停因是哪个",是【那道唯一实际生效的闸对中文近乎失效】

`mind-manager.js:57-63` 的 `_wordSimilarity`:

```js
const wa = new Set(a.toLowerCase().split(/\s+/).filter(w => w.length > 2));
```

**按空白分词,并丢掉长度 ≤2 的 token。** 一句没有空格的中文 = **1 个 token**。
⇒ 两句中文之间的相似度只可能是 **0% 或 100%** ⇒ **只有逐字完全相同才拦得住。**

实测(逐字复制该函数后跑,强度: ✅ 已实测):

| 输入 | 相似度 | 结果 |
|---|---|---|
| 含空格/数字的结构化文本(**对照臂**,证明函数能算出高分、不是恒 0) | 83% | 放行 |
| 纯中文改述(换词不换意) | **0%** | 放行 |
| 纯中文只改一个字("等你指令"→"候你指令") | **0%** | 放行 |
| 纯中文逐字完全相同 | 100% | 拦 |

分词实况:纯中文一句 → token 数 **1**;含空格一句 → token 数 4。

### ⇒ 推论

**这次能停下来,是因为那条回复恰好带了 `- 持仓:524 KAS` / `- USDT 余额:85` 这类含空格和数字的结构化行**,才凑出多个 token 算出 97%。
**"它跑 17 轮就会停"不是系统的性质,是这两个模型这一次恰好收敛到近似逐字重复的性质。**

🔵 同一个坑昨夜刚记过一遍:**「现在是对的」若依赖内容/数据恰好如此 ⇒ 那是运气,不是断言。**

### 🔴 附:同名函数两个实现,写对的那个在没被调用的路径上

`relay.mjs:61-84` 的 `_wordSimilarity` 做了**中文逐字 + bigram** 分词(对中文是对的);
`mind-manager.js:57-63` 的同名函数只按空白分词(对中文近乎失效)。
**而这次生效的是后者。**
