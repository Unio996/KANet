### 0.1 🔴 而"最自然的修补"比原方案更坏,先把它钉死

> 有人会说:那让 `welcome.eta` 的 fetch 把 secret 带上不就行了?

## 1. 提议的形状:**路由级回环断言**(不是鉴权)

### 1.1 为什么是这个

我前置档的结论是:**承重的防线不是鉴权,是 `HOST` 这一个环境变量**。
⇒ 那么正确的收口不是「补一道鉴权」(会打断 UI,见 §0),而是**把那条隐式的防线变成显式的、写在码里的断言**。
⇒ 🔵 它对应本仓那条:**让危险动作不存在,而不是把机制做复杂**。这里"让它不存在"= 让这两条路由**在非本机来源上根本不存在**。

### 1.2 形状

```
新增一个共享小工具(约 6 行), 作为 preHandler 挂在【这两条路由上】:
  · 取【实际 TCP 对端地址】判断是不是回环
  · 非回环 ⇒ 直接 404(不是 403)
  · 回环   ⇒ 放行, 零改动
```

### 1.3 🔴 承重细节一:必须读 `request.socket.remoteAddress`,**不能**读 `request.ip`

实读 `kasia-console/src/index.js:130`:
```js
const fastify = Fastify({ …, trustProxy: '127.0.0.1' });
```
⇒ `trustProxy` 被 scope 到回环。**后果**:当直接对端是回环时,fastify 会**采信 `X-Forwarded-For`** 来解析 `request.ip`。
⇒ 🔴 **任何能经由本机代理到达的请求,都可以把 `request.ip` 变成它想要的值** ⇒ 用 `request.ip` 做回环判断 = **这道断言可被 XFF 绕过**。
✅ **而 `request.socket.remoteAddress` 是实际 TCP 对端,不受 XFF 影响** —— 它才是那个 binding 值。

🔵 这一格就是 verify-value-source:**checker 必须读那个真正决定事实的值**,而不是一个"看起来是同一件事"的派生值。
⚠️ 实现注意:Node 在双栈下回环可能呈现为 `::1` / `::ffff:127.0.0.1` / `127.0.0.1` **三种写法**,判断必须三种都覆盖(只判 `'127.0.0.1'` 会把本机 IPv6 请求误杀)。

### 1.4 承重细节二:非回环返回 **404** 而不是 403

照仓里已有先例(`external-gateway` 那条已焊死的原则):**白名单外的路由是「连不上」而不是「被拒」**。
⇒ 403 会确认"这条路由存在,只是你没权限";404 什么都不确认。
⇒ 且它与本仓刚焊进 gateway 注释的那条一致,不新造口径。

## 2. 🔴 这个改动**不是**什么(先说边界,免得被读成鉴权)

```
❌ 它不认证【谁】在调 —— 本机上任何进程仍然可以建 relay / 铸钱包
❌ 它不改变 relay_nodes 是"本机可信表"这个性质
✅ 它做的只有一件事: 把「今天靠 HOST 绑回环」这条【隐式的、写在配置里的】防线,
   变成【显式的、写在码里的】断言 —— 于是哪天 HOST 变成 0.0.0.0,
   这两条路由不会跟着一起暴露出去
```
🔴 **验收时不许把它读成"这两条路由已加固/已鉴权"。** 它是**收窄暴露面**,不是**加认证**。

## 3. 影响面(逐个调用方实核,不是"应该没事")

| 调用方 | 来源 | 改动后 |
|---|---|---|
| `relays.eta:472` 表单 | 浏览器 → 本机 :3200 | ✅ 回环 ⇒ 放行,零感知 |
| `welcome.eta:451` fetch | 浏览器 → 本机 :3200 | ✅ 回环 ⇒ 放行,零感知 |
| `scripts/_onboard-trader-m.mjs:90` | 本机脚本 | ✅ 回环 ⇒ 放行,零感知 |
| 任何非本机来源 | —— | 🔵 **今天根本不存在**:live netstat 实测 :3200 只绑 `127.0.0.1` ⇒ **不可能有非回环调用方在用它** |

🔵 **⇒ 所以这个改动的打断风险在结构上是零**:它禁止的那一类来源,今天连端口都碰不到。
🟡 **而这一格的强度**:我读的是**此刻**的 netstat + 三个调用方的静态实读。若有某个我没搜到的调用方(譬如另一台机器经 tailnet 打过来)——**它今天也连不上**(:3200 绑回环),所以结论不变。
