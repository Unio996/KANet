## 2 · Bettor 三问逐裁
### A) 来源可信度分级 —— 🔵 该分，但**结论对分级不敏感**
- 现 §3 全标平 "UNVERIFIED-SOURCED"，**掩盖了差异**：厂商官方 spec（KS5 Pro 21 TH/s）与外推估值（5090 ~3-5e9）可信度差一个档。**建议加【可信度档】列**：
  - **A = 厂商标称/官方 spec**（IceRiver/Bitmain ASIC 行）——权威但乐观（真实工况略低）；对**攻击者**用=保守方向。
  - **B = 社区计算器/矿池聚合**（4090：WhatToMine/cryptoage/hashrate.no）——反映实际、随 OC 波动。
  - **C = 外推估值无来源**（5090）——最弱（见 B 问）。
- 🔴 **但决策不吃分级**：GPU(1e9)↔ASIC(1e13)差 **3-4 OOM**，任一行错 2-3× 都不改"一台 ASIC ≫ GPU 级网络"⇒ 枢轴结论**对整个来源不确定区间鲁棒**。⇒ 分级是给 Owner 的透明度（好），不是结论的承重前提。**加列、非阻塞。**

### B) 5090 估值是否该删 —— 🔴 **不删**，且**地板本不靠卡规格**
- **不删**：删掉会**隐藏"5090 的 kHeavyHash 公开数缺失"这个事实本身**（有信息）；现标"估值·非来源"已诚实。改**标 C 档**即可。
- 🔵 **两条更重要的**：
  1. **我们自己的 5090 可【直接实测】**（本机就有 RTX 5090，A.5 那台 VRAM 32606 = 5090）——跑一次 kHeavyHash 基准或读我们自己的挖矿统计，把最弱的外推变最firm的自测。比删/比外推都好。
  2. 🔴 **但地板 `H_floor` 根本不靠卡规格求和**——它由 §4 **链上实测**（法1 难度 / 法2 blue_work）得**我们实际聚合算力**，自动含真实卡数×真实率。卡规格表只用于**攻击者侧**（H_adv 折几台 ASIC）+ **sanity 交叉核**（链测 H_net ≈ 卡数×5090率?）。⇒ **5090 估值弱【不影响 H_floor】**，它只是 sanity 数。§3 该补一句点明这个分工（免得读者以为地板靠 §3 卡表加出来）。

### C) §5 "k=1000 ≤ 一台 KS3M ⇒ 不可作过渡假设" 逻辑 —— 🟢 成立，但成本基须更新
- **逻辑成立且更强**：k=1000 需 `H_need = 999×H_net`；若 H_net=1×4090(2e9) ⇒ H_need≈2e12 ≈ **1/3 台 KS3M**（6e12）⇒ **k=1000 比"一台 KS3M"还便宜**（一台 KS3M 给 k≈3000）。⇒ "k=1000 攻击成本低"结论**稳**。
- 🔴 **但成本基须改（Bettor 已指方向）**：v0.1 §5 写"租赁 ≤ 几十美元/天"——**NiceHash kHeavyHash 已停**（v0.2 §3 自证 UNAVAILABLE）⇒ **改二手 ASIC-CAPEX 购置**口径。且比较对象须是**头寸 value-at-risk**（不是固定 "$X/天"）：判据 = **"achieve k=1000 的 ASIC-CAPEX < 一个 Tier-2 头寸的本金"**。二手 KS3M ~ 单位数千刀、且 **ASIC 可跨多次攻击复用** ⇒ 摊薄后每攻成本更低 ⇒ **任何有意义 value 的 Tier-2 头寸都在攻击面内** ⇒ k_max≲1000 不可作真 value 过渡假设。**§5 判据从 OPEX/天 改 CAPEX vs 头寸值。**
- 🔵 **接我 (23) 地板规格闭环**：Owner 若定 `H_adv` = 一台 KS3M(6e12)、`k_baked`=1000 ⇒ `H_floor_min = 6e12/999 ≈ 6e9`。我们 GPU 挖矿若 ~1e10（2-3 张 5090）**过**、若 ~1e9（单卡）**不过**——**边界恰在我们跑几张卡 × Owner 选哪台 ASIC**。⇒ 枢轴"GPU 级 ⇒ fail-closed"方向对，**精确边界须 §4 实测 H_net + Owner 定 H_adv**（v0.2 §1 已诚实标"落结论哪一边同步后定"）。
