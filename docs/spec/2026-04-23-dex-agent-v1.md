## 1. 产品目标 & KANet 独特价值

### 1.1 要验证什么
KANet 相对 Web2 CEX 能做到：
- **即开即用**：Kasia 地址 = 身份，无注册无登录
- **有记忆**：Broker 记得用户每句话、常用链、习惯地址，不重复问
- **主动服务**：Broker 状态变化主动 DM，不让用户在黑暗中等
- **公开透明**：撮合费、Maker 信誉、链上可查，所有参与方可审计
- **非托管**：用户资金不经 Broker，风险最小化

### 1.2 Dex-Agent v1 定位
本 Owner 旗下 Broker + Seeder + Taker 一体，服务手机 Kasia 用户做小额 KAS↔USDT 零售交易。

## 2. 核心架构假设（不争论）

### 2.1 Broker 与 Maker 同 Owner
Broker (Trader-B) + Seeder (J2) + 未来 BUY Seeder = **同一 Owner 的多 relay**。不调外部 Maker，不做跨主体协议扩展。

**后果**：
- 撮合费是 Owner 内部分账，对用户隐形
- 无 whitelist / 信任问题
- 协议层不加 broker_fee 字段

### 2.2 一次订单一条链
用户指定 `pay_chain` 决定查哪条链的余额。Broker 具备 9 链能力（bnb/eth/polygon/arbitrum/optimism/avalanche/base/sol/tron），但单笔订单只查 1 条。

### 2.3 交易边界
- **小额即时**：单笔上限 100 USDT（折算）
- **快成交**：10 分钟成交上限，超时系统兜底退款
- **非托管**：用户 USDT 直付 Seeder BSC 地址（M1）或托给 Seeder 挂单（M2），不经 Broker 钱包
- **手机用户**：假设不常在线，Broker 主动 push 不保证送达

### 2.4 撮合费隐形收
用户一次确认、一次付款、一次收款。费用通过"Maker 少发 KAS"在后端实现。Owner 同体内部分账。

```sql
  user_kasia_address TEXT PRIMARY KEY,

  preferred_pay_address TEXT,        -- 用户常用付款地址

  notable_preferences TEXT,          -- JSON: 其他提炼出的偏好
```

#### v74: `retail_dex_buy_publications`
M2 限价买单跟踪。Seeder 代用户挂的 BUY offer。
```sql
CREATE TABLE retail_dex_buy_publications (
  id TEXT PRIMARY KEY,
  user_kasia_address TEXT NOT NULL,
  broker_relay_id TEXT NOT NULL,
  seeder_relay_id TEXT NOT NULL,          -- 代挂的 Seeder
  side TEXT NOT NULL CHECK(side='buy_kas'),
  qty TEXT NOT NULL,                      -- 用户要买的 KAS 数量
  limit_price TEXT NOT NULL,              -- USDT/KAS 用户出价
  total_usdt TEXT NOT NULL,               -- qty * limit_price = Seeder 收到的 USDT
  pay_chain TEXT NOT NULL,
  user_usdt_deposit_tx TEXT,              -- 用户把 USDT 打进 Seeder 的 TX
  seeder_publish_offer_id TEXT,           -- Seeder 链上 publish 的 exchange_offers.id
  state TEXT NOT NULL CHECK(state IN (
    'awaiting_deposit',   -- 等用户付 USDT
    'deposited',          -- 收到 USDT 准备挂单
    'published',          -- 链上 BUY offer 已挂
    'filled',             -- 被 seller accept, 正在 settle
    'completed',          -- KAS 已到用户地址
    'refunding',          -- 超时, 退 USDT 中
    'refunded',           -- 已退款
    'failed'
  )),
  expires_at TEXT NOT NULL,               -- 用户指定或 10 min 默认
  filled_at TEXT,
  kas_delivery_tx TEXT,                   -- Seller 发 KAS 给用户的 Kaspa tx
  usdt_refund_tx TEXT,                    -- 超时退款 tx
  error_reason TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX idx_buy_pub_user ON retail_dex_buy_publications(user_kasia_address, state);
CREATE INDEX idx_buy_pub_state ON retail_dex_buy_publications(state, expires_at);
```

### 4.4 Seeder BUY 分支（market-seeder.js 扩展）

当前代码 line 89-94:
```js
// BUY side temporarily disabled...
if (side === 'buy') {
  return { ok: false, error: 'buy_disabled_until_maker_auto_pay_usdt_implemented' };
}
```

**删除这个 block**。实现 BUY 分支：

#### 4.4.1 触发：Broker M2 订单
- 用户 M2 请求 → `retail_dex_buy_publications` 新行 `state=awaiting_deposit`
- Broker DM: "请付 ${total_usdt} USDT 到 Seeder BSC 地址 0x..."
- Seeder watch 自身 BSC 地址 (已有链上 scanner 基础)
- 检测到用户 USDT 到账 → state=deposited
- 调用 `publishSeedOrder` BUY 分支 → 发 `kanet_exchange_offer_v1` (give=USDT, want=KAS) → state=published

#### 4.4.2 等卖家 accept
- 其他 Maker 或散户持 KAS 的，链上看到 BUY offer，调 `/api/exchange/accept`
- accept_v1 中 `verification_meta.receive_address` = 用户 Kasia 地址（Seeder 挂单时就塞好这个字段）
- 协议走 matched → verifying
- 卖家付 KAS 给 receive_address (用户 Kasia)
- 验证过 → state=filled

#### 4.4.3 Seeder 发 USDT 给卖家
- exchange-machine 触发 auto-pay (seeder 是 taker 不触发, seeder 是 maker 触发 auto-pay-give)
- **新分支**：exchange-machine 需扩展支持 maker 自动发 give 资产（当前只做 taker auto-pay）
- Seeder 发 USDT 到卖家 BSC 地址 → state=completed

#### 4.4.4 超时退款 worker
- Seeder 独立 worker 每 30s 扫 `retail_dex_buy_publications WHERE state='published' AND expires_at < now`
- 若 offer 还 open（没被 accept）→ 链上广播 cancel_v1 + 发 USDT 退回用户 → state=refunded

### 4.5 9 链余额查询服务 `chain-balance.js`

```js
// src/services/chain-balance.js
export const CHAIN_BALANCE_SUPPORT = {
  bnb: 'evm', eth: 'evm', polygon: 'evm',
  arbitrum: 'evm', optimism: 'evm', avalanche: 'evm', base: 'evm',
  sol: 'solana', tron: 'tron',

export async function getTokenBalance(chain, address, tokenSymbol = 'usdt') {
  const family = CHAIN_BALANCE_SUPPORT[chain];
  if (family === 'evm') return _evmBalance(chain, address, tokenSymbol);
  if (family === 'solana') return _solBalance(address, tokenSymbol);
  if (family === 'tron') return _tronBalance(address, tokenSymbol);
  throw new Error(`Unsupported chain: ${chain}`);
}
```

### 4.6 状态推送（M5）

在状态机 transition 后自动 DM 用户。

**触发点**：
- `retail_dex_orders` transitions: aligning→confirming (报价确认文), confirming→awaiting_payment (accept 上链), awaiting_payment→paid (收到 tx), paid→executing (广播 paid_v1), executing→completed (交付完成 + 链上 explorer 链接), *→expired/failed (人话解释)
- `retail_dex_buy_publications` transitions: awaiting_deposit→deposited, deposited→published, published→filled, filled→completed, *→refunding/refunded

**实现**：`retail-dex-pusher.js`
```js
export function pushTransition(userAddr, brokerRelayId, template, args) {
  const msg = renderTemplate(template, args);
  sendCommandAsync(brokerRelayId, { type: 'send_message', target: userAddr, message: msg });
}
```

模板示例：
- `paid_broadcasted`: "✅ 已上链告诉 Maker 你付款了 (tx ${tx}). Maker 核对 + 发 KAS 中..."
- `completed`: "🎉 成交! Maker 发的 KAS tx=${kas_tx}, 已到你 Kasia 地址尾 ${addr_tail}. 这笔你付 ${usdt} USDT, 省 ${vs_market}%"

### 4.7 系统兜底 worker

Console 周期性 (每 60s) 扫：
- `retail_dex_orders WHERE state IN ('awaiting_payment','paid','executing') AND julianday(updated_at) < julianday('now','-10 minutes')`
- 超时 → 推 refunding 或 expired + DM 用户
- `retail_dex_buy_publications WHERE state='published' AND julianday(expires_at) < julianday('now')`
- → 调 Seeder 执行退款流程

### 4.8 UI `/exchange` 页 Broker tab

现有 tabs: CEX / Seeker / Taker → 加 **Broker** tab

显示：

- 撮合费率 (0.1 KAS/单)
- 服务中订单 (state=awaiting_payment/paid/executing 列表)
- 累计成交 (completed 订单数 + KAS 总量 + 累计 broker_fee_kas 收入)
- 公开声明 (非托管 + 10 分钟兜底退款 + 费率透明)
