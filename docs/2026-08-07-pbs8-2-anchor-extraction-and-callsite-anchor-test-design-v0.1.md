## 0. 为什么原文形态做不成(结论照录,论证见频道 06:33Z / 本节只留判据)

§8-4 原文: 「handler 级测试断言七个场景**各自零签名调用**」。三条阻塞:

1. 🔴 **离线恒真**: 唯一的"签名"动作是 `sendCommandAsync(oracle.id, {type:'sign_input_for_settle'})`

## 1. (a) 锚点判定提取为单源函数

**新文件**: `kasia-console/src/lib/pbs8-2-signreq-anchors.mjs`(镜像 `src/lib/refund-authorization.mjs` 的角色)。

**导出**: `evaluateSignReqAnchors(input) -> { ok: boolean, reason: string|null, code: string|null }`

- **纯函数**: 不读 DB、不发 RPC、不写日志、无副作用 —— 所有外部事实由 `input` 传入。
- `handlePoolOracleTxSignReq` 改为: 组装 `input` → 调本函数 → `if (!res.ok) { console.warn(res.reason); continue; }`。
  **判定条件本身一个字节不变**,只是从 inline 变成被调用。

### 1.1 🔴 `input` 里"链上值取不到"必须是【值】不是【异常】

```js
// 🔴 落码硬约束(2026-08-07 R9 扫射咬出): chainSpineValue 取不到时传 null, 不许抛。
//   理由: 若建模成抛异常, 用例只能断言"它抛了", 而【抛异常】与【离线环境本来就没有 RPC】
//   在离线下读数完全相同 ⇒ §0 那堵"恒真"墙原样复活, ④ 第一项(RPC 错)白做。
//   ⇒ "取不到"与"没去取"必须在类型层面就是两个不同的东西。
```

⇒ `input.chainSpineValue: bigint | null`,`null` ⇒ `{ok:false, code:'CHAIN_VALUE_UNAVAILABLE'}`
(= @Bettor R2 今日裁定的 `cannot-verify ⇒ 弃权不签、不回落`,**本函数只产出拒绝,永不产出授权**)。

## 2. 必答一 —— 「抽前抽后行为零变化」的判据

**不接受"我读了一遍觉得一样"。三条,缺一不可:**

1. **条件逐字相同**: 提取前后,三个锚点各自的**比较运算符、边界值、and/or 组合**逐字节相同。
   审的方式 = **人眼可确认是纯移动**(NWT 06:35 硬要求原文)。
2. **分支全覆盖**: handler 原来每一条 `return;` / `continue;` 分支,在新形态下都有**对应的返回值处理路径**。
   **少覆盖一条 = 行为变了。** ⇒ 落码时逐条列表对照,进 commit message。
3. 🔴 **注入实验(阳性方向)**: 把提取出的函数里**任意一条判定的边界值改一格**(如 `90n` → `89n`),
   **对应用例必须变红**。⇒ 证明用例实的在读这个函数的判定,不是在读别的东西。

> ⚠ **本节证的是"没变严也没变松",不是"判定本身正确"** —— 判定的正确性由 §11.1-11.3 各自的红队负责,不在本稿射程。

## 3. 必答二 —— (b) 调用点锚的删除注入实验

**(a) 独有的洞**: 函数对了,不等于 handler 调它(在册「闸的强度在调用点,不在闸里」)。

**(b) 做法**: 用例加一段**源码级锚**,读 `trade-protocol-filter.js` 文本,断言 handler 里存在对
`evaluateSignReqAnchors` 的调用**且其返回值被用于跳过签名**(不只是断言"出现过这个名字"
—— 在册「文件里出现名字 ≠ 有代码路径用它」)。

🔴 **验收 = 删除注入必须变红**(NWT 06:35 第 2 条): 把 handler 里那行调用**删掉 / 换成恒真**,
**用例必须变红**。**"我加了这段代码"不算数。** 注入实验的读数与还原后的读数都进证据日志。

## 5. 已知不覆盖 / 弱点(如实,不说满)

1. 🔴 **阳性臂做不成**: 本形态证的是「**该拒的被拒了**」,**证不了「该签的签得出来**」——
   阳性臂要真 relay,离线跑不完。**与 ⑤ 同一格天花板,不是本稿新引入的**(NWT 06:35 认)。
   ⇒ **落码后不许出现"签名闸已验证"这类措辞**,只能说"六类坏输入各自被拒,且拒绝来自本函数"。
2. **三锚点的性质不变**: 按 Codex v4 硬边界,它们**永远只是拒绝信号**,全过 ≠ 可以安全签名。
   本稿只改**可测性**,**不改变**任何一格覆盖范围。
3. **D4**: NWT 06:35 判**不适用**(纯提取、判定条件零变化、弃权率不变)。本稿照录该判定,不自评。
4. 🔴 **第三层完全不在本稿射程 —— input 组装的正确性(NWT 06:47 独立审补,PASS 的附带要求)**:
   (a) 证的是「**提取出的判定函数正确**」,(b) 证的是「**handler 调了它**」;
   **两条加起来仍【不证明】喂给它的 `input` 是不是从链上正确读出来的。**
   ⚠ 而现状更靠前一格: **这三个锚点本身今天都还没落码**,`chainSpineValue` 这类字段的
   **输入组装代码尚不存在**(NWT 现读 `trade-protocol-filter.js:541` 起确认)。
   ⇒ **本稿是"判定层 + 调用层"的可测性方案,不含"取数层"**;取数层错(读错 outpoint、
   读到陈旧快照、单位搞错)时,**(a)(b) 全绿而结论全错**。
   🔨 **落码时必须同时成立的措辞纪律**: 用例全绿只能说
   「**六类坏输入各自被这个函数拒了,且 handler 实的调了它**」——
   **不许说「锚点检查已验证」,更不许说「签名前的输入已校验」。**
