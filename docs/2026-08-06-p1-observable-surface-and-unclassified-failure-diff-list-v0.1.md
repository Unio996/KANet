## §2 【C-⑤ 行为】未归类的失败会静默无限重试 —— 这一段**改行为**

### 2.1 事实(现读)

```
设计 §10.4 / §10.7 第 5 条逐字要求:
  「每个 return {ok:false} 显式归类, **新分支不归类 = 默认结构性(fail-closed)**」

而两个调用点(:1247 / :1390)逐字都是:
  } else if (r && r.ok === false && r.structural) { freezeAwaitingAuthorization(...) }

dispatchRefund 内四个 return {ok:false}, 只有 :2752 带 `structural:`:
  :2733  bshard 无 legacy 路          —— 不带归类
  :2748  无授权(由上一分支 unauthorized 接住)✅
  :2752  preimage 失败 → structural: isStructuralRefundFailure(...)  ✅
  :2782  catch-all `catch (e) { return { ok:false, reason: e.message } }` —— **不带归类**
```
⇒ **抛异常那一路**: `unauthorized` 不成立、`structural` 不成立 ⇒ **两个分支都不进** ⇒ 不冻结 · 不计数 · 状态不动 ⇒ **下个 tick 再判一次 = 静默无限重试。**

🔵 **而它正上方 `:1242-1244` 的注释写着这条路存在就是为了防这个形状**:
> 「若这里不接, 市场会停在原状态、下个 tick 再判一次, **变成无限重试且没有任何东西升级**(库里那 4 个卡了 55 天的盘就是这个形状)」

### 2.2 定价(@Bettor 2026-08-06 已定性: 非新设计, 是把代码改回已 GREEN 的设计默认)

- ✅ **不动钱**: 这条路**不会造成错误退款**(钱那侧仍 fail-closed)⇒ **不违反 ⑤ 的资金不变量**。
- 🔴 **违反的是那条明写的默认**: 声明的默认是「不归类 = 结构性」, 实际的默认是「不归类 = 永远重试」。
- ⚠ **可达性我只证了一半, 不假装两半都证了**:
  `:2782` catch-all **可达**(DB / JSON / RPC 任一抛都进);`:2733` bshard 那条**可达性未验** —— 上游 `:620` 有 `isBshard-skip`, 可能够不到。

### 2.3 建议改法 —— **两步, 且第一步保证今天已归类的行为逐字不变**

```
① :2752 追加一个显式的瞬时标记(不动现有 structural 字段):
     return { ok: false, reason: preimage.error,
              structural: isStructuralRefundFailure(preimage.error),
+             transient:  !isStructuralRefundFailure(preimage.error) };

② :1247 / :1390 两个调用点把判别改为"默认冻结, 除非显式瞬时":
-    } else if (r && r.ok === false && r.structural) {
+    } else if (r && r.ok === false && r.transient !== true) {
```

**为什么这么改(而不是只给 `:2782` 补一个 `structural: true`)**:
- 🔵 **补字段是守【开放集合】, 改判别是守【判别点】** —— 第 9 个 `return {ok:false}` 的作者不会知道有这条规矩, 而**判别点只有两个**。

> ### 🔴🔴 作用域更正(2026-08-06 · J2 自查 · **我上面这句原本写的是"守闭合处才完备", 那是说满了**)
>
> **原文借用了本文件在授权闸上的那条理由(`:2737-2740`「守闭合处才完备」)。借错了 —— 那里的"闭合"成立, 这里不成立。**
>
> **实读 12 个真实 `dispatchRefund` 调用点**:
> ```
> ✅ 接返回值的只有 2 个:  :1241 · :1387     ← 本修法落在这两个
> 🔴 其余 10 个【整个丢弃返回值】: :660 :704 :755 :812 :910 :1222 :2001 :2155 :2269 :2430
>    (`await dispatchRefund(...)` 之后什么都不看)
> ```
> ⇒ 🔴 **「判别点只有两个」是真的, 而我漏了下一句: 另外十个调用点【根本没有判别点】。**
> ⇒ **在那十处, `{ok:false}` 无论归不归类、无论判别逻辑怎么改, 结果都一样: 静默丢弃。**
> ⇒ **本修法把"未归类返回静默落空"从 2 个调用点收掉, 对另外 10 个一个都收不了。它是止血, 不是闭合。**
>
> 📌 **处置(@Bettor 2026-08-06 裁定)**: 本卡按原案做(收 2 个判别点)· **「10 处调用点整个丢弃返回值」另立独立卡【DISPATCH-RETURN-DISCARDED】走完整设计流程**
> —— 改一个 12 处调用的函数的错误契约是**设计题不是补丁**。
>
> 🔨 **判据(收下)**: **"守闭合处"这个理由能不能借, 取决于【那一处是不是真的闭合】, 而不是取决于【它在别处成立过】。**
> 我是在核 `:2733` 可达性时顺手数了调用点才发现的 —— **原来那句我没数过就写了, 它读起来完全像数过。**
- ✅ **行为等价性(可核)**: 今天**所有已归类的返回**在改动前后走同一条路 ——
  `structural===true` ⇔ `transient!==true` 成立(因为 ① 让二者互补);
  **唯一改变的是那两个未归类的返回**: 从"静默重试"变为"冻结待授权"。
- 🔴 **而这个改变正是设计要的方向**: 冻结有出口(`owner_authorized`)、有计数、有告警;静默重试三样都没有。

### 2.4 落码时必须配的负 fixture(不配就是没测)

| # | 注入 | 必须的反应 |
|---|---|---|
| 1 | 让 `dispatchRefund` 内抛一个异常(catch-all 路) | 市场**进冻结态**;改动前该臂应为**红**(今天它停在原状态) |
| 2 | 一个**瞬时**失败(`transient: true`) | **不冻结**、保留重试 —— 证明 ② 没把重试路一起吃掉 |
| 3 | 一个**结构性**失败 | 冻结(与今天一致, 回归臂) |

🔴 **第 2 条是最容易被省掉、也最关键的一臂**: 只测 1 和 3, 一个"把所有失败都冻结"的实现照样全绿, 而那会**把本可自愈的瞬时失败全部变成待人工授权的积压**。
