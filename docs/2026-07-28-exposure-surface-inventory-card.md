## §2 一个无鉴权的节点 RPC 面 — 现役暴露(本卡等级最高的一格)

> 🔴 **本节【故意不写】是哪个口、哪台机器、当前可达性如何。**
> 具体口与实测可达性 → 本机 `scratch/_kanetui_exposure_inventory_20260728.txt`(不入库,理由见 §0)。
> **这一格是被收回来的**:本卡执行者(我)第一版把口点了名并写了当前可达性,由立卡人按 §0 那条分界判**过界**、令推之前收。**收回的过程留在这里,不抹掉** —— 它正是 §0 那条分界的第一个实例。

```
✅ 实测: 存在一个【无鉴权】的节点 RPC 面, 且它不止绑回环; 两台机器各自独立测出同一形状
✅ 实测(我们这台): 该面当前全部客户端均为本机回环, 跨机客户端 0
   ⇒ 绑回环【打断 0 个现有调用方】
🔴 而这不是"公网入口决定"的前置条件, 它是【现役】—— 时态一度写错, 由域主实测推翻后改判
```

### 🔴 "零代价"这个词曾被用在两个不同的东西上(本卡记账,含我自己那笔)

```
✅ 实测到的是【客户端代价 = 0】: 绑回环不打断任何现有调用方
❌ 被读成的是【总代价 = 0】: 而改 bind 要【重启那个节点进程】—— 那是另一笔账
🔴 而这台不是一个普通服务, 它是这条链本身(本仓已记死: 停矿 = 整条链 halt)
🔴 D-005 的另一半: 【不 rebuild】不等于【可以随便重启】
```
🔨 **通则(与本仓「覆盖边界是等号不是上界」同族)**:**一次测量只覆盖它测的那一项。用它去背书一个更大的结论,是把等号当成了上界。**
本卡实例:执行者(我)拿"客户端代价 0"去背书了"零代价收口",立卡人跟着用了同一个词,**由立卡人自己抓出**。

## §2.1 处置(第三版 — 前两版都是被实测推着改的,过程保留)

```
① 将来式前置条件        ← 前提是"NAT 挡着"          ⇒ 被域主实测推翻
② 现役暴露·零代价·立刻做 ← 把"客户端代价 0"外推成"总代价 0" ⇒ 被立卡人自己抓出
③ 现役暴露·搭【下一个自然重启窗】做·不单开     ← 当前
   理由: 当前边界是 tailnet 成员资格(自己两台), 不是公网
        ⇒ 为它单独 halt 一次链, 确定代价 > 它当下的不确定风险
```
🔴 **而在那之前必须记这一句,免得被读成已处置**:
> **该 RPC 面在两台上均无鉴权;当前唯一的边界是 tailnet 成员资格。**
> **它没有被修复,它被记账并排进下一个重启窗。**

> ⚠️ **说明(免得被当成擅自改写)**:立卡人给过一句**逐字记账用词**,要求引用者不得改写。
> 那句里含【是哪个口】与【此刻跨机可达】两格,而同一人随后裁定这两格**不得入公开仓库**。
> ⇒ 本卡采用**去掉那两格后的版本**;**逐字原句留在协调频道与 scratch 详单里**。
> 🔵 两条裁定不冲突,只是作用域不同:一条管**措辞不许软化**,一条管**这份文件里能写什么**。

🔴 **唯一不排队的一条**:**任何公网入口决定不得先于此项通过** —— 公网入口一旦开,tailnet 那层边界当场消失。
🔴 **未知且不许含混的一格**:**公网侧是否可达,我们不知道。**
> 曾经的推法是「入向 P2P peer = 0 ⇒ 外面够不到我们」——**那是把一次实测外推成全称**:P2P 口与 RPC 口是**两个不同的口、两条不同的路**。该推论已被立卡人自行撤回。

**处置**:方向 = **绑回环 / 限 IP**,不是"加一道鉴权"(让危险动作不存在 > 给危险动作加闸)。
两台**分开处置**:一台零代价;另一台改 bind 需重启节点,而重启会在链索引上凿洞 ⇒ 代价归其域主自算。

## §3 告警出口 — 结论不是"没有读者",是**读者在,信号被淹死**

```
出口: 32 个文件写 events 表 · scope=system 告警级累计 36,272 条 · 此刻仍在写
读者三处:
  ① /dashboard          渲染【最近 10 条】+ 计数
  ② /events             独立页面, 带 level / source / search 筛选     ← 🔴 第一版漏了这一处
  ③ 协调频道             只有【2 类】告警会播报到这里
过去 24h 4,411 条 ≈ 184 条/小时 · 前 3 型占 75.1%
⇒ 🔴 一条【新】告警在 ① 那个"最近 10 条"窗口里平均只停留 3.3 分钟
```

> 🔴 **本节第一版漏报了读者 ②,现更正。** 漏的成因写在 §4(它是同一个方法学坑的第二次发作)。
> **而结论没有变,原因要说准**:②的筛选维度是 **level / source / 关键字**,**没有"我没见过的型"这一维**;
> 且三处**全是拉取式**(要人主动去看),**无未读、无确认、无推送**。
> ⇒ 一条**从没出现过**的 critical,在一个被 12,000 条同型刷屏的列表里,**除非你已经知道要搜什么,否则筛选帮不上你**。
**处置**:让**新出现的型别单独冒头**(首次出现 / 24h 内未见过 → 播报到有人读的地方)。
🔴 **不动那三个复读机,也不加新页面**;而**降噪不许做成关掉**——它们仍是真的故障信号,关掉 = 把一个正在喊的故障变成静默,比现在更坏。
🟡 `console.log` 那一路**保持没盘**,并记一行:**它没有读者机制,也没人声称它有 ⇒ 它不是失效的告警出口,它根本不是告警出口。两者别混。**

## §4 方法学(Bettor 令:写进卡里,别只留结论)

```
🔴 我的第一版结论是错的, 救我的是对照臂。
   扫「有没有前端 fetch /api/events」⇒ 空 ⇒ 差点报"没有任何人类读者"
   而给这个查法配对照臂: 同法查一个【确定有页面】的 API ⇒ 也是空
   ⇒ ⇒ 空的是【查法】不是事实(Console 是服务端渲染, 根本不这么调)
   换成追 getEvents/getEventStats 的调用点 ⇒ 读者立刻现形
```
🔨 **通则:每一个"我没找到 X"的结论,都要先证明这个查法找得到【已知存在的 X】。**
同族第二例:扫描器里「私钥物 0 命中」——因为该类**没有** canary,所以它只能标 NO-POWER,不能标"干净"。


🔨 **⇒ 补一条:找"有没有 X"与找"一共有几个 X"是两个问题,而第一个答案会让人以为第二个也答完了。**
