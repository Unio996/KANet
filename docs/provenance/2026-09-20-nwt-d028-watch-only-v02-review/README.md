## 一、SHOULD 与观察

- **S4-1（SHOULD）阳性对照的判定规则要写死，现在的写法有歧义**：§2.2 第 4 步写"并入一个或多个**已知有余额**的热地址；**对照项读到 `0` 或缺项 ⇒ 整批 `unavailable`**"，§7 又写"热地址全为 0 时退化整批 `unavailable`（偏保守）"。问题：① 读取模块**并不知道**哪个热地址"已知有余额"——它只是从 `relay_nodes` 取地址；② 如果对照集合有多个地址，"**任一**为 0 ⇒ 整批不可用"的字面读法会在**任何一个热 relay 余额恰为 0 时**让冷存永久显示"—"（热 relay 花光钱是正常事）。**实测现状**（`outputs.txt`）：今天 18 个热地址在同步的本机节点上**全部为正**，所以这条今天不会触发——但它是个等着某天触发的陷阱。**写死为**："对照集合 = 同一批里读到的**全部**热地址；**至少一个 > 0** ⇒ 该批被阳性对照认证；**全部为 0 或缺项** ⇒ 整批 `unavailable`，原因码 `no_positive_control`（区别于 `node_not_synced`，便于排查）"；A7③ 相应改为"全部对照项为 0 / 缺 ⇒ 整批 `unavailable`；**只有部分为 0 ⇒ 不影响**"（后一半是新增用例，防实现者写成"任一为 0"）。
- **S4-2（SHOULD，小）两个显式说明**：① **`WATCH_PUBLIC_FALLBACK=1` 的 `ok_public` 路径没有同批阳性对照**（因为冷存不与热地址同批外发）——请写明：REST 是独立来源、不受本机 IBD 空值影响，所以该路径不需要对照，但**要**有它自己的失败处理（HTTP 非 200 / 超时 / 结构异常 ⇒ `unavailable`，绝不 0）。② A4 的静态检查依赖共享扫描器——它在 9-1 合入后已在主线，但我的 F4 审提出的 F4-1（`stripComments` 过度剥离会漏报）**正由 F5 修**，A4 与握手 V9 一样，请在实现前确认 F5 已合入。
- **观察 O4-1**：`GET /api/portfolio/unified?relayId=X`（现有的"单个 agent 视图"）在设计里没有说明 `watchAccounts` / `totals.watchKas` 是否出现。建议：带 `relayId` 时**不含**冷存（那是某个 agent 的视图，冷存账号不属于任何 agent），并加一条用例，免得 A1 的 20 = 18 + 2 只在无参数时成立却没人测另一种调用。
- **观察 O4-2**：§2.2 缓存"只缓存已判 `ok` 的结果对象、不缓存同步判据"——同意；页面显示 `readAt` 已经让 30 s 内的陈旧可见，不必再改。
