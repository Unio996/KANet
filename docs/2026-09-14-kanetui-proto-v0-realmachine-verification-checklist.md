## 1. `/tokens/create` — 代币定义创建（v0.3：不铸币，只存定义，无 TX）

依赖：`POST /api/tokens/create`（J2，语义=存定义）

| 步骤 | 操作 | 期望 |
|---|---|---|
| 1.1 | 打开 `/tokens/create` | 页面 200，标题"创建代币定义"，表单只有 名称/Ticker/默认面额(可选)/描述(可选)——**没有出单人下拉、没有发行数量** |
| 1.2 | 不填任何字段直接点「保存定义」 | 按钮 disabled（灰态），不发请求 |
| 1.3 | 只填名称，留空 Ticker | 按钮仍 disabled |
| 1.4 | 名称+Ticker 填好（默认面额/描述留空也行），点「保存定义」 | **若端点未上线**：按钮变"保存中..."后恢复，出现红色错误条"保存失败: HTTP 404（后端接口尚未上线）"，表单字段保留原值不清空。**若端点已上线**：跳转完成态，显示"✓ 定义已保存"——**没有 TX 摘要**（这一步不上链）+「去建市场」/「查看定义列表」/「再造一个」三个按钮 |
| 1.5（端点已上线时） | 点「去建市场」 | 跳到 `/proto-markets/create` |
| 1.6（端点已上线时） | 点「查看定义列表」 | 跳到 `/tokens`，能看到刚保存的这一条 |

## 2. `/tokens` — 代币定义列表

依赖：`GET /api/tokens`（J2）

| 步骤 | 操作 | 期望 |
|---|---|---|
| 2.1 | 打开 `/tokens` | **未上线**：红色"加载失败：HTTP 404（后端接口可能尚未上线）"。**已上线、无数据**：空态"还没有代币定义" + 「创建第一个 →」。**已上线、有数据**：表格显示 名称/ticker/默认面额/**用于哪些市场**/创建时间——新建的定义此列应显示"（还没有市场用它）" |

| 2.3（有市场引用某定义后） | 重新打开 `/tokens` | 该定义行的"用于哪些市场"列显示引用它的市场标题 |

## 3. `/proto-markets/create` — 市场创建

依赖：`GET /api/tokens`（选代币定义用，J2）、`POST /api/proto-markets/create`（J2）

| 步骤 | 操作 | 期望 |
|---|---|---|
| 3.1 | 打开 `/proto-markets/create`，此时 `/tokens` 还没有任何定义 | 结算代币下拉只有"选一个代币..."一项，下方提示"还没有代币定义，先去创建一个"（链接到 `/tokens/create`） |

## 5. `/proto-markets/:id` — 市场详情（下注 + 宣布结果 + claim 合一页）

依赖：`GET /api/proto-markets/:id`、`POST .../bet`、`POST .../resolve`、`POST .../claim`（均 J2）

按市场当前 `status` 走不同分支，建议 J2 后端上线后手工造 4 条不同状态的市场各点一遍：

| 市场状态 | 应该看到的面板 | 点验动作 | 期望 |
|---|---|---|---|
| `open` | 下注面板（v0.3：两步）+ 出单人宣布结果面板 | 选 YES/NO + 填数量 → 提交下注 | 见下方"§5a 下注两步单独验" |
| `open`/`closed` | 出单人宣布结果面板 | 点「判 YES 赢」或「判 NO 赢」 | 成功后提示"已宣布，刷新页面查看最新状态"；非出单人调用应看到后端拒绝的错误文案（前端不做权限判断，只透传） |
| `resolved` | 领取面板，显示"结果：YES 赢 / NO 赢" | 点「Claim」 | 赢家：绿色"Claim 成功，TX: ..."；非赢家/已 claim：如实显示后端错误 |
| `refunded` | 领取面板，显示"到期无人宣布结果，全员退款" | 点「Claim」 | 退款到账提示或如实错误 |
| 不存在的 id | — | 直接访问 `/proto-markets/does-not-exist` | 红色"加载失败：HTTP 404（后端接口尚未上线，或该市场不存在）" |

### §5a 下注两步单独验（v0.3，ledger 1335：KTT 无通用余额，下注=①铸筹码+②下注两笔 tx）

依赖：`POST /proto-markets/:id/bet` 返回 `{ ok, steps: [{step:'mint',...},{step:'bet',...}] }`（J2，字段名待定）

| 场景 | 操作 | 期望 |
|---|---|---|
| 5a.1 未上线 | 选 YES/NO + 填数量 → 提交下注 | 按钮"提交中..."后恢复；两步进度块**不显示**（因为拿不到 `steps` 数组）；红色"下注失败: HTTP 404（后端接口尚未上线）" |
| 5a.2 两步都成功（正常路径） | 同上 | 两步进度块出现：①铸筹码 ✓ + txid，②下注 ✓ + txid；下方绿色"✓ 已下注（两步均已落链）" |
| 5a.3 第①步失败（比如没钱铸筹码） | 同上 | ①铸筹码 ✗ + 红色错误文案；**②下注保持"○"未开始状态，不显示已尝试** |
| 5a.4 第①步成功、第②步失败（比如筹码铸出但转不进市场 covenant） | 同上 | ①铸筹码 ✓ + txid；②下注 ✗ + 红色错误文案；**额外一行琥珀色提示**"筹码已铸出但没能下成注——这份筹码目前没有绑定到本次下注，别当作已下注"；**不出现**"✓ 已下注"那行绿色提示 |
| 5a.5（若能构造） 重复下注同一方向 | 已下注一次后再提交一次 | 如实显示后端返回的错误，不重复计入 |

⚠ 5a.2/5a.3/5a.4 三种场景需要 J2 后端能配合造出对应结果（或提供一个可强制指定哪一步失败的测试开关）才能全测；若 J2 上线时机制还没做到能区分两步失败，至少验 5a.1（未上线时的前端行为）和 5a.2（正常成功路径），其余记为"待 J2 提供可控失败场景后补测"。
