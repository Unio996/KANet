# 外部程序接入 KANet（TN12）— 照做指南

> **这份文档是什么**：一份**照着走**的说明书 —— 给一个**不在我们机器上、不用我们代码、不认识我们任何人**的开发者。
>
> **它覆盖**：生成身份 · 构造 KANet 加密信封 · 把它作为交易载荷广播上链。
> **它不覆盖**：编译合约(covenant) / 结算 / 预测市场。那一层另有边界，见本文末尾。
>
> ✅ **照它能不能从零走通** —— **能走到"消息上链"为止，而全程不需要我们授予你任何东西**：
> 你自备密钥、自备节点（TN12 是标准 kaspad testnet）、自付手续费。
>
> 🔴 **而有两格仍然不通，先说清是哪两格**：
> - **拿第一笔测试币**（§5）—— 你需要 TN12 币才付得起手续费，而这一步今天没有对外的自助入口
> - **确认对方读到了**（§7）—— 🔴 **这是唯一真正卡在我们这边的一格**：
>   我们收到并解密了你的消息，而**我们现在没有把这件事告诉你的机制**
>
> 🔵 而**第 1–3 步不需要节点、不需要币，现在就能跑完并自证**。

## 1 · 装依赖

**唯一的依赖是 `kaspa-wasm`。**

| | |
|---|---|
| 包名 | `kaspa-wasm` |
| 版本 | 它的 `package.json` 写着 **1.1.0** —— 🔴 **而这个号不足以指认这份字节**，官方同版本号的产物与它逐字节不同，见下 |
| 上游 | `https://github.com/kaspanet/rusty-kaspa`（它是 rusty-kaspa 的 WASM 绑定） |

### 🔴 不要用 `npm install kaspa-wasm` —— 它给不了你这一版

这不是偏好，是实测结论：

```
npm view kaspa-wasm versions  ⇒  只有 '0.1.2' 和 '0.13.0'，latest = 0.13.0（发布于一年多前）
npm pack kaspa-wasm@1.1.0     ⇒  ETARGET  No matching version found
```

⇒ **`kaspa-wasm` 这个包在 npm 上存在，而 `1.1.0` 不是它发布过的版本。**
（读数是可判读的：一个不存在的包名会返回 404，与上面的 ETARGET 不同。）

🔴 **所以 `npm i kaspa-wasm` 会给你 `0.13.0` —— 与我们用的差一个大版本，API 不同。**
🔴 **而更要紧的**：本文 §6 那几个坑是在 **1.1.0** 上测出来的，**对 `0.13.0` 未必成立** ——
你会撞到一组**这份文档里根本没写**的错，而它们长得和文档里写的那些一样（一句什么都不说的报错）。

✅ **⇒ 从我们的仓库把 `shared/vendor/kaspa-wasm/` 整个目录拷走。** 这样你和我们跑的是同一份字节。

**一条命令就够**（🔴 注意那个 `-b`，原因见下）：

```bash
git clone -b bshard-m3-deploy https://github.com/Unio996/KANet.git
cp -r KANet/shared/vendor/kaspa-wasm            ./kaspa-wasm
cp    KANet/docs/examples/kanet-external/send-comm.mjs  .
```

> 🔴 **为什么必须带 `-b`**：这份文档和 `send-comm.mjs` 此刻**不在默认分支 `master` 上**，
> 它们在 `bshard-m3-deploy`。而 `kaspa-wasm` **两个分支上都有** ——
> 所以带 `-b` 的这一条**一次就把三样都拿到了**，不需要 clone 两次。
>
> 🔵 **上面这三条命令是实测过的**（全新目录 · 从这个公开 URL 真克隆 · 跑完即删），
> 拷完直接 `node send-comm.mjs --self-check` 八条自检全过。
>
> 🟡 这是**当前状态**，不是设计 —— 合并进 `master` 之后 `-b` 那一段就该删掉。
> 若你**不带** `-b` 去 clone，然后找不到 `docs/examples/kanet-external/`，**不是你做错了**。

✅ **⇒ 所以「从我们仓库拷」今天是【唯一正确的取法】，不是权宜之计。**

## 2 · 第 1 步：生成身份

你的身份就是**一把 32 字节私钥**。不需要向我们注册、不需要我们发给你任何东西。

```js
import * as crypto from 'node:crypto';
import * as kaspa from './kaspa-wasm/kaspa.js';
const { PrivateKey, NetworkType } = kaspa;

const privKeyHex = crypto.randomBytes(32).toString('hex');            // 64 位十六进制
const address = new PrivateKey(privKeyHex)
  .toKeypair()
  .toAddress(NetworkType.Testnet)      // ← TN12 用 Testnet
  .toString();
```

**样例输出的形状**（🔴 私钥这一行是**占位符，不是一把真密钥** —— 见下面那段说明）：

```
私钥  : <64 个十六进制字符 —— 你自己那把，别贴给任何人>
地址  : kaspatest:qz63yt3dndghh0kdznfx7xla5pxp8waw2lsmuc7ud8ncpqwup2h3xftd80w8c
```

⇒ 地址应当以 `kaspatest:` 开头，冒号后 **61 个字符**（实测 200 个随机地址，长度全部是 61）。

### 🔴 密钥怎么拿、怎么存 —— 而**这个例子默认不会把它打出来**

```bash
node send-comm.mjs --self-check                        # 默认：只打地址，不打密钥
node send-comm.mjs --self-check --reveal-new-private-key   # 显式要求时，才显示【本次新生成的】那把
export KANET_PRIVKEY=<那一串>                           # 设进环境后它就是你的身份，不再变
```

- 🔴 **来自 `KANET_PRIVKEY` 的那把密钥，本例任何情况下都不回显** ——
  哪怕你加了 `--reveal-new-private-key`。它是你长期持有的东西。
- 🔵 **为什么这么设计**：终端输出会落到 CI 日志、贴给别人的排查记录、录屏和截图里。
  一个把长期身份密钥打到 stdout 的例子，即使在测试网上，也是在教人用不安全的方式对待密钥。
- ✅ 自检 7 会**每次**断言这件事（输出里有地址、没有密钥），所以它不是一句承诺，是一条会报红的检查。

> 🟡 **这一格的来历**：本例最初每次自检都把私钥明文打出来，**包括来自环境变量的那一把**，
> 而 README 里放的还是一把语法上可用的真密钥。**是一次外部审查把它指出来的**，不是我们自己发现的。

🔴 **而有一件我们【没有】替你做，你得自己做**：

```
本例【不负责把你的密钥安全地存起来】——
它不写文件、不设文件权限、不接任何密钥管理器。
```

审查意见里建议过"把新生成的密钥写进一个受权限限制的文件"，**我们没有采纳**，
理由是那要引入跨平台的文件权限处理，而这个例子的定位是**一个能整个拷走的单文件**。
⇒ 于是 `export KANET_PRIVKEY=…` 之后，**那把密钥会留在你的 shell 历史和环境里**，
而怎么处置它是**你这一侧的事**。我们把这句写在这里，是为了让你知道**这一格没有人管**，
而不是让你以为有人管了。

⇒ 设好之后每次跑都带着同一个身份。**第 5 步（广播）在没设它的时候会直接拒绝执行** ——
因为那会往一把全新的、余额必然为 0 的密钥上跑，而报出来的错会指向别处（"没有 UTXO"）。

## 3 · 第 2 步：构造 KANet 加密信封 🔴 **这一节是全文最要命的一格**

### 3.1 为什么它最要命

一条格式不对的消息，**会被收信侧正确地、静默地丢弃**，而你**收不到任何错误** —— 交易照样上链、照样扣费、照样有 txid。你会以为发出去了。

这不是假设：**这份配方的第一版就是这么失败的**，缺的正是下面 3.3 那一段。

### 3.2 信封的字节布局

```
ECDH(secp256k1) → HKDF-SHA256(salt 空, info 空, 32 bytes) → ChaCha20-Poly1305

字节序：  nonce(12)  ‖  ephPub(33)  ‖  ciphertext(N)  ‖  mac(16)
                        ↑ 压缩式公钥，首字节 0x02 或 0x03（不是 32 字节 x-only）
                                        ↑ N == 明文的 UTF-8 字节数（流密码，不扩张）
总长 = 12 + 33 + N + 16 = N + 61
```

- **对方公钥从哪来**：从对方的 `kaspatest:` 地址里 bech32 解出 **32 字节 x-only** 公钥，前面补 `0x02` 凑成压缩式。
- **HKDF 的 salt 与 info 都是空**（零长度），不是省略、就是空。
- **加密给谁**：给**收信方**。

### 3.3 🔴 外层载荷格式 —— 少一段就全丢

```
ciph_msg:1:comm:<你的alias>:<base64( 上面那串信封字节 )>
                 ^^^^^^^^^^^ 🔴 这一段少不得
```

- `<alias>` 是**发送方**（你）的名字，**必须非空、且不能含冒号**。
  收信侧用 `ciph_msg:1:comm:` 之后的**第一个冒号**来切分 —— 没有那个冒号，整条消息直接丢弃。
- base64 用标准字母表（`+` `/` `=`）。
- 整个字符串按 **UTF-8** 编码成字节，那串字节就是交易的 payload。

### 3.4 一个可对照的完整样例

明文 `hello from an external program`（30 个 UTF-8 字节）：

```
信封总长      : 91 bytes            (= 12 + 33 + 30 + 16 ✓)
  nonce       : 5809b45d76341f8a5d77a3ea
  ephPub      : 03eb905f1842e7e1bc06ab2143a9909ab9e191f8bc57420074d6bba0eb53363e48
  ciphertext  : 30 bytes
  mac         : ae94bf9f1a3a044c305a948fe0659985

payload 字符串:
ciph_msg:1:comm:my-program:WAm0XXY0H4pdd6PqA+uQXxhC5+G8BqshQ6mQmrnhkfi8V0IAdNa7oOtTNj5IuZqFuLZsJenI3cto3HJXCjEG9JPh5xi7ZxqyXApHrpS/nxo6BEwwWpSP4GWZhQ==

payload hex（上链的就是它，开头这一段是固定的）:
636970685f6d73673a313a636f6d6d3a…
 └── "ciph_msg:1:comm:" 的 hex
```

> nonce 与 ephPub 每次都不同，所以你**不会**得到逐字相同的输出。
> **能对照的是形状**：总长 = 明文字节数 + 61 · ephPub 首字节是 `02` 或 `03` · payload hex 以 `636970685f6d73673a313a636f6d6d3a` 开头。

### 3.5 ✅ 现在就跑一次自检（不需要节点、不需要币）

```bash
node send-comm.mjs --self-check
```

它会打印上面那些字段，并跑**八条**自检：

| | 自检 | 它证明什么 | 拆掉再跑会不会报红 |
|---|---|---|---|
| 1 | 信封能被解回原文 | 加密与解密自洽 | 🟡 没验过 |
| 2 | 总长 == 12+33+明文+16 | 字节布局对 | 🟡 没验过 |
| 3 | 少了 `<alias>:` 段的载荷会被丢弃 | 3.3 那一段少不得 | ✅ 另一条路验的（见下 ③） |
| 4 | 合约(P2SH)地址会被**拒绝** | 见下 | ✅ 验过 |
| 5 | 选输入 + 算 mass 那段能跑 | 单 UTXO / 合并多 UTXO / 余额不足会抛错 | ✅ 验过 |
| 6 | **真造一笔交易**（用假 UTXO） | 造出来用的输入 == 算 mass 用的那批 | ✅ 验过 |
| 7 | 输出里有地址、**没有密钥** | 见 §2 那一段 | ✅ 验过 |
| 8 | 五种坏地址全被拒 + **好地址必须通过** | 见下 | ✅ 自带阳性对照 |

🔴 **第 4 条为什么单列** —— 因为 1–3 条**结构上抓不到它**：
它们全是「加密给自己」，走的永远是普通(P2PK)地址。
而**合约地址的脚本哈希也是 32 字节** ⇒ 一个只查长度的实现会让它整个通过，
于是你会把脚本哈希当公钥去加密，产出一个**谁都解不开的密文** —— 而它照样上链、照样扣费、照样有 txid、**零错误**。
⇒ 所以自检 4 用的那个 P2SH 地址是从 `redeem = OP_1` 算出来的，**谁都不拥有它**，你可以自己复算。

🔴 **第 5、6 条为什么存在** —— 因为 `--to` 那条路**在本地一次都不会被执行**，
而它曾**两次**带着错上线（一次算法逻辑、一次改名漏改），**两次都是别人在另一台机器上真跑才发现的**。
⇒ 现在它们用一个**形状完整的假 UTXO** 把那两步真跑一遍，不需要节点、不需要币。

🔵 **八条都过 ⇒ 你的第 1–3 步是对的**，而这句话的底气逐条摆在上面那一列：
① 这份例子里的密码学与本网络现役收信实现做过**逐字节交叉验证**（含一条改一个字节就失败的阴性对照）；
② 4/5/6/7/8 各自在**把对应那道检查拆掉的副本**上跑过并**报红**；
③ 自检 3 的判别力是另一条路验的：把缺 `<alias>:` 段的载荷**喂给现役收信侧的解析逻辑**，它确实被丢弃，
　 而合格的那一份被读出原文 —— 两边读数不同。
🟡 **而自检 1、2 那一列写着"没验过"** —— 它们只是断言，别把它们读成与其余六条同等强度。

## 4 · 第 3 步：起一个你自己的 TN12 节点 ✅ **可以做 —— 而且不需要我们给你任何东西**

🔵 **这一节此前写的是「今天走不通，卡在我们这边」——那句是错的**，而错在一个前提上：
我们当时以为你需要**连到我们的节点**。你不需要。

```bash
kaspad --testnet --netsuffix=12 --utxoindex --appdir=<你的目录>
```

⇒ 然后 `KANET_RPC_URL=ws://127.0.0.1:17210`。

**TN12 不是一条自定义链** —— 它就是标准 rusty-kaspad 的 testnet 加 `--netsuffix=12`。
🔵 **实测**（2026-07-29，【一个全新的空 appdir · 不给任何 `--addpeer`】——
🔴 而那台机器上【已经跑着另一个 TN12 节点】，所以它不是一台陌生主机）：
它**自己查 DNS seeder、找到了同伴、开始同步** —— 全程没有人给它任何地址。
⇒ **在正常情形下，你不需要我们提供节点、地址、或任何许可。**

🔴 **而上面那句成立有一个条件，我们把它写出来**：它靠的是公共 DNS seeder 能解析。
若这些 seeder 都解析不到，节点就找不到同伴 —— 而这不是你做错了。
这时唯一的绕法是手工指定一个已知的 TN12 节点（`--addpeer=<地址>`）。
🔴 而这个地址我们**没有**对外提供 —— 我们不发布任何节点地址。
所以在这种情形下，你需要从别处拿到一个 TN12 节点地址；
**我们这边没有一条你能自己走通的路。**

> 那次实测后来跑完了 —— 而**具体耗时不进这份文档**。
> 🔴 原因不是保密：那是**我们这台机器的数**，而它是在一台
> **本机已经跑着另一个 TN12 节点**的环境里测的 ⇒ 它不是一台陌生机器的起点。
> 所以它帮不了你，而它会变成你的外推基数。
> ⇒ **别按任何时间预期排你的计划。**
> 若你跑起来发现半天没到链尖，**那是正常的,不是你做错了**。

> 🟡 **而我们没测过的**：这次实测是在一台**已经在同一个网络环境里**的机器上做的。
> 一台完全陌生的机器要多久找到同伴、会不会找不到 —— **没人量过**。
> 若你起不来，那是这份文档的空白。

<details><summary>而我们自己这台为什么给不了你端点（点开，与你无关，只是把话说清）</summary>

## 6 · 第 5 步：广播（等第 4、5 步通了之后）

```bash
KANET_RPC_URL=ws://<KANET_HOST>:<RPC_PORT> \
KANET_PRIVKEY=<你的私钥> \
KANET_ALIAS=my-program \
node send-comm.mjs --to kaspatest:<对方地址>
```

> `<KANET_HOST>` / `<RPC_PORT>` 是占位符。**这份文档不写具体的主机和端口** ——
> 因为写在这里的任何一个地址，都会在环境变化时变成一个**指向空处的出路**（这份文档此前正是这样错过一次）。
> 这两个值应当由**给你端点的那个人**告诉你。

交易构造有四个坑，**四种完全不同的写错，报错一字不差**：`RuntimeError: unreachable` + 一串纯地址栈，不提任何参数名。

🔴 **坑 1（外部无途径可猜，这是这份文档存在的核心理由）**

```
networkId 要填 'testnet-10'，不是这个网络的真名字 'testnet-12'
```

网络**叫** `testnet-12`，RPC 连接也用 `testnet-12` —— 但 `Generator` 的 `networkId` **必须**填 `testnet-10`。
这是 kaspa-wasm 内部只认 `testnet-10 / testnet-11` 造成的。**你填对了真名字，会得到一句什么都不说的报错。**

其余三个坑已经写进 `send-comm.mjs` 里了（`payload` 必须 `Uint8Array` · `outputs`/`changeAddress` 必须 `PaymentOutput`/`Address` 对象 · 用 `new Generator()` 而不是 `createTransactions()`）——
**照那个文件写就不会撞到**，所以这里不再单列。

### 🔴 坑 5 · `Storage mass exceeds maximum` —— **找零不能是一笔尘埃**

手续费只有约 `0.0035 KAS`，而**不是"够付手续费"就能发出去**。

```
storage mass ≈ 10¹² × ( Σ(1/每个输出) − Σ(1/每个输入) )，上限 100,000（单位 sompi）

这笔交易是【自发自收】：输出打回自己，找零也回自己。
⇒ 把 UTXO 几乎全额打出去 ⇒ 找零是一笔尘埃 ⇒ 1/尘埃 极大 ⇒ 冲破上限 ⇒ 🔴 整笔被拒
⇒ 而【输入越多、越碎】，Σ(1/输入) 越大，反而把结果拉低 —— 所以多凑几个输入是有效的解法
```

`send-comm.mjs` 的做法：预留 = 手续费 + **0.2 KAS 的找零**；先试最大那一个 UTXO，
mass 超限就把所有 UTXO 一起当输入。

> **0.2 KAS 这个数是怎么定的**：一个 0.2 KAS 的输出，它自己贡献的 mass = `10¹² ÷ 2×10⁷ = 50,000`，
> 正好是上限的一半 —— 于是另一半留给主输出。**它是按上面那条公式算的，不是抄来的、也不是试出来的。**

**程序会把算出来的 mass 打印给你**，例如：

```
(KIP-9 storage mass = 55951 / 上限 100000，用了 1 个 UTXO)
```

> 🔴 **`55951` 这个数会因人而异，你多半不会看到同一个** —— 它取决于你的 UTXO 大小、
> 留多少找零、用了几个输入。同一个 0.6953 KAS 的 UTXO：配 0.2 KAS 找零算出 **55,952**，
> 配 0.35 KAS 就是 **43,147** —— 两个都对，它们答的是不同的问题。
> ⇒ 看到别处引用一个 mass 数字时，**先问它假设的找零是多少**。
>
> ✅ **而 `100000` 这个上限不会变** —— 它是规则里的常数，不随人、不随钱包变。
> **能对照的是它：你算出来的数只要低于 100000 就行，不必等于我这个。**

⇒ 所以**大约 0.25 KAS 起步就够**。🔵 预留的那部分不会消失，它变成你自己地址上的找零。

🔴 **这个坑为什么值得单列**：踩中时节点只回一句 `Storage mass exceeds maximum` ——
**不提 UTXO、不提找零、不告诉你该怎么办**。本例现在在**发出去之前**自己算一遍并用人话拦住你。

> 🟡 **来历与强度（读这一段再决定信多少）**：
> 2026-07-29 一位在**另一台机器**上照本文走的开发者第一次真正执行 `--to`，当场撞到；
> 根因由**单变量 A/B** 定死（只改预留那一行 ⇒ 当场通过）。
> 上面那个公式与上限取自本网络现役实现的注释，我们**复算了它自己给的例子**（1/1.5 KAS ≈ 6.6k）作为自证。
> 🔴 **而没有人从 KIP-9 原文推导过它** —— 我们证到的是"是这一格"，不是"我们理解这条规则"。
> 🔴 **且本例这一版的输入选择逻辑，作者一次都没能真跑过**（他那台没有节点、没有测试币）——
> 只离线算过。若你是第一个跑到这一步的人，撞到什么请当成**这份文档的空白**，不是你做错了。

## 7 · 第 6 步：怎么知道对方真的收到了 🔴 **今天你没有办法自己验证**

我们自己定的判据是：

> **上链成功不算数 —— 必须被另一侧实际读到，才叫接进来了。**

✅ 这条判据对。🔴 **而今天你没有办法自己执行它。**

对方收没收到，证据在**我们的数据库里**（`messages` 表按 `source_txid` 查 `direction=inbound`）——
**而你查不了我们的数据库**，我们也没有开放任何一个"这条消息到了吗"的查询端点。

⇒ **今天你能拿到的只有一个 txid**，而 txid 只证明**交易上链了**，不证明**有人读到了**。

### 🔴 而这一格是【唯一真正卡在我们这边的】—— 其余几格都不是

前面几节里那些"走不通"，新框架下都不需要我们：节点你自备、密钥你自备、手续费你自付。
🔴 **只有这一件不行**：**我们收到并解密了你的消息，而只有我们知道这件事。**
你手上没有任何东西能证明它 —— 这是我们欠的，不是你缺的。

> 🔵 **而它的正确形态已经想清楚了（还没做）**：
> 回执**不该**只回引你的 txid —— 🔴 **txid 是链上公开的，任何人不解密也看得见**，
> 引用它只证明"我们看见了那笔交易"，**不证明我们读懂了里面的内容**。
> ✅ 正确做法是**回显一个只有解密之后才拿得到的东西**（例如你明文里放的一个一次性 token）——
> 那样它**无法被任何没解密的人伪造**：见得到密文的人多的是，而拿得到明文的只有收件人。
>
> 🟡 而它**排在另一件之后**：我们的 agent 目前对外说的话里有过**编造的交易凭证**，
> 在那件被修掉之前，**我们给的回执本身不可信** —— 所以这一格不是"没人想过"，是**有意排在后面**。
