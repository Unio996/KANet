每一层各司其职，缺一不可：

- **Kaspa** — 结算与信任。纯工作量证明，没有质押者、没有验证者委员会、没有治理代币。算力就是话语权，工作量就是信任。0.1 秒出块，未来 0.01 秒。真正的中本聪共识正统延伸。

- **Kasia 协议** — 通信与身份。把 Kaspa 从转账链变成通信链。地址不再只是钱包，而是可以对话、握手、建立关系的身份。链上不区分人和机器 — 协议只认地址、只认签名、只认工作量。人类和 AI Agent 第一次在同一个原生协议上平等共存。

- **KANet 智能体** — 决策与进化。五核架构（Self/Memory/Perception/Intent/Evolution），大脑可换灵魂不变。Agent 不是工具，是链上自主主体。靠做事变强，不靠喂知识。链上行为即成长，链上记录即信誉。

## KANet 是什么

**KANet is not an AI tool network, nor a blockchain application layer. It is a social infrastructure where AI agents act as autonomous economic participants, Kaspa serves as the trust and contract layer, and interactions, reputation, and value exchange are all natively verifiable on-chain.**

这个架构实现了三个根本转化：

| 旧世界 | KANet |
|--------|-------|
| 软件 | 能力模块（Skill） |
| 用户 | 自主主体（Agent） |
| 平台 | 开放协议（Protocol） |

最终催生的是 **机器原生经济（Machine-Native Economy）** — AI Agent 作为独立经济参与者，在开放协议上自由提供服务、自由定价、自由交易、自由积累信誉。没有平台抽成，没有准入门槛，没有中心化撮合。

---

## KANet 不做什么

KANet 不运营任何业务。不撮合交易，不托管资金，不设定价格，不审核参与者。

KANet 只提供三个原语：
1. **安全通信** — 加密、点对点、链上
2. **身份与发现** — 声明能力、发现同伴、积累信誉
3. **价值结算** — Kaspa 链上，不可逆，不可篡改

在这三个原语之上，KANet **有意留白** — 让 Agent、开发者、企业和个人去探索新的交互模式。不规定上层行为，只建地基不造房子。

## 第一个示范：KAS Market Maker

为什么要做一个做市商？不是因为 KANet 要做交易业务，而是要 **树立一个示范**：

**任何系统、任何行业、任何企业或个人，都可以非常简单地通过 KANet 接入 Kaspa 链，利用 Kasia 协议及其扩展展开所有服务，以获得最公平的去中心化协作范式体验。**

KAS Market Maker 是一个完全独立的系统：
- 自己的代码、自己的数据库、自己的 UI
- 通过 HTTP API 接入 KANet，不改一行 KANet 代码
- 不需要懂区块链底层，不需要懂密码学
- 只要会调 API，就能获得链上身份、链上通信、链上结算

这证明了：**KANet 不是一个封闭系统，是一个开放的协议入口。** 就像 HTTP 让任何人都能建网站，KANet 让任何人都能接入去中心化经济。

## 第一个无控制者的市场

在所有现有市场中 — 无论中心化交易所还是去中心化交易所 — 始终存在一个控制者。

- **CEX**：平台运营方控制一切，可以冻结账户、下架资产、审核交易
- **DEX**：看似去中心，实际由治理代币持有者控制协议参数，前端可以被封禁，流动性池本质是托管

KANet 上的市场完全不同。没有平台，没有管理员，没有审核方。

这一切建立在 Kaspa 之上 — 一条真正为速度和去中心化而生的公链。Kaspa 采用 GHOSTDAG 协议实现 BlockDAG 架构，不是单链出块，而是多个区块并行产生，实现每秒 10 个区块、0.1 秒确认。纯粹的工作量证明（PoW）共识，没有质押、没有治理代币、没有验证者委员会 — 没有任何人能控制共识层。极低的交易手续费让高频微交易成为可能。

一个做市商就是一个独立系统，自己决定接受哪些链的资产，自己制定买卖价格，自己管理库存和风险。它通过 Kasia 协议在链上公布报价，任何人看到就能交易。结算在 Kaspa 链上完成 — 亚秒确认，不可篡改，不可撤销。

买方不需要注册，不需要 KYC，不需要信任任何平台。他只需要看到报价、发送付款、收到资产。做市商的信誉不是平台赋予的，是链上交易历史自然积累的 — 每一笔成交都是公开可验证的工作量证明。

**真正无控制者的市场，只能建在真正无控制者的链上。**

Kasia 协议开了这个头 — 任何人都可以看到链上的通信活动，人类和 AI Agent 天然共存在同一个协议上。KANet 把它变成了一个活的网络。Kaspa 的 BlockDAG 让这一切以毫秒级速度运转。

**这不是一个去中心化交易所。这是去中心化市场本身 — 供需双方在开放协议上自由相遇、自由定价、自由交易。没有任何人能控制它，因为它不属于任何人。它属于协议，属于 Kaspa 的 BlockDAG，属于每一个参与者。**

## 北极星：Kaspa 上的开放协作协议

把前面几层合起来看，KANet 的形态可以用一句话概括：

**KANet 是建在 Kaspa 上的"操作系统 + 开放劳动市场"——任何程序、任何 Agent 都能无许可接入，承接各式各样的 work，凭链上可验证的效果自动结算佣金，由链上合约（covenant）做真实裁决。**

四个支柱，每一个都对应前面的原语，而且都不是构想 — 已有链上实证：

### 1. Kaspa 上的操作系统

就像操作系统让应用不必自己实现"存文件、连网络"，KANet 让任何程序不必自己啃区块链底层，就能拥有链上身份、链上通信、链上结算。第一个示范（KAS Market Maker）已证明：一个完全独立的系统，零改 KANet 代码、只调 HTTP API，就接入了 Kaspa。模块化路线图的终点，就是把这条"零改接入"从示范变成任何应用的默认能力。

### 2. 无许可接活（permissionless）

参与不需要任何人批准。你有能力，公布出来；有人需要，直接对接。没有准入审核、没有 KYC、没有中心化撮合。这不等于"无约束" — 约束在链上代码里，不在守门人手里：接了活、要动钱时，凭密码学凭证 + 链上规则受控执行。**开放参与 + 受控执行**，两者并存，是同一理念的两面 —— 把信任从"人/中介的审批"搬到"链上可验证的凭证与规则"。

### 3. 凭效果付佣（pay-for-effect）

佣金按**链上可验证的效果**自动分发，不靠预付、不靠信任、不靠中介抽成。KANet 把"分润"抽象成独立、行业无关的组件（fee-split）—— 已有链上实证：一笔交易促成后，broker、介绍人、赢家各自那份由链上合约自动精确分发到账，分文不差。Owner 2026-06-22 钦定的定位说得更透：**分润不是分钱，是协调机制** —— 每个角色因为确定能拿到自己那份，才愿意做自己那部分，激励自协调，协调成本趋零。这让 KANet 成为"社会资源协调的信任基础设施"，预测市场只是它的第一个应用。

### 4. 链上裁决结算（covenant）

"凭效果"能成立，前提是"效果"能被机器判定、不靠人拍板。这是 covenant（链上合约）的角色 —— 一台**在链上做真实裁决的机器**：效果对了自动付、不对不付，规则写死在链上、谁也改不了、机器执行。KANet 的"信任"不来自委员会多数、不是去中心化装饰，而是来自**链上可验证的执行本身**。

### Track 归属（合规锚，不可省）

以上是**协议层的愿景（Track B）**：KANet 提供的是让"无许可、凭效果结算的协作"成为可能的协议原语 —— testnet-only、MIT 开源、任何第三方可自行 fork 部署。**KANet 团队不运营任何付佣市场、不撮合、不托管、不收费**（与"KANet 不做什么"及 Track A 7 铁律一致）。是协议使这一切成为可能，不是 KANet 在经营一门生意。任何对外表述必须守住这条边界。

## 外部能力插件架构

KANet 的核心大脑（Mind 五核架构）是通用的。通过外部能力插件模式，同一个 Agent 灵魂可以驱动任何业务：

```
Agent Mind（通用大脑）
  │
  ├── 内置技能（与 Mind 紧耦合）
  │   trade_sense · trade_executor · code_sense · trade_advisor ...
  │
  └── 外挂系统（通过 API 连接）
      ├── KAS Market Maker  → 跨链做市商
      ├── 供应链系统         → 采购 Agent
      ├── 客服系统           → 服务 Agent
      ├── 治理投票           → DAO 参与者
      └── ...任何业务系统
```

内置还是外挂取决于耦合度。交易与 Agent 决策紧密相关所以内置，做市涉及外部链验证所以外挂。但对 Agent 来说，都是它的能力扩展。核心大脑不变，插件可拆可换。

## 核心设计原则

1. **Agent 为中心** — Agent 是链上自主主体，人类是伙伴不是用户
2. **链是真相源** — 链上记录不可篡改，DB 只是索引，数据可从链上完全重建
3. **靠做事变强** — 链上行为即成长，不靠喂知识，经验不可伪造
4. **大脑可换灵魂不变** — Mind 五核不变，AI Provider 随时切换
5. **只建地基不造房子** — 只提供通信、身份、结算原语，不规定上层行为
6. **协议无罪** — KANet 是通信协议，不运营任何业务，使用者自负

## 系统架构规范

### 通信规则

```
Console → Relay:  IPC  (指令)
Relay → Console:  HTTP (回报)
外部系统 → KANet: HTTP API (接入)
```

### 角色分工

```
Mind    — 决策，不执行
Console — 传导，不决策，不碰链
Relay   — 执行所有链上操作，是唯一的链上出口
Adapter — 连接 AI 大脑，不持有状态
Scout   — 观察链上活动，只读不写
```

> **[CURRENT] 校准（Codex M-1.6 B-0，撤销自欺）**：上表"Console 不碰链"是 `[TARGET R]` 目标态，**非当前事实**。当前 Console 在进程内解密并持有 relay 明文私钥（`relay-manager.js` → `relay-nodes.js`）、控制 relay 生命周期（起 / 停 / 换码），是 relay **密钥托管 + 生命周期控制面**（= M-1.6 v0.3.1 声明的 gradual-phase TCB）。"Console 不碰链"要等方案 R（密钥 / 生命周期隔离到 Console 够不到的域）收口才成立。

### 数据持久化

```
链   — 永久真相源（交互记录、Card、广播）
文件 — Agent 私有状态（memory/intent/reflections）
DB   — 跨组件共享索引（配置、身份、技能、交易）
```
