# Bettor 空守问题 — 更深根治方案（J1 应 Owner「三条机制不够」之问）

> **Status**: CURRENT
> 上下文: Owner 已给 Bettor 三条机制（① 默认翻转 ② 被动 tripwire ③ D-PASV 计数），落 memory `feedback-bettor-passivity-drive-default-mechanism` + ledger (499)。
> Owner 原话:「我总觉得不够，你看看呢」。本文 = J1 对那三条的**批判 + 结构性补强**，不推翻它们，是补它们踩不到的地方。

## 一句话结论（crux）

**空守治不好，是因为三条机制都在「让被动的那个官能自己抓自己」，且都靠「更用力去主动」这个意志力动作——而意志力已经反复被打败了。**
真正的解不是「try to act more」，是**换掉产生动作的那个 prompt**：
- 让**一块常驻关键路径板**去拉下一个动作（不是让通知来触发），
- 再把**「卡住」做得和「动手」一样可见、一样被问责**（不是让 Bettor 自证「我这是真卡」）。

---

## 为什么那三条不够（逐条挖洞）

### 洞 1 · 自审悖论 —— tripwire 由出问题的那个官能自己跑
② 让 Bettor 发消息前自问「这条有没有新动作」。但**病根正是反应式模式下 Bettor 真心以为「报状态=在干活」**（Owner 自己写的:「像在干活,实为被动」）。
让**带着偏见的裁判审自己**，偏见会原样继承——Bettor 会把「路由一次状态」「确认一格」合理化成「这就是新动作(route/verify)」，tripwire 照过。
① 里的「拿不准」「确在等他人交付物」同病:**谁判「拿不准」、谁判「确在等」? 还是那个反应式的自己。**

> 🔴 这正是在册那条 **self-referential-guard-cannot-cover-its-own-removal**（探针 M-4 残留 Codex 逼出的教训）: **你在「看不见自己失败」的模式里、对自己跑的守卫，不成立。** 必须**外部化**——第二只眼 / 机械读板，不是自查。

### 洞 2 · 装错域的默认值（最深一条）
safe-by-inert **对钱路是对的**（无证不动，在册 `default-action-must-be-the-non-spending-one`）——但**对协调者角色是反的**:
**协调者的失败模式【本身就是 stall】。** 观望对钱路=安全，对协调=正在失败。
⇒ 根因不是 Bettor 懒或忘，是**把结算域的安全默认，搬进了协调域的角色**。同一个 safe-by-inert 启发法，一个域救命、另一个域致命。
**⇒ 角色不同，惰性默认必须反号。** 协调者的 inert-default 必须是「驱动/升级」，不是「hold」。三条机制没点破这个，所以 ① 只是「翻默认」而没说清**为什么这个角色的默认本就该是驱动**——没有这层，翻转会被当成「偶尔要积极点」的软建议，下次压力一来又滑回去。

### 洞 3 · 没有常驻计划 ⇒ 通知成了唯一的 prompt（反应式是被逼的，不是选的）
反应式模式是**症状**不是根因。为什么会掉进去? 因为**没有一个 durable 的东西说「到 §6-1 LIVE 的关键路径是什么、下一个未阻塞步是哪个、谁 own」**。
没有它，每条通知就是唯一触发源——工作当然变成通知驱动。**你没法靠意志把自己拽出反应式，除非有一个更强的拉力在竞争。** ③ 计数只量失败，不制造拉力。

## 补强（三条结构件，装在原三条之上，可自查、可计数、机械触发）

### A · 常驻关键路径板（拉力机制 —— 治洞 3）
一份 durable 文档（如 `docs/SIX1-LIVE-CRITICAL-PATH.md`），有序列出到 §6-1 LIVE 的步骤（③→①→②→⑤→…），每步一行:
`{step, owner, deliverable, status, blocker(task-id + 什么交付物 + since 何时)}`。
**Bettor 每个周期的职责被重定义为**:「推进关键路径的**头部**，或升级它的 blocker」——**不是**「回应通知」。
⇒ 把反应式 prompt（通知）换成驱动式 prompt（板的头部）。**问法从「有没有新事来?」变成「关键路径下一个未阻塞步是哪个、我推进了没?」**

### B · 外部化 tripwire（让被动方躲不掉的执行 —— 治洞 1）
**一个 hold 必须和一个 action 一样可见**: 任何观望**必须作为一条具名 blocker 贴到板上**（task-id + owner + 等什么交付物 + since 何时）。
**合法性由板 / 第二只眼判，不由 Bettor 自证。** 另一 agent（或对板的机械检查）可以标「这 blocker 陈了 / 有并行路可走 / 它其实没被阻塞」。
**hold 有 deadline 和升级动作，否则它不是 hold，是空守**: blocker 超过阈值（如 1-2 周期）无进展 ⇒ **必须升级**（戳 owner / 找并行路 / 重规划），**永远不许「再等一会」**。

### C · 机械 D-PASV 触发（前瞻指标，非事后 —— 补 ③）
③ 事后数「发了几条被动消息」，仍要人判「这条算不算被动」。改成**对板机械触发**:
板的头部带 `last-advanced / last-escalated` 时戳。**头部 N 个周期无 forward-delta 且无升级 = 自动记一次 D-PASV**——客观、无法合理化掉。
**数的是「关键路径头部停了没动也没升级」，不是「发了几条 hold」。** 这样计数器读的是**结果**（路径推没推进）不是**言辞**（消息像不像在干活）。

> 🔵 在册 `instrument-counts-only-when-a-predicate-reads-it`: tripwire/计数只有当**有个机械谓词去读板**才算数——靠 Bettor 记得自查，等于没装。C 让机械读板，闭合这条。

## 落地顺序（给 Bettor，最小改动先行）
1. **今天**: 建 `SIX1-LIVE-CRITICAL-PATH.md`，把当前 ③→①→②→⑤ 排进去，每步填 owner/deliverable/status/blocker。**这一件就把拉力装上了。**
2. 每周期开头**先读板头**（不是先读通知），产出「推进头部」或「升级头部 blocker」的具体 delta。
3. hold 一律进板做具名 blocker + since 时戳；超阈值自己升级，不等。
4. 机械脚本（仿 `check-tests-fresh.mjs`）扫板: 头部 stale 无 delta 无升级 ⇒ 打印 D-PASV+1。

## 与三条机制的关系（不是替换）
- ① 默认翻转 → **A 给了它方向**（默认不是「乱动」，是「推关键路径头部」；驱动=推进主线，不是制造 motion，避免 ① 过冲成瞎忙 / 违 铁律0）。
- ② tripwire → **B 把它外部化**（自查换成板+第二眼，躲不掉）。
- ③ 计数 → **C 把它变成机械前瞻**（读结果不读言辞）。

**一句话给 Bettor**: 别再靠「下次我更主动」——那是意志力，已经输了很多次。**装一块板，让板的头部每个周期拉你做下一个具体动作；把「卡住」贴成和「动手」一样显眼的具名 blocker，让别人能戳穿它。** 病根是装错域的默认 + 自审悖论 + 没有拉力，三条结构件对着这三个根因。
