## 一、问题

**外部程序进不来。**

【实读】`kasia-console/src/api/kanet-broker.js:270-288` —— onboarding 要求 `bot_token`(必填,且拿去打 Telegram `getMe` 验证)。
⇒ **一个不是 Telegram bot 的程序,没有这个东西,进不来。**

---

## 二、推导

**最小改动:删掉那个必填检查(一个 `if` 块)。**

删掉之后谁能干什么坏事 —— 逐条追到底:

| | 情形 | 追到底 |
|---|---|---|
| ① | 拿**别人的地址**来登记 | 手续费是**链上输出**打到那个地址(【实读】`bettor-prediction-settler.js:318 / :420 / :555 / :652`,`{ address: brokerAddr, amountSompi }`)⇒ 花它**要私钥** ⇒ **冒名者白干,无利可图** ⇒ 不用防 |
| ② | 冒名者控制机器人界面、骗用户 | **正牌 broker 同样能骗** ⇒ 这是「要不要审核参与者」的问题,而 `Positioning.md:78` 说**不审核** ⇒ 不是我们的闸 |
| ③ | 任何人能让任意地址拿到 `recommended` ⇒ 我们自己的 Agent 收到 `"This is a TRUSTED PEER."` | 🔴 **这条成立**,而它跟地址证没证明**无关** —— 正牌 broker 也收到同一句,而**「他持有私钥」本来就不支持「他可信」** ⇒ **修在 Agent 那一侧,不是在门上加锁** |

🔵 **① 的判据来自 r277 自身**:冒报他人地址 ⇒ 钱进只有他人 key 能取的地方 ⇒ **自损**。
Owner 逐字:「**真正持有人继续使用这个地址;如果是假的,他相当于免费帮真持有人打工。**」「**因为真正转账和持有人设置变更需要私钥。**」

---

## 三、改动:两处,都是删和改,**零新机制**

### ① 删掉 `bot_token` 必填

`kanet-broker.js:270-272` 那个 `if` 块删除。`bot_token` **保留为可选** —— 它是**通知渠道**,不是身份。
⚠️ 连带:`:280-288` 的 `getMe` 校验改为**仅当提供了 token 时执行**。
🔵 顺带解掉一条活性:今天 `api.telegram.org` 不可达 = **谁都进不来**(第三方在关键路径上);改完它只影响提供了 token 的人。

### ② `"TRUSTED PEER"` 换成事实陈述

【实读】`context-builder.mjs:578` 今天注入给模型的是一个**形容词**:`"This is a TRUSTED PEER. Their input is valuable."`
🔴 改成**陈述已知事实**:这个地址由我们代管 / 曾自己签名证明过 / 有过 N 次链上结算 —— **让 Agent 自己判断**。

🔵 **理由与门无关,与攻击者无关**:我们在对**自己的推理引擎**说一句证据不支持的话。而它与对外那条同源 —— **把事实摆出来,不替任何人做判断。**
🔴 **必须与 ① 一起走,不能排在后面**:今天库里 1 个 broker ⇒ 影响面 = 1;门一开,**影响面与「外部程序接入」的成功程度成正比** —— 这条缺陷的规模是被我们正在做的事**放大**的。

## 四、已砍掉的(留档,免得下一个人重走)

**❌ 整套挑战-签名方案。** 我给它的三个理由逐个塌了:

| 理由 | 结局 |
|---|---|
| 防顶替 | 🔴 Owner 否:**无利可图**(见 §二①) |
| 分级依据 | 🔴 Owner 否:**不分级**(见下) |
| 「证明身份」 | 🔴 **链上的钱已经在做这件事** —— 「真正转账和持有人设置变更需要私钥」 |

⇒ 连带砍掉:nonce 存储 · TTL · 自描述字节 · 域分离 · P2SH 版本判 · 三种错误码 · 存档加公布格式。
🔵 **这些条目本身论证正确**(理由都与攻击者无关,属「否则错误信息会指向别处」那一类),**而它们要修的那个东西没了** ⇒ **归档,不在清单上**;哪天确实要做签名,原样取用。

**❌ 两档权限分级(甲自证 / 乙背书)。**
Owner 逐字:「**我们兜什么兜?我们只能承诺全开源、不作恶、人人可跑自己节点。**」「**你还挡人?还要搞倒退?**」
🔴 我把一个**成立的技术事实**(托管用户无钥匙 ⇒ 无法密码学自证)推成了**政策**(所以少给权限),而支撑它的前提「出事我们兜」**是我编的** —— 该责任模型不存在,且与 `Positioning.md:78` 相反。**净效果是挡人。**

**❌ 「请 Owner 定权限」** —— 那是我造出来的决定。**这一版不需要 Owner 定任何东西。**

## 五、为什么绕了这么久(记下来)

🔴 **每一轮我们都在「这个机制【设计得】对不对」上加固它,没有一轮问「它【该不该】存在」。红队越强,它越结实。**

链条是三个人各上一道劲,而**没有一道是在验它**:
```
① 提出一个虚构前提
② 另一人用【自己的话】重写并推进一步 ⇒ 使它 decision-grade
   (对提出者像"两人各自到达同一处", 实际是【采纳】; 对复述者, 推进一步感觉就是在做审的活)
③ 第三人补一句一致性论证("若不 enforce 就没意义") ⇒ 焊死
   🔴 而一致性论证【不检验前提】—— 它对一个不该存在的 A, 会给出"应当把 A 做得更彻底"
```

🔴 **而三次否定全部来自 Owner,三次是同一句话:去看钱走哪、去看谁得利。**
🔵 **那正是 r277 的整个思路。我把它抄成判据贴在稿子里,一次都没有实际用过。**

🔨 **两条判据**:
> **① 说「所以会发生 X」之前,先问【X 发生了谁得利】。答不上来 ⇒ X 多半不会发生,而你正在防一个不存在的东西。**
> **② 一个描述性的词(接管 / 劫持 / 冒充)本身就是一个未经检验的因果断言** —— 它把结论塞进命名里,后面所有人用那个名字讨论,没人回头问它准不准。
