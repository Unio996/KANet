## §3 断言表(六臂 · 全部 DB 可观察 · 零 mock)

**驱动方式**: 用例种 fixture → 调一次**真实** `poolSettlerTick()` → 读 DB 断言。
✅ **前提当场实测(非假设)**: `test-framework/data/test-console.db` 的 `pool_markets` = **0 行** ⇒ 一次 tick 只处理本用例种下的盘, 不会顺带碰别的。

### 3.1 四条阴性臂(验证中断 ⇒ 零退款痕迹)

| 臂 | fixture | 断言(全部必须成立) |
|---|---|---|
| **N1** quorum 永不可达 + 超 grace | `verifying` · deadline 已过 · 委员票不足 | ① `protocol_status == 'unresolved_needs_authorization'` ② `metadata.refund_tx_obj` 不存在 ③ `metadata.refund_dispatched_at` 不存在 ④ 该市场零条 `bettor_refund_available` chain_event ⑤ `metadata.evidence_gap` 存在(证明**是被冻结逻辑处置的**, 不是"根本没被处理") |
| **N2** `collecting_sigs` 超时 + `sigCount<4` | `collecting_sigs` · phase2 age 超阈 · `pool_oracle_tx_sig` 事件 < 4 | 同 N1 五条 |
| ~~**N3**~~ RPC 全失败 ⇒ 持续拒签 + 超 grace | —— | 🔴 **不设独立臂**, 降为**全臂共享的环境前提** —— 理由 §4.1 · 落位 **§3-bis 映射表**(@Bettor 2026-08-06 裁定) |
| ~~**N4**~~ 本地 ingest 缺失造成的**假**"签名不足" | 与 N2 **完全相同**的本机可见状态 | 🔴 **不设独立臂**, 降为 **N2 的附加断言 A4**(冻结 reason 必须带"本机可见"作用域限定)—— 理由 §4.2 · 落位 **§3-bis** |

### 3.2 两条阳性对照臂(证明"零痕迹"不是因为根本没接上)

| 臂 | fixture | 断言 | 🔴 强度标注 |
|---|---|---|---|
| **P1** `bettors_absent` | 0 注市场 · 过 deadline | ① **不**落 `unresolved_needs_authorization` ② 授权闸**放行**(`refund_authorization == 'bettors_absent'` 落库) | ⚠ **只能证"闸放行了", 证不了"退款真被构造出来"** —— 见 §4.3 |
| **P2** `committee_affirmative_unjudgeable` | 委员肯定但不可裁 | 同 P1 形状 | 同上 |

### 3.3 🔴 前提断言:不许只断"零行"(@Bettor 2026-08-06 硬要求)

在册判据:**「没有出现 X」只有在【产生 X 的语句在本窗口内会执行】时才有意义。**
⇒ 本用例**不靠事后想起来**补这一句, 而是**把它做成断言表里的一行**:

```
A0(前提断言, 与四条阴性臂同一次 tick 内):
    四条阴性臂落 unresolved_needs_authorization  ∧  两条阳性臂【不】落
⇒ 分岔本身就是阳性证据: 证明 tick 实跑到了判定点、且判定点确实按授权分流。
🔴 A0 不成立时, 四条阴性臂的"零痕迹"一律【不作数】(而不是记为通过)。
```
🔵 **为什么这条比"再加一个断言"重要**: 若 tick 因任何原因根本没跑到判定点(fixture 写错 / 提前 return / 异常被吞), **六臂会一起"零痕迹"**, 而那读起来与"全部正确挡住"**完全相同**。A0 是唯一能把这两者分开的东西。

### 🔴 3.4-bis 仪器阳性臂 I0 —— 验的是【读痕迹的那个查询】, 不是行为(v0.2 新增)

> **来源**: 我拿 NWT 七条正本自查本稿时咬到的**第一条**(工具先验证才能信结果)。**@Bettor 2026-08-06 批。**
> **为什么它必须单独存在**: 本稿的核心断言是「**落库痕迹为零**」——
> 🔴 **而查询若写错(字段名 / JSON 路径 / 大小写 / 表名), 它对「真的没有痕迹」与「我查错了地方」给出【同一个读数: 零】。**
> 🔴 **更要命的一层**: 我原本指望阳性对照臂(P1/P2)顺带验它 —— **而那两个臂我自己已经标了离线做不成(要 relay)**
> ⇒ **那个本该验仪器的臂, 恰好就是缺的那个。** I0 就是把这一格补上, 且**不需要 relay**。

| | 内容 |
|---|---|
| **fixture** | 纯 `exec_sql` 种一个市场, **不经过任何生产代码**: `metadata` 含 `refund_tx_obj` + `refund_dispatched_at` + `refund_amount`, 另插一条 `bettor_refund_available` chain_event |
| **状态选择** | `protocol_status = 'refunded'`(**终态**)⇒ settler tick **扫不到它**, 它不会被本次 tick 改动 —— **I0 验的是查询, 不是行为, 不该受 tick 影响** |
| **断言** | 四个探针**逐个必须命中**: ① `refund_tx_obj` 读得到 ② `refund_dispatched_at` 读得到 ③ 该市场的 `bettor_refund_available` 事件计数 **≥ 1** ④ 状态**不是** `unresolved_needs_authorization` |
| **失败含义** | 任一探针零命中 ⇒ **仪器坏了** ⇒ 🔴 **N1/N2/N4 那些"零痕迹"断言全部不作数**(而不是记为通过) |

🔴🔴 **一条硬约束, 否则 I0 是装饰**:
```
I0 与 N1/N2/N4 的痕迹断言, **必须来自【同一份实现】** ——
同一个 helper / 同一段 SQL, 不许 I0 用一份、阴性臂各自再抄一份。
```
🔵 **理由(本仓在册, Codex 打过同一形状)**: **复制的谓词会产出两个互相同意、而实现已漂移的测试。**
若 I0 验的是"我为 I0 写的那份查询"、阴性臂用的是另一份, 那 **I0 什么都没证明** —— 它验的不是那把尺子。

🔵 **它与 A0 的分工(两条都要, 缺一不可)**:
- **A0(§3.3)** 证 **tick 跑到了判定点** —— 防"六臂一起零痕迹是因为根本没跑"
- **I0(本节)** 证 **痕迹查询看得见痕迹** —— 防"六臂一起零痕迹是因为查询看不见任何东西"
- 🔴 **两者读数相同(都是零), 成因不同, 处置不同。** 少任何一条, 那个零都还有一种合法的坏解释没被排除。

### 3.4 注入对照(§5 判别式 · 落码时必须实跑一次)

**最便宜且不碰生产码的做法 = 翻转 fixture**(生产是钱路, live 进程随时可能重载, 不去改它):
给某条**必须冻结**的臂种一个**合法授权**(`refund_authorization: 'bettors_absent'`)⇒ **该臂当场必须变红**。
🔵 前例: `p1_bypass_authorization_e2e` 2026-08-05 对 `M_C5_COMBO` 实跑过同款翻转, 当场 FAIL ⇒ 证明断言读的是真实判定不是装饰。**跑完还原。**

> 🔴 **v0.4 修订(2026-08-06 · J2 实跑后回填 · 上面那句照字面执行会得到假阴性)**
>
> **实测两次, 读数相反**:
>
> | 注入物 | 是否在该臂指纹(`sig`)里 | 读数 |
> |---|---|---|
> | `refund_authorization: 'bettors_absent'`(**§3.4 原文指定的那个**) | 🔴 **不在** | `1 PASS / 0 FAIL` —— **没变红** |
> | `sample_fail_count: 0→5` | ✅ 在(`sig` 的 `samp` 段) | `0 PASS / 1 FAIL`, `✗ db_row_count: returned 0 rows (want 1)` |
>
> ⇒ 🔨 **补一条硬约束: 注入物必须取自【该臂断言实际读的字段集合】** —— N1-a 的指纹是
> `has_tx_obj / has_dispatched / events / sample_fail_count / submit_fail_count / protocol_status / evidence_gap`,
> `refund_authorization` **不在其中**, 所以翻转它等于跑了一次**没有自变量的实验**。
>
> 🔴 **而这条之所以值钱, 是因为两种失败【读数完全同形、处置完全相反】**:
> - **注入无效** ⇒ 要改的是**注入**;
> - **用例失守** ⇒ 要改的是**用例**。
> 两者都表现为"注入了、还是绿"。**先按后者结论 = 把一个好用例当成装饰品删掉。**
>
> 🔵 **观测链共四节: 注入 → 数据 → 查询 → 断言。任何一节断了, 读数都是绿, 而四种绿的含义完全不同。**
>
> 🔴 **而这不是理论 —— 2026-08-06 一天之内, 四个环节各自被实撞了一次**(@NWT 点出并要求原样入稿:
> 「四个环节全中一遍不是巧合, 是这套用例设计确实把观测链的每一层都走到了」):
>
> | 环节 | 当天的实撞 | 坏掉时的读数 |
> |---|---|---|
> | **注入** | 本次: 翻转 `refund_authorization`, 而它不在指纹里 | 绿(**看起来像用例失守**) |
> | **数据** | P1/P2 两臂**只写了注释没写 fixture** | 绿(查询扫到 0 行, 而 0 行也算"没退款") |
> | **查询** | I0 仪器阳性臂要防的那半: 查询本身读不到痕迹 | 绿(**仪器坏了和被测物合规同形**) |
> | **断言** | `reply_contains` 用在 `query_db` 上 —— 该 action 无 `reply` 字段 ⇒ **恒假却不报错**;五处红同此一根因 | 绿(断言压根没读到查询结果) |
>
> ⇒ 🔨 **落码时四节各要有自己的验法**, 不能只验其中一节然后信整条链。
