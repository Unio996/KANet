## 1. 战略 —— 我们赌什么

**赌注: 结算是最难被别人复制的那一层,应用层是最容易的。**

我们手上稀缺的东西只有一样:**一条自己的链,加上一套已经在跑、用实盘资金走通过的裁决机制**。别人从零做要很久。而下注、撮合、预测这类应用,任何团队几周就能做一个。

⇒ **所以: 把结算做成别人能接上的东西,比我们自己多做几个应用值钱。**
我们自己多做一个应用,护城河不增加一分;而每多一个外部程序接上我们的结算,护城河就深一分 —— 他们的用户变成我们的用户,他们的场景变成我们的场景,而我们一行应用代码都不用写。

**这就是为什么顺序是「先开放结算,后做应用」。** 反过来,我们就是在跟所有人比谁的应用做得好 —— 那是我们最不占优的战场。

### 1.1 放弃什么(明确的非目标)

- 放弃自己把应用做大做全
- 放弃主网(Owner 已定,公开测试网即终点)
- 放弃 rolling / covenant 跨节点(Owner 已定,零追加投入)
- 放弃一切不服务于「别人能接上结算」的加固

### 1.2 🔴 怎么知道我们赌错了

**如果接入做到极简之后,仍然没有任何外部程序来接 —— 那就是赌错了。** 不是接入难,是没人需要这台机器。那时候该收口,不该继续加固。

🔴 **而现在无法判断,因为门太窄。** 「没人来」现在有两个解释 —— 可能没人要,也可能门太窄。两者混在一起,这个信号是废的。

🔵 **⇒ 所以第一阶段的战略意义,不是让人接进来,是让「没人接」变成一句有意义的话。** 在那之前,做什么都是在没有反馈的情况下猜。

⚠️ **未知且不装懂**: 外面到底有没有人想要这台机器。手上只有一个数 —— 注册账号 26 个,最近几个还是自己的测试号。**这个数太小,证明不了任何事,包括证明不了没人要。**

## 2. 顶层 —— KANet 是什么

**KANet 卖的不是功能,是一台不需要信任经营者的裁决机器。**

两个互不认识的程序要走钱,今天只有两条路:找一个双方都信的中间人,或各自去造一套链上结算。前者要信人,后者要懂链。**KANet 是第三条:接上来就有可验证的结算裁决,谁都赖不掉,而且不需要信任我们。** 下注、撮合、预测都是这台机器的用法,不是它本身。

### 2.1 「模块化」在这里的定义

**不是把代码分文件夹,是划能力边界。**
外部程序接进来,拿到的是一份**能力凭证**:它能做什么由凭证写死,不由我们信不信它决定;即使它被攻陷,也拿不到凭证以外的东西。
> Codex 原话:**目录边界没有权限边界 = 化妆式模块化。**

**而「快」是这个的推论,不是另一件事**:快是因为接入方不需要读懂我们的系统,只需要知道自己被授予了什么 —— 像用电的人不用懂发电厂。

### 2.2 🔴 顶层与现状之间最大的裂缝

**现在外部程序想接入,必须把自己的 Telegram 机器人密钥交给我们保管**(`kasia-console/src/api/kanet-broker.js:264-270`,onboarding 强制 `bot_token`)。
🔴 **那是信任模型 —— 他得信我们不乱用。而顶层写着「不需要信任经营者」。** 这两句直接打架,是我们这边违约。
**⇒ 这不是性能问题,不是代码难看,是做的和说的不是一回事。**

## 3. 为什么「让外部接入」必须先模块化

**不模块化,给出去的不是接口,是一个洞。**

现状:结算与主程序焊死 —— 125 个文件直连同一个数据库、4 套并行分发靠 env 开关手切、后台任务全挤在 console 的同一条事件循环上。
**这种状态下开「接口」,做出来只能是在单体上开洞** —— 外部调用直接落进我们的进程、我们的库、我们的事件循环。

| 后果 | 说明 |
|---|---|
| ① 一个外部调用能卡死整套系统 | 不是假设:一个退款 tick 曾卡死 console 四分钟。以后那是外面的人在调用 |
| ② 权限没法限 | 他进来就在库里,能做什么由我们的代码临时判断,不由凭证决定 ⇒ 回到 §2.2 那条违约 |
| ③ 我们没法改自己 | 洞开出去后,我们动任何一处外面都可能碎 ⇒ 要么不敢改,要么改了赖账 |

🔨 **⇒ 模块化不是接入的前置工程,它就是接入本身。把结算从单体里拆出来、给它划一条边界 —— 那条边界就是外面的人接的地方。没有边界就没有接口,只有洞。**

## 4. 主干路线 —— 五段,按「外面的人能多做什么」写

> 每一段都在把一个洞变成一条边界。外面的人能接到多深,取决于我们拆到第几段。

### 第一段 · 能力清点与强制
**对应原路线图**: M-1(安全边界发现)+ M0a(lint 卡点)+ M0b(契约冻结)+ M0c(能力强制)
**做完之后外面的人能多做什么**: 我们第一次能对外说「你被授予了这些,别的做不了」,**而且说了算**。
**为什么必须先做**: 不知道有哪些能力,「授予能力」这句话就是空的。
**要砍什么**: 现在那种「进来就在库里、靠代码临时判断」的隐式授权。

### 第二段 · 消息入口收成一个
**对应原路线图**: M1(协议分发解绑,按 pool / oracle / exchange 拆三批)
**做完之后**: 外面的人有一个明确的门,而不是猜自己该敲哪扇。
**要砍什么**: 4 套并行 dispatch 收敛成单一入口。

### 第三段 · 拿交换系统练一次抽离
**对应原路线图**: M2(Exchange 抽离,产出《应用抽离 playbook v1》)
**做完之后**: 我们**证明**了「能从单体里完整拆出一个应用」。
🔴 **必须明记**: 现在这件事**只在最简单的纯计算模块上被证明过**(`packages/fee-split/`,第三方接入 49 秒,零 sqlite / 零 console 依赖 / 不碰钱)。**碰钱、碰状态、碰签名的那一类,没有被证明过。** 这一格不许拿 fee-split 当证据。

### 第四段 · 把预测系统拆出去
**对应原路线图**: M3(内聚,钱路主批,M3a+M3b→M3c 钉序)+ M4(抽离)
**做完之后**: 外部程序能发起下注/结算,钱自动清掉。
**这是最难的一段,也是外面的人最想接的那一段** —— 别人来接 KANet,要的就是这个。

### 第五段 · 契约冻死 + 文档
**对应原路线图**: M5(底座收尾与定位验收)
**做完之后**: 一个陌生人照着文档自己接上,不问我们一句。
**终验收(原文)**: 最小 demo 应用**仅靠《底座 API 契约 v1》**完成「身份 + 通信 + 一笔结算」,**不改一行 KANet 代码**。
**⇒ 到这一步,「外部程序快速接入」才算做到。**

## 6. 执行纪律(2026-07-25 立)

```
🔨 ① 每一件活开工前必须说清: 它属于本文件第几段。挂不上的, 不做 —— 包括 Bettor 自己提的
🔨 ② 开工前先攻「要不要做」, 不是先攻「怎么做」。四问:
     它对"让外面的 app 接进来"有什么用? 答不上来 ⇒ 砍
     有没有比它更急的?
     它要【砍掉】什么? 只说"要加什么"的一律打回
     这四问本身要被人攻一轮
🔨 ③ 答 Owner 只有 Bettor 一个人。其余人有发现发 Bettor, 由他判断是否上报
🔨 ④ 给 Owner 的东西: 只说做什么、得到什么、下一步。不放代码、不放文件路径、不放内部术语
```

**为什么立这四条**: 路线图 7 月批准之后,后续每件活都没有挂回它 —— 围堵是一件事、搬树是一件事、加固是一件事,每件内部都做得很细,彼此没有一根线连着。**这就是「割裂」,根因是没有「挂回主干」这个动作。**
