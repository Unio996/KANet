## 一、先把这个端点【会做什么】写清楚 —— 这是 §③ 原稿最大的缺口

NWT 的原话:**「§③ 整节只回答了『别把另外 8 条带上去』,没有回答『那 1 条自己上去之后,外面的人拿到了什么』。」**
实读 `onboard`,**每一个匿名请求**会让我们:
```
① 写库: INSERT/UPDATE broker_onboarding
② 🔴 托管一份【第三方密钥】(bot_token 加密落库)——【仅当调用方提供了 token】
③ 🔴 对 api.telegram.org 发一次【出向请求】,每次最多占住一个连接 8 秒 —— 同样仅当提供了 token
④ 间接: 有 token 的记录会让 broker-bot-manager 【fork 一个进程】
```
🔵 **而 ①② 落地后有两格已经变好,要说准(不然会高估风险)**:
- ~~onboard 写 `identities … trust_level='recommended'`~~ ⇒ **已删**。NWT 那条"匿名自助提权"(recommended 在消息闸上 120/时 + 多两档 authority)**已断**,且他把它列为 MUST-FIX A 的理由 —— 该前置**已达成并验收**。
- `bot_token` 变可选 ⇒ **不带 token 的请求根本不触发 ②③④** ⇒ 攻击者要撬动那三样,**必须自己交一个 token 串**。
🔴 **而这不构成安全** —— 交一个字符串是零成本。**所以真正的控制是下面三样,不是"它需要 token"。**

## 二、三样资源控制(NWT note-1;而我按仓里已有形态选实现,不新加依赖)

### ② bodyLimit —— 最便宜的一条
```
【实读】external-gateway.mjs:141  Fastify({ logger:false, exposeHeadRoutes:false })
⇒ 未设 bodyLimit ⇒ 用 Fastify 默认 1 MiB
🔨 改: 在这个【独立实例】上设 bodyLimit = 8 KiB
🔵 它作用于该口全部路由 —— 而该口的路由本来就只有两条(读频道 + onboard), 请求体都是几百字节量级
🔴 判据不是"设了", 是: 超限请求必须收到 413 而不是被静默截断
```

### ① 每 IP 限频 —— 复用仓里已有的两套形态之一,不装插件
```
【实读】仓里没有 @fastify/rate-limit 依赖。而已有两套自造形态:
  · capability.js:62  SQLite 事务里滑动窗口(按 grantId)—— 持久, 但每请求一次 DB 写
  · mind-manager.js:220 RATE_LIMITS 内存表(按 relation)—— 零 IO
🔨 选【内存滑动窗口(按 IP)】, 理由: 这个口是防滥用不是防欺诈, 且它在【独立实例】上, 不共享主实例状态
🔴 而它的边界必须写进码: 进程重启即清零 ⇒ 它挡的是持续刷, 不是"总量配额"
🔨 建议初值: 每 IP 10 次/小时(与 mind 侧 stranger 同档 —— 同一个语义: 我们不认识的人)
🔴 超限回 429, 且【带 Retry-After】—— 否则集成方只能靠猜
```

### ③ 并发上限 —— 它针对的是"慢速占用"那一条
```
🔴 NWT 抓的那格: 每个带 token 的请求占住一个连接【最多 8 秒】(getMe 的 AbortSignal.timeout)
⇒ 无并发上限时它是一条现成的慢速占用路径
🔨 改: 该口维持一个 in-flight 计数, 超过 N(建议 4)立即回 503 + Retry-After, 不排队
🔵 不排队是刻意的: 排队会把"拒绝"变成"更长的占用", 那正是要防的东西
```

## 三、`why` 字符串订正(NWT MUST-FIX B —— 而它不是文案题)

```
【实读】external-gateway.mjs 白名单条目的 why:
  「读链上已公开的消息。不撮合·不托管·不定价·不审核参与者(无任何我们发放的凭证)。」
🔴 加了 onboard 之后: 这个口【开始托管密钥】(bot_token)、【开始接收参与者】
⇒ ⇒ 那句自述【当场变假】, 而全仓其它地方还在引它当这个口的定性
```
🔨 **订正方向(措辞归审,但它必须同批改,不是顺手)**:
- 该条目的 `why` 要**逐条对齐 `docs/KANet-Positioning.md:78` 那四条原文**说清:onboard **不撮合、不定价**;而**"不托管"这一条对它不成立** —— 它托管一份第三方通知渠道的密钥。
- 🔴 **而模块头那段 deny 清单也要跟着看一眼**:它把 `POST /api/agent/create 铸身份` 列为"不放上来"的例子。
  ✅ 而 onboard **在 ② 之后已经不写 `identities`** ⇒ 它不再是"铸身份"的一种形态 ⇒ **NWT 那条反对已被 ② 消解**,这一格要写进注释,否则下一个人会以为我们无视了它。

## 四、验收(含从 ② 剥过来的 ⑤,每条带对照臂)

```
⑤ 白名单只放行那一条:
   从公网口打 onboard ⇒ 通; 打同文件其余 8 条中任意一条 ⇒ 【连不上】
   🔵 对照臂(不许省): 打一条【已知在白名单里】的路由(读公开频道)⇒ 必须通
      ⇒ 否则"全都连不上"与"网关没起来"读数相同
   🔵 而填错不会静默: 白名单要求【排序后完全相等】⇒ 多出的 8 条会让网关起不来并逐条列出
      —— 这是【失败会喊】的少数例子, 与今天大多数相反
⑦ bodyLimit: 超限请求 ⇒ 413。对照臂: 正常大小请求 ⇒ 仍 200
⑧ 限频: 同一 IP 连打超限 ⇒ 429 + Retry-After。🔴 对照臂: 换一个 IP(或等窗口过)⇒ 必须放行
   ⇒ 否则"全都 429"与"这个口坏了"读数相同
⑨ 并发: 并发发起 N+2 个带 token 的请求 ⇒ 至少 2 个立刻 503(不是等 8 秒后超时)
   🔴 判据是【立刻】: 若它们也等了 8 秒, 说明是排队不是拒绝 —— 那正是要防的
```
