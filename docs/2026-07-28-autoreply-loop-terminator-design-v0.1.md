## 0. 一句话

**「跑十几轮就会自己停」不是这个系统的性质,是那两个模型那一次恰好收敛到近似逐字重复的性质。** 今天**没有任何与内容无关的上限**;而唯一在拦的那道闸,**对中文近乎失效**。

### 0.1 为什么挂批零

它是**现役风险**:每一轮往返 = 一笔真付费链上交易,而公开测试网上任何两个开着自动回复的程序相遇即触发。依据路线图 §5.1 立的轴——**按现役风险分诊,不按发现来源**(Bettor 2026-07-28 裁定,显式加为批零第四项,非豁免)。

### 1.1 🔴 中文退化 —— 我从码上自己算了一遍,不是引用测数

```js
const wa = new Set(a.toLowerCase().split(/\s+/).filter(w => w.length > 2));
```
**`split(/\s+/)` 对没有空格的中文 ⇒ 整条消息 = 【一个 token】。** 于是:

| 两条中文回复 | token 集 | 相似度 | 结果 |
|---|---|---|---|
| 逐字完全相同 | `{整句}` vs `{整句}` | overlap 1 / max 1 = **100%** | ✅ 拦 |
| **只改一个字** | `{句A}` vs `{句B}` | overlap 0 / max 1 = **0%** | 🔴 **放行** |
| 完全改述 | 同上 | **0%** | 🔴 **放行** |

🔴 **⇒ 这道闸对中文退化成「只拦逐字全同」。** 而两个 LLM 之间**几乎不会**逐字全同。
🔵 **⇒ 那 17 轮能停,是因为那条回复恰好带了 `- 持仓:524 KAS` 这类【含空格的数字行】**,凑出多个 token 才算到 97%(NWT 实测)。**换一对措辞发散的 agent,或换成纯中文,它不会停。**

## 2. 🔴 结构论证:内容相似度**永远**不能当终止条件

```
终止条件必须满足: 无论对方说什么, 有限步内必然触发
而相似度闸的触发条件是【我这次生成的内容和我上次生成的内容像】
⇒ 它的触发【依赖生成内容的分布】—— 而那是我们不控制、也不可预测的
⇒ ⇒ 它是【尽力而为的质量过滤器】, 不是【上限】
```
🔵 **这是「『现在是对的』若依赖数据分布 ⇒ 那是运气不是断言」的又一实例。**

### 2.1 🔴 v0.2 强化(NWT 加的一格,比我原论证狠)—— 不是"我们不控制",是**对手控制**

```
我们的回复是【对面消息的函数】
⇒ ⇒ 🔴 想让循环继续的那一方, 可以通过【变换自己的措辞】来间接操纵我们回复的相似度
⇒ 任何以【内容】为输入的谓词, 都可被对手绕开
```
🔴 **⇒ §2 的结论因此从「经验上不可靠」升级为【结构上不可用】。** 相似度闸不是"拦不住聪明的对手",是**对手拥有让它永不触发的输入**。这条对 P0 的选型也是决定性的:**终止条件的输入必须完全在我们这一侧**(轮数/冷却周期数就是),不能有任何一格取自对面的内容。
🔴 **⇒ 所以把 `_wordSimilarity` 换成中文分词版,是【改进】,不是【修复】。** 谁都不许拿它报"洞堵上了"——它把运气的概率调高了,没有把运气换成保证。

## 3. 修法(三件,**主件是让循环不存在,不是把它拦住**)

### 🔴 P0(v0.2 新增·NWT MUST-FIX 1)· **计数器的复位语义 —— 不写它,交付的就是限速不是终止**

**v0.1 我写了"连续自动回复达到 N 次 ⇒ 停止 + 冷却 T",却没写【计数器什么时候归零】。NWT 指出这个空格决定成败**:
```
(甲) 时间间隔复位(🔴 最常见的写法)⇒ 对面把节奏放慢到 X+1 秒一轮 ⇒ n 永远到不了 N ⇒ 【永不触发】
(乙) 只有冷却 T 结束才复位      ⇒ 冷却完计数归零 ⇒ 循环【原样重开】⇒ 每个 T 周期再烧 N 笔
                                  ⇒ 总轮数【仍无上界】
⇒ ⇒ 🔴 两种都交付【限速】, 不交付【终止】。而 §2 明写要的是后者
```
🔨 **裁定:走 NWT 的②——做真终止,不做限速器。**
```
🔨 加一个【不靠时间自愈的终态】: 连续 K 个冷却周期仍在触发 ⇒ 该 peer 进 do_not_auto_reply
   🔴 只有【显式动作】能解除 —— 时间过去不解除。这是"终止"与"限速"的全部区别
🔴 不许留在"没写": 落码的人会按(甲)写(最自然), 而(甲)是三种里【唯一完全不成立】的
```
🔵 **⇒ 这一格是本设计 v0.1 最大的漏洞:我写了上限的【数值】,没写上限的【语义】,而语义才是它成不成立的地方。**

### P1 · 与内容无关的轮数硬上限(**承重件**)

```
状态: 每个 (relayNodeId, peer) 一个计数器 { n, firstAt, lastAt }
规则: 连续自动回复达到 N 次 ⇒ 停止对该 peer 自动回复, 进入冷却 T
      🔴 计数【不看内容】—— 这正是它区别于现有闸的全部意义
🔴 位置: 放在【调 Brain 之前】, 不是放在 :553
   理由: :553 是生成之后 ⇒ 每一轮仍然烧一次 LLM(实测 4632ms)。
        而与内容无关的判断【本来就不需要内容】⇒ 提前判是免费的
🔨 N / T 的具体值本稿不定死 —— 见 §5 未知格
```

### P2 · 对端是【本机 agent】时用更紧的上限

> 🔴 **v0.2 改(NWT MUST-FIX 2)**:v0.1 我提议用 `relayToName` 判"对端是不是本机 agent"。**NWT 实读:这张表做不了这件事,而错法是"看起来实现了"。**
> ```
> ① 初始化(:120-133)取数 = INNER JOIN adapter_nodes + address IS NOT NULL
>    ⇒ 🔴 没有 adapter 的本机 relay 【根本不在表里】
> ② 懒填(:178-185)只在某 relay【自己要回复时】把它自己加进去
>    ⇒ 🔴 【永远只加"正在回复的那个", 从不加对面那个】
> ⇒ ⇒ 回答我 §7③ 自己问的那个问题(漏了会怎样): 不是"退化成宽上限", 是【完全不生效】
> ```
> 🔨 **改用闸已经算好的那个值**:`evaluateSenderGate(:296)` **已经在按地址正确做这件事**
> (`SELECT id,name FROM relay_nodes WHERE address=? AND id!=?`),结果已在 `gate.meta` 里随 task 进队列。
> ⇒ **P2 直接读 `senderMeta.relation === 'sibling'`**:零新增查询,且**与闸用同一个值 ⇒ 两者永不漂移**。
> 🔵 **⇒ 这比我原提议好在:我要新算一次,而正确答案已经算好了躺在 task 里。**

```
🔵 事实: 自激往返需要【双方都是开着自动回复的 agent】。单侧不会(NWT 实测)
🔵 而"对端是不是我们自己的 agent"闸已经判过了 —— 用 senderMeta.relation === 'sibling'
⇒ 🔨 命中 sibling ⇒ 用显著更小的 N(甚至 1)
🔴 而这是【收紧上限】不是【禁止】—— 我们自己的 agent 之间的正常对话是既有行为,
   直接禁掉就是"为修一个洞打断一个在跑的功能"。不做这种交易
```

### P3 · 把相似度闸**显式降级**(这就是本设计要**砍掉**的东西)

```
🔴 砍掉的是它的【职责】, 不是它的代码:
   它今天在事实上承担着"终止条件"这个角色 —— 而它承担不起(§2)
🔨 动作: 保留为质量过滤器, 并在它上方写一行注释钉死:
   「本闸是尽力而为的质量过滤器, 不是终止条件。终止条件是 P1 的轮数上限。
     它对无空格中文退化成只拦逐字全同 —— 见 docs/2026-07-28-autoreply-loop-terminator-design。」
🔵 理由: 下一个人若看到"反正它拦住过一次", 会把它当保证。注释是唯一拦得住这个的东西
```

🔨 **⇒ 本设计砍掉什么(纪律②要求必答)**:砍掉「**相似度闸是终止条件**」这个**事实上一直在被依赖、而从来没成立过的假设**。P1 不是新加一层防御,它是**把一个本来就应该存在、但一直缺席的东西补上**。

## 4. 🔴 它对「让外面的 app 接进来」有什么用(纪律②第一问)

```
外部程序接入 = 公开测试网上会出现【我们不控制的自动回复程序】
⇒ 任何一个这样的程序遇到我们任何一个自动回复 agent ⇒ 触发往返 ⇒ 每轮一笔真付费交易
⇒ 🔴 而代价记在【双方】账上, 其中一方是外面的人
🔵 ⇒ 这不是内部整洁问题, 它是【我们把一个已知的花钱缺陷交给外面的人】
⇒ ⇒ 在公测之前必须有上限。这是它挂批零(must-not-slip)的实质理由
```
