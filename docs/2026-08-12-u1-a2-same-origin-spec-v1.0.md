## §1 目标与适用范围

**A2 要回答的**：两个委员身份是不是**同一份 mnemonic** 派生的。

**能与不能（这一条是规范的一部分，不是免责声明）**：
- ✅ **正向可证**：「这两个身份同源」——可由登记根相等 + 派生证明**密码学地**判定。
- 🔴 **反向不可证**：「这两个身份确实不同源」——**任何事后软件检查都做不到**。造钥方可以私下用一份 seed 派生到**另一个硬化账户**，只出示两个互不关联的根（硬化兄弟不可关联，实测在证据稿 §3）。
  ⇒ **反向保证只能来自生成仪式**（runbook §2 步骤 2 在目标宿主本地生成）。**C 边界，(159)/19:57Z 两次确认不变。**

⚠ **⇒ A1/A2 打勾 ≠ R3 有密码学保证。** 这条必须出现在**运行时输出**里（**V6**），不能只活在文档里。

## §2 规范条款（落码即照此）

### N1 · 登记根 = 账户层 xpub
登记根 **= `m/44'/111111'/0'` 的 xpub**。**不是** master xpub（跨不过硬化级，推不出子 pubkey），**不是** seed 指纹（与 relay pubkey 无可验链接 = 裁定要防的"换皮的 ②"）。

### N2 · 委员身份派生布局
```
m / 44' / 111111' / 0' / 0 / i
```
**登记根到每个身份的路径全程非硬化 ⇒ 验证方可从登记根推导出该身份 pubkey 并逐字节比对**（满足 (156) 硬要求）。

🔨 **N2 的作用不是"允许一根挂多身份"，恰恰相反**：它保证**同一 seed 的任何额外身份都只能落在同一个根下 ⇒ 一旦出现就【可见】**。旧布局下第二个身份藏在另一个硬化账户里 = **不可见**。

### N3 · `identities-per-account` **锁死 = 1**（@Bettor 19:57Z）
每个登记根**有且只有一个**注册身份（`i = 0`）。
🔴 **同一登记根下出现第二个注册身份 = 构造性违规，直接拒绝** —— 不需要任何仪式性判定、不需要人工裁量。
**后果（两条都要记）**：
- 泄露放大面**归零**：无兄弟可沦陷；那把子私钥本就等于该身份全沦陷，**无增量损失**。
- **零迁移成本**：现实本就 10 份 mnemonic ↔ 10 个 `is_oracle` 身份，一比一。

### N4 · 委员必须 mnemonic 型（(159) §8.3）
`privkey_encrypted`-only 身份**不入委员**（R1 的分配单位是一份 mnemonic，privkey-only 落在规则外）⇒ **登记时 fail-closed 拒绝**，拒绝理由可读。存量 2 个 privkey relay 维持现用途不受影响。

🔴 **N4-bis · `custody` 必须由服务端自己查出来，绝不收提交方的申报值**（v1.2-rc · @NWT 20:59Z MUST-FIX，我认）：
v196 的 `CHECK (custody = 'mnemonic')` **只能核这个字符串字面值等不等于 `'mnemonic'`，核不了它是不是真的**。
⇒ 若注册入口把请求方自陈的 `custody` 直接写库，这一列就**和 `root_fingerprint` / `identity_pubkey_xonly` 不是一类东西**了——
后两者有 N8 的 PoP 与派生证明护着，而 **`custody` 没有任何密码学能护它**，它会退化成"我说我是 mnemonic 型"。

**条款**：注册时 `custody` **由服务端从 `relay_nodes` 独立派生**——
`mnemonic_encrypted` 非空 **∧** `privkey_encrypted` 空 ⇒ `'mnemonic'`；**其余一律拒**（含两者皆非空这种混合态）。
**提交方即使带了 `custody` 字段也一律忽略**（不是"以服务端为准"，是**根本不读**——读了就迟早有人让它参与判断）。

🔨 **这条与 N8 是同一条纪律的两次出现**：**caller / witness / 提交方给的值 = 可控可伪**。
N8 那次撞在有密码学能护的字段上（所以能用签名解决）；**这次撞在一个没有密码学能护的字段上 ⇒ 只能靠服务端自查**。

### N5 · 两个逃逸口一起钉死（@J1tn `8969aca7` · 我原先只报了第二个）
| # | 逃逸口 | 钉法 |
|---|---|---|
| **①** | `relay-manager.js:70` 全量继承 `process.env`，`:86-87` 的 `else` 分支**不删继承来的 `KASPA_PRIVKEY`**，而 `wallet.mjs:105-118` **先读 `KASPA_PRIVKEY` 命中即 return** ⇒ **mnemonic relay 的签名身份被整个替换** | **spawn 侧互斥写死，且【双向】**：`if (privkey) { set PRIVKEY; delete MNEMONIC } else { set MNEMONIC; delete PRIVKEY }` |

🔴 **N5-① 的第二个方向不是对称强迫症，理由在这里**（@J1tn 21:12Z，我认，落码照此）：
privkey 分支里**继承来的 `KASPA_MNEMONIC` 今天是惰性的** —— 但它的惰性**只由 `wallet.mjs` 的一处优先级维持**（privkey 命中即 return）。
**那处优先级一旦被改动、或被一条新路径绕过，它就活了，而且是静默的。**
🔨 **判据（可推广）**：**把「靠某行【不存在】维持的保护」换成「靠某行【存在】维持的保护」** ——
后者被破坏时是**一次可见的 diff**，前者不是（它只是某个人某天顺手改了别处的优先级）。

🔵 **与 env 读数的关系（@J1tn ④）**：这两行落地之后，「console 进程 env 里没有这两个变量」这个**时点读数就不必再维持** —— **那时才是不变量**。在此之前「重启过就重读」成立，但触发条件可收窄成**「console 被人从一个新 shell 起过」**（启动侧 `kanet.env` / `kanet-start.sh` 零处设置这两个变量 ⇒ 它们只可能来自更外层 shell）。
| **②** | `KASPA_ACCOUNT_INDEX` 走继承（全仓一处读、零处写 ⇒ 只可能来自继承环境） | **不许走继承**：由 console 按 relay 显式传；解析结果 `Number.isInteger` 校验，**坏值抛而不是静默取 0/NaN** |

🔴 **N5 的作用域，必须与条款同页写死**（否则又是「局部性质写成全局保证」）：
> 钉死消除的是**无痕的、误操作即可触发的**同源隐藏路径（复制一份 env、换宿主、换运维）。
> **它不构成对敌对域运营方的约束** —— 进程跑在他自己的宿主上。对他的那一半，答案只有 §1 的 C 边界。
> 它换来的是：把「造第二个身份」从**一个环境变量**抬到**一次代码改动**（无痕 → 留痕）。

🔵 **未验一格（@J1tn 明确标注，别当已知）**：`parseInt` 坏值行为里 **`NaN` 那一支他没走到底**（要真走 wasm `deriveChild(NaN, true)`）。**落码时必须自己验，别引他那句当已知。**

### N6 · 登记根分发面收窄
账户层 xpub **只落库 / 只给验证方**，**绝不进 `dev-coord-testnet` 或任何公开面** —— 频道是**链上明文、不可撤回**（在册 `reference-dev-channel-is-onchain-plaintext-not-internal`），贴一次 = 永久公开，而它是泄露链的必要输入之一。

### N7 · 残余边界进运行时输出（**V6**）
见 §4-V6。

### N8 · 注册必须带 **proof-of-possession**（v1.1-rc 新增 · @Bettor 20:23Z 裁 · 方向 @NWT）
🔴 **为什么必须有这一层**：N1/N2 的派生证明**纯粹是公钥算术** —— 非硬化派生只需要根的 xpub，**不需要任何私钥**。
而 N6 要求根对**验证方**可读，且各域为了互相核对同源**本来就得读到别人的根**（NWT：这个可读性收窄不了，它是 A2 要做的事的必要前提）。
⇒ **根与派生 pubkey 都是可抄的值** ⇒ 没有 PoP 时，登记表每一行只是**声称**，不是证据：
域 X 可以抄域 Y 的根、算出正确的派生 pubkey、用**自己的** relay_id 提交，**通过全部既有校验** ⇒ 伪造 SAME_ORIGIN，或让 N3 构造性违规**指认到域 Y 头上**。

**条款**：
1. 注册 submission **必须**携带一个签名，签的 payload **至少绑定**：`root_fingerprint` ∧ `identity_index` ∧ `relay_id` ∧ **服务端签发的一次性挑战串**（单次使用 + 过期）。
2. 🔴 **验签所用的公钥 = 【申报的那个 identity pubkey】本身** —— **不是**提交者的任意钥、**不是** `relay_nodes` 里那行的地址。
   **这一条是整层的承重点**：域 X 从未持有 R_Y 之下任何身份的私钥，所以他**签不出**能被该 pubkey 验过的签名。
3. **fail-closed**：缺签 / 形状不合法 / 挑战不是服务端签发的 / 挑战已用过 / 已过期 ⇒ **一律拒**，不落库。
4. 🔵 **复用既有原语，不新造签名体系**：验签走 kaspa-wasm `verifyMessage({message, signature, publicKey})`
   （与 `kasia-console/src/lib/coord-status-sign.mjs:91-93` 同一条路；签名侧 relay 已有 `signMessage`，见 `kasia-relay/src/relay.mjs:642-647`）。
5. 🔵 **重放整份合法提交没有收益**：payload 里带着提交方自己的 `relay_id`，原样重放只会去执行**对方那条**注册；且一次性挑战会让它直接失败。

⚠ **N8 关掉的是"抄根冒充"这条**。它**不**关掉「一个域确实控制着同一 seed 派生的两个硬化账户」—— 那仍是 §1 的 C 边界（仪式域）。

## §3 安全性陈述（带确切前提 · 含已撤销的说法）

🔴 **已撤销，别复活**：设计稿 v0.1 曾写「放大面被 R1/R3 夹住 ⇒ **R3 不受影响**」。**该句作废**（@NWT `9d7fc088` PUSH-BACK，我复核成立）。它错在**循环**：用「R1 成立」去论证「违反 R1 的后果可控」，而 **R1 是否成立正是 A2 存在来检验的那件事**。

**现行准确陈述**：
1. **在 N3（锁 1）之下**，形态 A 的兄弟泄露放大面 **= 0**（无兄弟）。这是 N3 带来的，不是论证出来的。
2. **R1 被违反时**（同 seed 跨两域），一把子私钥泄露 + 公开登记根 ⇒ **跨域** ⇒ R3 被打破。**N3 让"第二个身份"在【同根】情形下变成构造性违规而被拒；【异硬化账户】那条路仍属 C 边界（仪式域）。**
3. **委员抽样的兜底程度是 stake 分布的函数，不是常数**：@NWT 用 `pool-committee-sampler.mjs` 算出单域(2/10)两人同场 ≈ **22.2%**、且只有 2/5 票 vs **4-of-5** 门槛（我独立重算一致）——
   ⚠ **但那是【均匀抽样】的数，而抽样器是 stake 加权**（`:117-128` `hit = rand % totalStake`；`:100` 非正 stake 抛错）⇒ **stake 不等时须重算**。
   ⇒ 防线链 = **R1（运维承诺）→ R2（运维配额）→ R3（抽样数学）→ stake 锚定**，**四节无一节是密码学强制**。

## §5 残余敞口（明写，不留给下一个人撞）

1. **反向不可证**（§1 C 边界）—— 靠生成仪式，不是密码学。
2. **N5 不约束敌对运营方** —— 只消除无痕误配路径。
3. **`parseInt` 的 `NaN` 支未验**（@J1tn 标注）—— 落码时自验。
4. **兜底程度依赖 stake 分布 + stake 锚定**（§3-3）—— 非常数。
5. **形态 A 是一条新派生代码路径**，不是配置项调整（现行叶子固定 `0/0`）⇒ 新路径**必须自带一次 §N5 式的逃逸口审视**，否则只是把洞换个名字。
6. **本机 live 现态**：两个逃逸口**当前均未生效**（4 个近期广播的本机 relay 运行时地址与 `relay_nodes` 逐字符对上，`scripts/u1-escape-hatch-live-check.cjs`）——
   ⚠ **作用域**：只覆盖近期广播过的 relay；且这是**行为证据**，排除的是「正在生效」，**不是**「变量不存在」。
