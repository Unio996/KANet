## §1 遏制点 —— `RELAY_DIR`,而它之所以成立是【加载期 const + fork cwd】两件事叠起来

**现读 `kasia-console/src/services/relay-manager.js`**(⚠ 在 `src/services/`,不在 `src/lib/`;NWT 07:07 给的行号 `:19`/`:91` **是对的**,只有目录需更正):

```js
:19   const RELAY_DIR = resolve(process.env.RELAY_DIR || `${KANET_ROOT}/kasia-relay`);   // ← 模块加载期求值一次
:90   const child = fork('src/relay.mjs', [], {
:91     cwd: RELAY_DIR,                                                                   // ← 每一个被 spawn 的 relay 子进程
```

🔴 **为什么这是【进程级】而不是【某个 relayId 级】**: `fork` 的第一个参数是**相对路径** `'src/relay.mjs'`,解析基准就是 `cwd`。
⇒ 把 `RELAY_DIR` 指向假目录 ⇒ **这个 console 进程此后 spawn 的每一个 relay 都是假体**,不需要按 relayId 逐个拦。
⇒ **满足 (A) 结构性**: 它不是"我记得在测试里把某个调用换掉了",而是**出站进程的可执行文件本身被换了**。

**而 settler 侧确实只有这一个出站族(本稿作者自量,非转引)**:
`grep -nE "await fetch\(|new RpcClient|https?\.request|axios" kasia-console/src/services/pool-market-settler.js` ⇒ **计数 0**;
11 处出站**全部**是 `sendCommandAsync(...)`(`:859 :2452 :2682 :2937 :2988 :2993 :3139 :3176 :3443 :3549 :3669`)。
⇒ **遏制 `sendCommandAsync` 的落点 = 遏制 settler 的全部出站。**

## §2 台账形态(B) —— 假体必须能回答【阴性臂零调用】,不只是【阳性臂被路由到了】

臂 (d) 现有的 sink 只证明了**一条命令到达**(哨兵)。blocker① 要的更强:**证明阴性臂期间对 claim/签名/广播/relay/链的调用数 = 0**。

**形态**: sink 把**每一条**收到的 IPC 命令**追加**成一行结构化记录,至少含
`{ seq, ts_ms, relay_id, type, market_id?, sentinel }` —— **append-only,不覆盖**。

🔴 **三条设计约束(每条都对着一个在册的坏法)**:
1. **必须记【全部】命令,不是只记感兴趣的那几种** —— 白名单式记录会让"没记到"与"没发生"读数相同(在册:没发生有两种成因)。
2. **零条也必须留下【文件存在且为空】这个事实** —— 空文件与"sink 根本没起来"必须可分辨。⇒ sink 起来时先写一行 `up` 记录(臂 (d) 已有 `[fake-relay-sink] up sentinel=… pid=…` 的雏形)。
3. 🔴 **断言读的是台账,不是 sink 的返回值** —— `startRelay().ok === true` 在本仓**已经骗过一次人**(g4 那次 `spawn ENOENT` 仍返回 ok,因为 spawn 失败是 fork 之后的**异步** error 事件)。**返回值不是证据,落盘记录才是。**

## §3 时序断言 —— 本稿最容易被做成"看起来对"的一格

@NWT 07:07 在裁"算"的同时抛回一条**他够不到、该我核**的前提:
> 「N1/N2 fixture 跑的那次 tick,会不会碰到 relay 还没注册进 `_relays` / `RELAY_DIR` 重定向来不及生效的窗口」

🔴 **这是【时序】问题,不是【覆盖】问题。**「settler 只有一个出站族」(§1)回答的是覆盖 —— **拿它去顶时序,就是换了个维度充数。**

**⇒ 硬约束(不是 caveat)**: 断言必须证明**重定向早于第一次 `sendCommandAsync`**,而不是"事后发现被路由到了"。
**形态**: 台账里那条 `up` 记录的 `ts_ms` / `seq` 必须**严格早于**本次 tick 的第一条命令记录;用例断言这个**顺序**,不只断言存在。
🔵 判据来源同族: 臂 (d) 文件头自己记的 g4 教训 —— **"注册完了"和"起来了"一样,需要独立观测,不能靠调用返回。**

## §4 (C) 缺遏制 ⇒ import 前即 fail

现状: 臂 (d) 在**模块体**里断言 `DB_PATH`/`KANET_DB_PATH`/`KASPA_RPC_URL`,**理由是** `relay-manager.js` 顶层 import 链会在 `db/client.js` 顶层就把库打开 ⇒ 事后断言等于断言既成事实。
⇒ **同一位置再加一条 `RELAY_DIR` 断言**:未指向本次运行现生的假目录 ⇒ **抛,零发送**。
🔴 **必须是【断言】不是【设置】** —— 若用例自己 `process.env.RELAY_DIR = …`,则"遏制生效"这件事由**用例自己制造**,阴性臂就失去意义(而且会污染同一次运行里后面的用例:`RELAY_DIR` 是加载期 const,改回去也救不了)。

## §5 本稿【不】覆盖什么(边界,写死)

- **不是套接字层遏制**。走的是 Codex ① 的**第二条**路(本地假体),NWT 已裁其合格 —— 但若日后有人要求"必须是 socket 层",**本设计不满足,须重估**(我 07:17 报的 1–2 天上界正是挂在这个裁定上)。
- **只覆盖 `sendCommandAsync` 这一族出站**。§1 的计数 0 是**对 `pool-market-settler.js` 一个文件**的;**其它模块没量**。
- **不覆盖跨节点** —— 跨节点 maker 在 `dispatchRefund` 之前就被拦掉(臂 (d) 文件头已记)。
- **不证明退款交易本身正确** —— 假体回的是刻意伪造的占位对象。**本设计证的是"命令流被遏制且可审计",不是"交易对"。**
