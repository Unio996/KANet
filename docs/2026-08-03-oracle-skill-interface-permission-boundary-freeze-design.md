## §2 三权的可机械判定定义(不是形容词)

D-012 §6-1 要求「三权分立烤进接口签名,Oracle 结构上够不到资金路径」。要能被红队攻击,三权必须定义成**可判定**的,而不是"职责说明":

| 权 | 定义(判据形态) | 拒绝形态 |
|---|---|---|
| **P1 报告事实(Attest)** | 输出是**对一个域分隔 typed receipt(FactReceipt / OutcomeAttestation)的签名声明**,其**必须绑定的九类字段见 §2.1**。判据(**v0.4 重述,原措辞与改动理由见 §2.1 末 ⚠**):被签字节里**不含任何逐方分配** —— 无收款地址、无逐 bettor 金额、无 payout 树/root、**无交易摘要** ⇒ **在 (事实, 政策版本) 固定的前提下,把钱在 bettor 之间挪一分,无法通过改 P1 字节做到** | 拿不到合格证据 ⇒ **abstain**,不猜 |
| **P2 规则解释(Interpret)** | `(attested outcome, 规范输入集, 政策版本) → payout 树` 的纯函数,**且必须消费并承诺一个「规范输入集对象」**(§2.2)。判据:任意第三方拿**同一个被承诺的输入集**独立复算出逐字节相同结果。🔴 **「两个节点算法确定性相同」不构成本判据** —— 确定性相同 ≠ 喂进去的是同一个完整输入集 | 输入集**证不了** ⇒ **`verifier-inconclusive` + 零授权**,**且不得回落到任何更弱的检查(含候选 B)去签名**(§4.5) |
| **P3 放钱(Disburse)** | 只由 covenant 依据 P2 的承诺执行。判据(**v0.4 重写**):**对「确切的 P2 承诺 + 确切的被消费前态 + 序列化交易语义」三者的验证**,逐项见 §2.3 | 🔴 **「放钱路径上零 `checkSig`」不再是本判据** —— 它只是必要条件之一,单独成立时**什么都没证明**(§2.3) |

**三权分立的验收判据(一句话,可被红队直接攻)**:
> **持有 committee 成员私钥的进程,不存在任何一条能对「决定谁拿多少钱的字节」出签的路径。**

### §2.1 P1 的绑定面(v0.4 新增 · Codex ①)

**问题(Codex 原话所指)**:只绑 `(market_id, outcome)` **太小,可重放** —— 一份**旧的但仍然有效**的 attestation,可以在策略/状态变更之后被重放、被拿到**另一条网络**上使用、或被按**另一套 payout 政策**解释。签名本身不会失效,失效的是它当初成立的语境,而语境没被签进去。

**契约要求**:P1 被签对象是一个**域分隔的 typed receipt**,必须绑定以下九类(缺一即不合格):

| # | 绑定什么 | 挡住的重放形态 |
|---|---|---|
| 1 | **协议/域标签 + receipt schema 版本** | 跨协议/跨对象类型混用同一签名(域分隔符缺失 = 同一串字节在另一处被当作别的东西验) |
| 2 | **网络 / genesis 标识** | 把 testnet 的 attestation 拿到另一条网络上用 |
| 3 | **市场身份 + 确切状态版本** | 市场状态推进后,旧 attestation 仍被当作对新状态的声明 |
| 4 | **结果命名空间 + 编码版本** | `outcome=1` 在两套编码下指不同结果 |
| 5 | **证据摘要 或 规范观测锚** | 声明与它所依据的观测脱钩(事后换证据、同一结论换来源) |
| 6 | **committee epoch / 集合标识 + 签名者身份** | 换届后旧成员的签名仍被计入当届 quorum |
| 7 | **序号 / nonce + 过期锚** | 同一份声明被无限次重投;永不过期 |
| 8 | **supersedes 语义(更正用)** | 更正与原件并存时,哪一份有效无法判定 |
| 9 | **P2 期望的策略 / 解释版本** | 同一事实被按另一套 payout 政策解释 |
| **10** | 🔴 **supersede 的授权门槛与集合身份**(v0.5 新增,见下) | **更正机制本身被当成一条绕过 quorum 的后门** |

🔴 **第 ⑩ 类 = NWT 红队 MUST-FIX(2026-08-04,针对 v0.4 §2.1)。原样收下,不打折。**
- **他打中的**:第 ⑧ 类只回答了「两份并存时选哪一份」,**没回答「一份声称 supersede 旧件的新 attestation,需不需要满足与原件相同的 quorum」**。若落码时 supersede 只按 nonce/序号新旧判定,则**一个更弱的签名集合**(门槛更低 / 换届后的旧委员残余 / 任何能拿到更晚序号的路径)可以在**不碰 policy version** 的前提下改写 outcome —— 而 outcome 决定 payout。
  ⇒ **这确实是一个"符合 v0.4 新措辞、却能在不换政策版本的前提下挪钱"的字段** ⇒ **§7-5 那道题被答出来了,新措辞在 supersede 这一格上漏了。**
  🔵 **要说准确的是漏在哪**:漏的不是"outcome 决定 payout"(那是设计意图,不是洞),是**「谁有权发起一次有效的 supersede」这件事本身没有被九类中的任何一类约束** —— 等于给一个本该 4-of-5 的动作开了一条门槛不明的旁路。
- **契约要求(第 ⑩ 类)**:supersede 的**签名门槛与签名集合身份,必须等于或高于被取代那一份的原始门槛**,且**必须显式核对同一 committee epoch / 集合标识**(第 ⑥ 类的值必须参与比对,不能只是各自带着)。序号更晚**不构成**授权。
- 🔨 **判据形状**:**「更正」是一次与原件同权的授权动作,不是一次记账动作。** 任何把更正做成"覆盖最新一条"的实现,都把授权判定悄悄降级成了排序判定。

### §2.1-bis 🔴 NWT ② 的明确答案(v0.5 新增 · 实读代码,不猜,带版本作用域)

🔵 **第三条,它把攻击面挪了个位置(比前两条更要紧)**:决定谁被算作"静默"的 `silentOracleIndex` 是 **settler 侧从 `signedIndices` 算出来的**(`:1323`),**不是委员签名字节里的字段**。
⇒ 即使在 v0.5 legacy 路上,这笔钱也**不是"改一个 P1 字段"能挪的** —— 它由 **settler 的观察结果**决定,而 **settler 的观察没有任何人复算**。
⇒ **所以这一格的真实缺口不在九类字段清单里,在 §4.3「P2 今天是被信任的输入,不是被验证的输出」那一条。** NWT 这一问的价值不在答案是 roster,在于它把"签名者身份能不能挪钱"这个问题**逼到了 settler 那一侧**。

> ⚠ **v0.4 在这里改了一句上一版已被接受的文字,必须点出来供审(我不藏改动)**

> 🔨 **判别式没变、还更硬**:红队攻的是「找一个被签字段,改它能在**不换政策版本**的前提下挪动某个 bettor 的钱」。

### §2.2 P2 的规范输入集对象(v0.4 新增 · Codex ②)

**问题**:「纯函数 + 确定性」只保证 **同样的输入 → 同样的输出**,它**完全不管**两个节点喂进去的是不是同一个输入集。而在子集② 里,输入集恰恰是**每个节点各自攒的**(§7-1:至少 5 条静默 `return` 支路,丢一笔与从未有过那一笔读数相同)。⇒ **两个节点各自"确定性地"算出不同的 payout,双方都认为自己是对的。**

**契约要求**:P2 必须**消费并承诺**一个规范输入集对象,该对象至少含:

| # | 字段 | 为什么它必须在里面 |
|---|---|---|
| 1 | **前态 outpoint + 版本** | 「哪一个状态实例」不能靠地址推断(地址是类型,outpoint 才是那一个) |
| 2 | **每笔注:outpoint / txid + 地址承诺 + 方向 + 金额** | 逐笔可核,而非只核聚合 |
| 3 | **确定性去重与排序规则** | 同一集合的两种排列会算出不同 root;规则本身必须是被承诺的一部分 |
| 4 | **政策 / 费 / bond / dust / change 版本** | 与 §2.1 第 9 类同一个版本标识,两侧必须对得上 |
| 5 | **输入集 merkle root** | 使"我用的就是这一集"成为一个可比对的单值 |
| 6 | **payout-root + 总额记账** | 输出侧的承诺,与输入侧闭合 |

🔴 **失败语义(Codex 写死,本稿逐字收编)**:**证明不了输入集的参与者,必须返回 `verifier-inconclusive` 并且不产生任何授权 —— 【不得回落到候选 B 去签名】。**
> 🔵 **这一条与 §4.5 的 `cannot-verify` 是同一个东西的两侧**:§4.5 说的是"必须能表达没资格断言",本条说的是"表达完之后不许再往下签"。**只做前者不做后者,等于给弃权配了一条绕行路。**

### §2.3 P3 的验收定义(v0.4 重写 · Codex ③)

**问题**:「放钱路径上零 `checkSig`」**只证明这条路不直接依赖签名**。它**不证明**:

| 它不证明的 | 意味着什么 |
|---|---|
| 前态是正确的 | 可以在一个错误/过期的前态上放钱 |
| P2 承诺来自**规范完整**的注单集 | 可以按一个残缺集合算出的 root 放钱 |
| **每一个** payout 输出都绑到已承诺的 root | 可以夹带未被承诺的输出 |
| 备用 selector 入口**绕不过**该承诺 | 合约里另一条 entry 可能是敞开的 |
| fee / change / dust 与网络版本绑定完整 | 价值可从这些"边角"漏走 |

**契约要求**:P3 的验收**定义为**——
> **对「确切的 P2 承诺 + 确切的被消费前态 + 序列化交易语义」三者的验证。**

⇒ 冻结文本里 **不许**再用「P3 零 `checkSig`」单独作为 P3 达标的陈述;它降级为**必要条件之一**,引用时必须与上表五项一起给。
🔨 **判据形状与今日同族**(§4.5 弃权率、§3.2-1 「privkey 不 leave process」):**一个成立的陈述盖住另一件没做的事** —— 今日第三次。

> ⚠ **用词按 §3.4 词汇表**:此处说的是 **committee 成员**(代码中今天即 `is_oracle = 1` 的 relay,见 §3.4 映射表),**不是**契约词汇里的 Oracle(T3 外部事实源,今天是 UMA hook、不持签名私钥)。**这句判据在旧词汇下写成「oracle 私钥」会指错对象** —— 它承重,所以必须用对词。

## §4 冻结的接口契约(本稿核心产出)

### 4.1 【承重】签名能力必须类型受限

**契约**:committee 成员密钥持有进程**不得暴露"对任意 tx 任意 input 出签"的原语**。签名入口必须是**带类型的声明**,由持钥侧自己判定"我签的是不是 attest 类字节"。

- 形态(不是实现方案,是契约要求的形状):`attest_outcome(market_id, outcome, …)` —— 持钥侧**自行**核对被签对象属于 attest 类且**守恒**(照 §3.1 `:180`/`:283`/`:398` 那条 clamp 的语义),不合则拒签。
- 🔴 **判据必须是结构性的,不能是"调用方会先检查"**。今天全部策略都在调用方(`handlePoolOracleTxSignReq`),而**调用方与持钥方之间隔着 IPC** —— 任何绕过调用方的路径都直达 `:711`。
- 🔴 **本条与 PB-S8-2 的关系(先说清,免得被读成同一件事)**:PB-S8-2 是在**调用方**加 payout 字节绑定;本条要求的是**持钥方**结构上签不了那种字节。**两者不互相替代**,PB-S8-2 落地也不使本条完成。

### 4.2 【承重】P1 被签对象的守恒要求

被 committee 成员签名的 TX **必须是守恒类**:该笔 TX 不改变资金在参与者之间的分配(v0.7 形态 = 池面值原样进原样出,`consolidated_pool` clamp)。
⇒ 推论:**"签一笔把钱分给赢家的 TX"这件事,在冻结后的接口里不存在**。子集②要么迁到这个形状,要么在冻结文本里被显式标记为**未达标的历史路径**(带作用域,不许被"已三权分立"覆盖)。

### 4.3 P2 必须是可独立复算的承诺,不是被喂来的对象

- payout 由**纯函数 + 确定性整数算术**导出(`computePoolPayouts` 已是纯函数,资产在);
- 签名者**独立复算**并与承诺(payoutRoot 类)比对,**不接受消息自带的 payout 对象作为可信输入**;
- 复算所依据的输入必须**可证完整**(见 4.5)。
- 🔴 **v0.4 加(Codex ②,本条是上一行的硬化)**:「可证完整」不是形容词 —— 复算**必须消费并承诺 §2.2 那个规范输入集对象**(前态 outpoint/版本、逐笔注的 outpoint+地址承诺+方向+金额、去重与排序规则、政策/费/bond/dust/change 版本、输入集 merkle root、payout-root 与总额记账)。
  **两侧比对的是「输入集 root + payout-root」这一对**,不是只比 payout 结果。
  ⇒ 🔴 **`pool-shard-settle.mjs:315-320` 那个活实例只满足本条的一半**:它**做了**独立重算与不符拒签(§4.3 前两行),但它比的是**重算出来的 payout**,**没有**一个被承诺的输入集对象把"我们俩用的是同一堆注"钉死。**引用它作为"本形状已有实例"时必须带这半句** —— 否则会把"已做一半"读成"已达标"(同 §3.2-3 PB-S8-1 的措辞纪律)。

🔵 **这个形状在本仓已经有一个活实例,冻结文本应当直接引它而不是另写一遍**(承 Bettor 口径「推广既有形状,非从零发明」):
`kasia-console/src/lib/pool-shard-settle.mjs:315-320` —— **先**本地 `computePariMutuelPayout` + `settlePayoutRoot` 重算,**与 claimed 比对不符即 `命门③ REJECT` 拒签**,**通过了才**调 `sign_input_for_settle`。
⇒ **§4.3 的差距因此不是"没人做过",而是"做过的那条路没覆盖子集②"**:`handlePoolOracleTxSignReq`(子集②)在够到签名前**没有**任何等价的 re-derive 步骤(`trade-protocol-filter.js:541-674` 全段无 payout 复算)。**冻结要求 = 把 `pool-shard-settle.mjs:317` 那步变成契约必需项,而不是某条路径的自选动作。**

### 4.5 abstain-not-guess 与「没资格断言」必须是一等返回值

承 KB `oracle-hardening-four-gate-framework.md`(四正交闸 + 三态)与团队今日两张同族卡:

- **三态**:能结构化且委员同抽同字段 ⇒ settle;不一致/字段不足 ⇒ **abstain**;结构化不了 ⇒ 建市时 prevet 拒。
- 🔴 **接口必须能表达第四种读数:「我没有资格断言」** —— 与"我判定为否"**不是同一个返回值**。依据是团队今日两次独立撞到同一形状:
  - (130) consumer 侧自知之明闸:整表 0 行时,"真无人下注"与"我从未同步到注"**读数相同** ⇒ 不广播、记可计数 skip。
  - (134) Bettor 的链上守恒锚:`Σ(本地已知 stakes)+fees/bonds == 被花费 spine UTXO 的链上面值` ⇒ 把"本地数据全不全"**从假设变成可判定**;对不上 ⇒ 本机无判断资格,退化并记 `cannot-verify`。
- ⇒ **契约要求**:P2 的复算入口**必须**返回三值之一 `{agree | disagree | cannot-verify}`,且 `cannot-verify` **不得**被调用方折叠成 `disagree` 或静默跳过(必须可计数、可告警、带接收者)。

🔴 **v0.4 加(Codex ②,逐字收编)——`cannot-verify` 的下游是【零授权】,不是【换个便宜的检查再签】**
- **`cannot-verify` / `verifier-inconclusive` ⇒ 不产生任何授权,且【不得回落到候选 B 去签名】。**
- **为什么这条必须单列**:v0.3 只写了"要能表达没资格断言"。**能表达 ≠ 表达完就停下。** 一个实现完全可以老老实实返回 `cannot-verify`,然后调用方说"那就退一档用便宜检查吧"——**弃权被如实报告了,签名照样出去了**。⇒ **弃权必须是终点,不是分支。**
- 🔵 **与 §5 PB-S8-2 那行的关系**:候选 B 是**便宜的拒绝信号**(能拒就拒),**永远不是**"更强的检查不可用时的替补授权源"。**降级只能降到不签,不能降到用弱证据签。**

🔴 **v0.2 补:守恒锚的准确覆盖 + 一条硬要求(Bettor 2026-08-03 自纠并升级,`#devnxf`)**
- **锚本身成立,是覆盖被说宽了**:`Σ(本地已知 stakes)+fees == 被花费 spine UTXO 面值` **只在持有完整未花费仓位集的节点上产出「可验证」**(实践上 = 市场本机 / settler 机);**在远端节点它会正确地、系统性地弃权**(原因见 §7-1:`trade-protocol-filter.js:1367` 按设计不存已花掉的仓位)。⇒ 它给出的 `cannot-verify` **是对的答案,不是失效**。
- 🔴 **而这带出一条必须同时上的硬要求**:**一个永远弃权的检查,和一个永远通过的检查,在日志里长得一模一样。**
  ⇒ **契约要求(硬)**:任何实现本节三态的检查,**上线时必须同时上报「弃权率」**;**若弃权率 ≈ 100%,该检查即是装饰,必须当缺陷处理,不得当作「没触发」。**
  🔵 这条与 §3.2-1 的病同源:`sign_input_for_settle` 那句「privkey 不 leave relay process」也是**一个成立的陈述盖住了另一件没做的事**。**成立但无效**与**不成立**,在读者那里同样致命。
