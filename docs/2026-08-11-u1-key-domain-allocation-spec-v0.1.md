## §1 先把地基上的事实查清（现读，不引转述）

```
本机 relay_nodes 总数            = 32
其中 is_oracle = 1               = 10   ← 决定"谁能签"的那一列(trade-protocol-filter.js:578-580)
这 10 个的私钥托管形态           = mnemonic_encrypted 10/10, privkey_encrypted 0/10
全库 ecdsa_pubkey_xonly 非空     = 0
```

🔴 **三条直接影响算法形态的推论**：

- **(a) 委员密钥今天是 mnemonic，不是裸私钥。** ⇒ 「把第 N 把钥匙放到第 M 台宿主」在实现上是**放一份助记词**，而助记词**可派生整棵地址树** —— 单把 mnemonic 的爆炸半径大于单把私钥。**分配算法必须按 mnemonic 为单位算隔离，不能按"某个签名密钥"算。**
- **(b) 现有 10 个 is_oracle 全在本机。** ⇒ 施工的实质是「10 → 5 域」的**再分布**，不是「从零分配」。runbook §2 步骤 3「划出域 1 现有 relay 的一部分」= 这一步。
- **(c) `is_oracle` 是承重列**（在册迁移卡已定性：它决定本机哪些身份参与签名 = 钱路）。⇒ **本 spec 绝不改写 `is_oracle`**；域归属只写进 v195 的 `u1_domain_assignment`，两者**故意保持解耦**（见 §4）。

## §2 映射规则（问 1）

### R1 · 分配单位 = 一份 mnemonic ↔ 一个域
承 §1(a)：**同一份 mnemonic 的任何派生身份，全部属于同一个域。** 不允许「同一助记词的两个派生 relay 分在两个域」——那在密钥层面根本没有隔离，只是在记录层面看起来隔离了。
> 🔵 v195 的 `UNIQUE(relay_id)` 挡的是「一个 relay 跨两域」；**R1 挡的是它的上一层**：一份 mnemonic 跨两域。**v195 表本身挡不住 R1 的违例**（两个 relay_id 可以来自同一助记词），⇒ **R1 需要落地时的独立检查**，见 §5 验收。

### R2 · 每域至少一份、至多⌈N/5⌉份
5 域、N 份委员 mnemonic（今 N=10）⇒ 均分为每域 2 份。
**不允许某域 0 份**（那样"5 域"退化成实际 4 域，而 D1 花的那台机器就白花了）。

### R3 · 阈值不可被单域满足
**任一单域持有的委员钥数 < threshold。** 今天 4-of-5 ⇒ **任一域 ≤ 3**。
🔴 **这条是整个 u1 的目的本身**：它不成立时，攻破一台宿主即可独立凑齐签名，前面所有工作归零。
⇒ R2 的均分（每域 2）自动满足 R3；**但 R3 必须独立成条并独立检查**，不能靠"我们是按 R2 分的"来推——R2 若因运维原因被临时打破（某域宿主坏了把钥挪走），R3 是那一刻唯一还在挡的东西。

### R4 · 域 1 = 本机，且本机份额必须先降到 R3 以下
现状是 10/10 在本机 = **单域持有 100%**。施工的第一个可验证里程碑不是"新宿主就绪"，而是**本机份额 ≤ 3**。
⇒ **验收判据 B（255 市场 63→0）之前，还有一个更早、更便宜的判据：本机 is_oracle 中仍持钥的数量。**

## §3 轮换再分配（问 2）

**轮换 = 换钥，不是搬钥。** 承 scoping §5「不在本机生成后传输，传输本身是暴露窗口」：

- **R5**：轮换时**在目标宿主本地生成新 mnemonic**，旧钥**作废不搬运**。
- **R6**：轮换期间**新旧并存的窗口内，R3 必须对「新∪旧」的并集成立** —— 否则并存窗口本身就是一个可攻破的单域超额持有窗口。这是轮换最容易被忽略的一格：两边各自合规，并集不合规。
- **R7**：轮换必须**逐域串行**，不并发。并发轮换会让 R6 的并集在多个域同时膨胀。

🔴 **R8（依赖，标未决）**：轮换流程的**权限模型**（谁有权发起、谁批准）**不在本 spec 内** —— scoping §10 项 5 已定性它依赖 D-012 §6-1 冻结，是技术前置阻塞。**本 spec 只定"轮换时钥怎么分"，不定"谁能按下轮换"。**

## §4 与 §4.1 持钥侧类型闸的接口（问 3）

### 4.1 先说 §4.1 今天的真实状态（现读 `0539aec8` 全文 + diff）
- §4.1 是**契约要求**，措辞是「committee 成员密钥持有进程**不得暴露**"对任意 tx 任意 input 出签"的原语」。
- 🔴 **它今天零实现**：稿子自陈「今天全部策略都在调用方（`handlePoolOracleTxSignReq`），而调用方与持钥方之间隔着 IPC」。
- ✅ **rev-7 没有动 §4.1** —— 我逐行读了 `0539aec8` 的 diff：**改动全在 §4.3-bis**（我那三条 critique 的落地）。
  ⇒ **我原先那个"等 rev-7 落地再写、否则要重写"的顾虑，查过之后不成立。本 spec 可以按现状写。**

### 4.2 接口约定（本 spec 对 §4.1 的唯一依赖）
**分配算法不假设类型闸存在，也不因类型闸缺席而放宽。**
- **I1**：域归属**不作为**任何签名授权条件。持钥侧将来实现类型闸时，它判定的是「被签对象是不是 attest 类字节」，**与该钥属于哪个域无关**。
- **I2**：⇒ `u1_domain_assignment` 表**永远不进授权语句**（与 v195 注释里写死的定位一致，也与在册「B 的判定结果不得出现在任何授权语句里」同一纪律）。
- **I3**：**隔离与类型闸是两条正交防线**：隔离让「凑不齐 threshold」，类型闸让「凑齐了也签不出那种字节」。**任一条落地都不使另一条可省。**

## §5 验收（比判据 B 更早、更便宜的两格）

| # | 判据 | 怎么测 | 为什么它必须独立于 R2 |
|---|---|---|---|
| **A1** | 任一单域持钥数 < threshold（今 ≤3） | 按 `u1_domain_assignment` 聚合 + 逐 relay 现读是否真持钥 | R3 是目的，R2 只是达成手段；手段被运维打破时 A1 是唯一还在挡的 |
| **A2** | 无两个 relay_id 共享同一份 mnemonic 却分属不同域 | 需要一个**能判定"两个 relay 是否同源"的检查**——🔴 **今天没有这个能力**（`ecdsa_pubkey_xonly` 全库为空，无现成同源指纹） | v195 的 `UNIQUE(relay_id)` 挡不到这一层 |

🔴 **A2 是本 spec 交出去的最大缺口，明写在这里**：R1 定得了规则，**今天验不了它**。
⇒ **落地前必须先解决"怎么判定两个 relay 同源"**（候选：派生路径登记 / 公钥指纹落库 —— 后者需要先把 `ecdsa_pubkey_xonly` 填起来，而它现在全空）。**不解决就落地 = R1 是一句无法检查的规矩。**
