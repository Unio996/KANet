# KANet 预测市场 — 系统特点介绍

> **Status**: CURRENT（2026-07-07 KANet-UI 补记·D-004 文档硬门）— committee-sig trust-minimized 结算仍是当前对外可讲的现状；ZK-native 是独立并行推进的目标架构（见 DECISIONS.md D-001），未替换本文描述的现状，本文不因 ZK 进展而过时。

> 一句话:**建在 Kaspa 信任链上的全链上预测市场——无限规模、自动结算、人人可审计、Telegram 零门槛。**
> 口径:当前在 **测试网(TN12)**。下列每条特点都有**链上实证**(真盘 + txid),不是 demo。

---

## 它解决什么

传统预测市场要么**中心化**(平台说了算、可篡改、可跑路),要么**链上但贵且有规模上限**(每个市场能容纳的人数受合约大小限制)。

KANet 用 Kaspa 的高速 BlockDAG + 链上 covenant,做到:**任意人数押注、自动按真实结果结算、每一分钱链上可查、普通人在 Telegram 里一键就能玩**。

---

## 四个核心特点(均已链上验证)

### 1. 无限押注 —— 滚动分片,没有人数上限
每个市场由"分片(shard)"组成,一片满 32 注自动开下一片,**无限滚动,永不撞"满员"**。**下注人数没有任何上限。**
- **实证**:测试盘押到 **52 注**(滚成 2 片),第 51、52 注照常进,零撞满员。资金守恒分文不差(链上 52 KAS == 数据库 == 各方独立重算)。
- 注:押注无限;"发奖"那一步当前一次最多给 1024 个赢家分钱(见下方边界,超出是下一步扩展)——两者是不同的两件事。

### 2. 链上自动结算 —— 结果出来,机器自动分钱
市场到期 → 预言机判定结果(实跑判定逻辑,非人工填) → 系统自动把所有分片**合并结算** → 赢家分配方案**烤死进一个链上地址**(不可篡改) → 赢家各自上链领走奖金。
- **实证**:多片真盘(35 注 / 2 片)全链上自动结算闭环——合并 → 关盘 → **18 个赢家各自动领走 1.944 KAS**,资金守恒精确(close tx `aebd1cdb…`)。**第 2 片的赢家也领到了钱**=多片合并没漏任何一片(整个机制的命门)。

### 3. 全链上可审计 —— 不信任何人,自己就能验
赢家分配方案(payoutRoot)和关盘地址都是**内容寻址**的——给定押注数据,任何人都能独立重算出同一个值;算不对,链上根本不接受。
- **实证**:每个里程碑都经 **5 个独立视角各自从链上重算对死**(driver / 两个独立节点 / UI / 红队),逐字节一致才算数。"验证而非信任"是工程纪律,不是口号。

### 4. Telegram 零门槛 —— 不懂币也能玩
用户在 Telegram DM 里生成**托管钱包**(测试网领币),**一键押注**自动付款,无需懂地址、私钥、转账。
- **实证**:真实用户(含 Owner)在真 bot 里押注成功;16 笔连续真押过 50 注,金额精确落账(含极小路由标记),资金守恒。

## 技术底座

- **Kaspa TN12**:高速 BlockDAG + 链上 covenant(脚本层强制规则)。挖矿供币(~11,500 KAS/min)。
- **covenant 结算**:押注锁进 P2SH covenant,结算由 covenant 校验(payout∈[合法区间]、merkle 证明 climb、关盘标志)——**链共识自证,伪造的证明上不了链**。
- **委员会信任最小化**:结果判定由 4-of-5 预言机委员会签证,链上 covenant 校验分配。**ZK verifier 在 TN12 链上已 active**(Groth16),为未来纯零信任结算留好接口。

---

## 诚实边界(测试网,不吹)

- **测试网**:用的是 faucet 测试币,非真钱。托管钱包是为零门槛体验,真钱请用自己的非托管钱包。
- **driver 驱动**:当前结算由程序驱动跑通(已链上证),**完全无人值守的自治守护进程是下一步**。
- **trust-minimized 非 trustless**:结果判定靠委员会签证 + 链上 covenant 校验(可证欺诈、偷不走池子),**不是纯密码学零信任**(那条在推进)。
- **规模**:单盘赢家 ≤1024(再多需进一步分片扩展,已记 TODO);押注人数无上限。
