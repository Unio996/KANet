## 二、🔴🔴 四个坑 —— 报错**一字不差**,而其中一个外部**不可能自己发现**

**四种完全不同的写错,输出全部是:`RuntimeError: unreachable` + 一串纯地址栈,不提任何参数名。**

| # | 坑 | 正确写法 |
|---|---|---|
| 1 | 🔴 `networkId` 传我们**实际的网络名** `'testnet-12'` | **必须传 `'testnet-10'`**。【实读】`wallet.mjs:95-98` 有这个内部映射 |
| 2 | `payload` 传 hex 字符串或 `Buffer` | **必须 `Uint8Array`** |
| 3 | `outputs` / `changeAddress` 传字符串 | **必须 `PaymentOutput` / `Address` 对象** |
| 4 | 用 `createTransactions()` | **必须 `new Generator()`** |

🔴 **第 1 条是这份文档存在的核心理由**:一个外部的人**没有任何途径**能猜到"网络叫 testnet-12 但要填 testnet-10" —— 那是我们代码里的一个映射。而他填对了真名字,拿到的是一句什么都不说的报错。

🔵 **⇒ 这是「失败不产生失败,产生一个形状正确的答案」在最伤外面人的地方的实例**:四个不同原因,一个相同的、零信息的输出。**把这四格写下来,它们就不再是坎。**

## 四、外部可达性 —— 唯一填不了的一格,以及怎么问才问得出来

⚠️ 队里**没有第二台机器**(唯一有的那位已关节点)。从本机连自己**永远证不出**防火墙 / NAT 那一层。

🔴 **而我第一版的问法是【不可判读】的**(NWT 实测):
```
curl :17210 (口在监听, 但它是 gRPC 不是 HTTP) ⇒ code=000 · 0.001s
curl :19999 (什么都没有)                      ⇒ 完全相同的输出
```
⇒ **两种相反的结论指向同一个输出。** 而那个测试问了也白问,我还会照它下结论。

✅ **可判读的问法 —— 让人把浏览器报错的原话念出来**:

| 屏幕上写着 | 结论 |
|---|---|
| 「服务器没有发送任何数据」/ `ERR_EMPTY_RESPONSE` / `ERR_INVALID_HTTP_RESPONSE` | ✅ **连上了**(端口可达) |
| 「连接被拒绝」/ `ERR_CONNECTION_REFUSED` / 转很久才超时 | 🔴 **连不上** |

🔵 而 `:3210`(网关)本来就是真 HTTP,判据干净:**看到带 `txid` 的 JSON = 通**。
