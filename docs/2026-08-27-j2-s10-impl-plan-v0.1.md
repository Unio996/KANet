# §10 跨节点 pubkey 身份 v1 · 实施计划 v0.1（报备层 · 零落码）

> **Status**: DRAFT v0.2 · J2 2026-08-27 · Bettor 派工 (12) · 依据 `docs/2026-08-19-s10-pubkey-identity-design.md`@847bcf22（Codex MSG-250 五项 CLOSED，register-only）· NWT 深审 v0.1 = PASS-WITH-NOTES（e128a735，N2 干净：PoP 在 payload、独立验签、非 Console 中介）· **v0.2 = 吸收三条 NOTES（⑦ 作用域收紧 / 去 `local_relay_id` 列 / TOCTOU 与回滚补注）· 进 Owner 决策包；本文不改任何码/表**
> **一句话**: §10 v1 = 一个**独立 S10 信封**（`{domain,version,network,relayPubkeyXOnly,operation,epoch,signature}`）+ 一张**以 pubkey 为主键的身份表** + 一个**纯函数验证器**；接进 A2 注册的方式 = **A2 提交必须附带由该 relay 地址钥签的 S10 声明**（同一 challenge 作 epoch、同一 IMMEDIATE 事务消费），否则 `RELAY_NOT_OWNED`。这就是 ⑦（first-squatter-wins on 未注册 relay_id）的关法：抢 relay_id=B 必须签得出 B 的钥。🔴 **作用域（NWT 收紧）：它关的是【跨节点 / 远程】抢注——远程方签不出本机 relay-B 的地址钥；【同机】抢注仍在 loopback 信任内（有 `console.db` + `CONSOLE_ENCRYPTION_KEY` 即可解密 B 的助记词自签，同 (528) 已接受的同机模型）。不许把"⑦ 关闭"读成同机也挡。** **不需要节点、不广播；需要 Owner 决**（协议层身份定义 + 新表）。

## §0 范围（沿设计 §0，不扩）
- v1 只做 `operation="register"`；**rotate / revoke / 旧记录迁移 = 不含**（设计 §7 明列 OPEN，L2 的 operation 域已留隔离位，验证方硬白名单只收 register）。
- 不做自动签发口（Track-A 仍 operator 手工挑战，runbook 不变）；不部署对外；不动 Owner 实例 §0 墙。
- 不改 A2 六字段语义（MUST-FIX C：S10 是独立信封，**不**从 `identityPubkeyXOnly` 推导 relay 身份）。

## §4 依赖
- **节点 / 广播**：**不需要**。全部是 DB + 密码学（kaspa-wasm signMessage/verifyMessage）+ 同事务 CAS；与设计 P4 一致（远端验证 payload 自足，不联系 relay）。IBD 期即可实施与测试（临时库真迁移）。
- **Owner 决**：**需要**——协议层身份定义（S10 信封 = wire protocol）+ 新表 v198 + A2 注册加硬拒因 = 重大功能，铁律 0；D-011 口径下"批"在方向层：Owner 批 §10 v1 落地方向，逐 commit 走内部双审（NWT 红队 + J1 审席/供数）。
- **J1**：golden vectors 第二实现在 J1 侧（(547)）；#2 对拍以 `artifacts/…v1.json` 为锚，落地后请 J1 用它的实现复验一次 signed_message（跨节点独立算力）。
- **Codex**：设计层已 CLOSED；实现层报备须让"真验证器跑 §6 的 1-13 负测"（memory 明列）⇒ §2 的 N 臂 + M 臂全绿后经桥送 Codex。
- **前置**：§6-1 E2E（KANet-UI 今晚）与本计划**不互斥**：E2E 走的是 v1 前的路径（无 `s10`），其证据作用域已标"plumbing 通 ≠ LIVE"；v1 落地后 E2E 要**再跑一次**（带 `s10`），那次才是"⑦ 已关"的运行证据。

## §6 明列不做 / 风险
- **rotate/revoke/迁移**：不含（设计 §7）。已注册 pubkey 换钥 = 新身份，旧行留着；这是已知空白不是漏。
- **P2 根治**（全部 7 个 `ecdsa_sign` 生产者统一域标签）：不含，单独立项；v1 依赖"今天无人产 `KANET-U1-IDENTITY-v1|` 前缀"这一实核事实。
- **同机信任模型**（P2 作用域）：同机调用方能请求任意域的签名——这在已接受的 N2 模型内；本计划不宣称关掉 loopback 内的一切。
- **地址派生一致性**（P6）：绑定用 `XOnlyPublicKey.fromAddress(relay_nodes.address)`；若某 relay 行的 address 与其助记词不一致（escape-hatch 那类症状），绑定会拒——这是**正确的拒**，runbook 已要求注册前跑 escape-hatch 检查。
- **测试面**：三份既有 u1 测试都要补 `s10` 夹具；漏一份就是"改了路径没改观察量"（规则 69），C3 的 NWT 审点专列。
