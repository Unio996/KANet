## 功能需求

### 4.1 fee 明示 — buildOrderConfirmText + createOrder 落库
老客户发 "买 50 KAS" 走到报价确认时, 订单文本要明示:
```
=== 订单确认 abc12345 ===
买 50 KAS (市价)
汇率: 0.034 USDT/KAS
你付: 1.7 USDT (BSC) → Maker 直收 0x...
扣 0.1 KAS 撮合服务费 (Broker 内部结算, 不用你单独转)
实到: 49.9 KAS (到你 Kasia 地址 ...xyz)
...
```

createOrder 时读 retail_dex_broker_config.fee_kas_per_order (默认 '0.1'), 计算:
```js
broker_fee_kas = fee_kas_per_order  // 默认 '0.1'
net_delivery_kas = qty - broker_fee_kas  // '49.9'
```
setField 两个字段到 retail_dex_orders (T1 已加这俩字段).

第一次用户: broker config 行不存在 → 默认 0.1 KAS. 不自动 INSERT.

### 4.2 余额前置校验 — dialog.js interpret
LLM 返 ready=true 之后, createOrder 之前:

```js
const { getTokenBalance } = await import('./chain-balance.js');
const { order } = validation;  // side/qty/pay_chain/pay_address
if (order.side === 'buy_kas') {
  // 查用户 EVM 地址上的 USDT
  const chainCode = normalizeChain(order.pay_chain);
  const r = await getTokenBalance(chainCode, order.pay_address, 'usdt');
  if (r.error && !r.error.startsWith('no_')) {
    // 查询失败给友好提示, 不拦 (fail-open, 让用户试)
    console.warn(`[retail-dex-dialog] balance check failed: ${r.error}`);
  } else {
    // 算需要的 USDT (qty * midPrice 估算, 没 offer 时用市价)
    const midPrice = snap?.midPrice || 0.034;
    const needed = parseFloat(order.qty) * midPrice;
    if (r.balance !== undefined && r.balance < needed * 0.99) {  // 1% tolerance
      return {
        ready: false,
        reply: `你的 ${order.pay_chain} 地址 0x${order.pay_address.slice(2,8)}... 当前 USDT 余额 ${r.balance.toFixed(4)}, 不够付 ${needed.toFixed(2)} USDT (买 ${order.qty} KAS 约需). 建议: 1) 先充值 USDT; 2) 改小数量 "买 X KAS" (X 是你能付的上限).`,
        validation_error: 'insufficient_balance',
      };
    }
  }
}
// 通过 → 继续返 ready: true
```
