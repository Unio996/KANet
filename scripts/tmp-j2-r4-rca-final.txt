## 真根因

relay-manager.js sendCommandAsync (line 241):
```js
resolve(msg.result || {});  // ← 失败时 result = { error: '...' } 或 {}, 不 reject
```

NWT broker-action-queue executeAction → sendCommandAsync 拿到 `{ error: '...' }`. NWT pump 检查:
```js
if (result?.ok === false) throw ...  // ← `ok` 不在, 检查 false → 不 throw
```

→ queue 静默接受失败为成功. 标 "OK -" (txId 不在). 不 retry. dm_pay_instr 真没发. Martin 0 inbound.

## NWT 假设 (循环) 错

- relay-manager.js 没被 J1 #C 改 (我 grep 0 引用 BROKER_RELAY_ID)
- broker-action-queue.executeAction 直接 import relay-manager sendCommandAsync, 不经 wrapper
- 没循环

## J1 假设 (relay 内失败但 ok=true 上报) 对

实际是 relay 失败但 sendCommandAsync resolve `{error}` (不是 throw, 不是 {ok:false}). 同等问题.

## Fix (~5 LOC, NWT broker-action-queue.js)

executeAction 内:
```js
const result = await sendCommandAsync(...);
if (!result?.txId && (item.kind in TX_PRODUCING_KINDS)) {
  throw new Error(`no txId returned: ${result?.error || 'unknown'}`);
}
return result;
```

或者检查 `result?.error`:
```js
if (result?.error) throw new Error(result.error);
```

加 retry 触发 + chain_event drop 标记 (Q4).

TX_PRODUCING_KINDS = `['accept_v1', 'paid_v1', 'dm_quote', 'dm_pay_instr', 'dm_completion', 'dm_position', 'sendKas', 'sendUsdt']` — 全 broker action 都需 txId.
