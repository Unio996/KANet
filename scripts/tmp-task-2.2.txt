### 改 1: handleDm aligning 分支 — 字段齐后的流程重写
原: nextMissingField 返 null → quoteAndMaybeConfirm 调 computeQuote (旧签名)
新流程:
1. 字段齐后 先调 selectBestOffer(order) → offer
2. offer 为 null → 返 '当前无匹配挂单 (链/qty 不匹配)，稍后再试'，订单保留在 aligning
3. 有 offer → 调 computeQuote(order, offer, brokerRelayId)
4. computeQuote error → 返 friendly + 订单保留
5. computeQuote ok →
   - setField(id, 'quoted_usdt', quoted_usdt)
   - setField(id, 'agent_pay_addr', maker_pay_addr)  // 字段名不改，存 Maker 地址
   - setField(id, 'mid_price_at_quote', String(mid_price))
   - setField(id, 'exchange_offer_id', offer.id)    // 已有字段
   - preCheck (原样调用)
   - !ok → buildOrderConfirmText 返失败
   - ok → updateState(id, 'confirming') + buildOrderConfirmText 返成功文本

### 改 2: confirming 分支 — YES 时广播 accept_v1
原: YES → updateState(awaiting_payment) 就返
新: YES → 先广播 accept_v1, 成功后才转态

广播 payload:
```js
const acceptPayload = {
  t: 'kanet_exchange_accept_v1',
  offer_id: order.exchange_offer_id,
  taker: brokerAddress,                      // 从 relay_nodes 查 brokerRelayId 的 address
  taker_chain: normalizeChain(order.pay_chain),
  payment_asset: 'usdt',
  verification_meta: {
    receive_address: order.user_kasia_address  // 关键: Maker delivery 直发用户
  }
};
```
发送 (复用现有工具，在 retail-dex.js 顶部 import):
```js
const { sendCommandAsync } = await import('./relay-manager.js');
const bcastRes = await sendCommandAsync(brokerRelayId, {
  type: 'send_broadcast',
  channel: 'kanet-exchange',
  message: JSON.stringify(acceptPayload),
});
if (!bcastRes?.txId) return '挂单失败: accept 未上链 (稍后重试)';  // NO TX NO STATE CHANGE
updateState(id, 'awaiting_payment', { accept_tx: bcastRes.txId });
```
(accept_tx 字段: **本 task 不加 migration**, 用已有 pay_tx_hash 字段不合适 — 直接存 accept_tx 为 extraFields, updateState 里已支持任意字段, 但 DB 列没这个 → 会 SQL 错. 所以本 task accept_tx 先写 error_reason 或者直接不存, 下一 task 再加列. **选: 暂存到 console.log, DB 不记, 下 task 补**)
修订: updateState(id, 'awaiting_payment') — 不带 accept_tx, 但 log 记 tx. 下 task 加字段.
