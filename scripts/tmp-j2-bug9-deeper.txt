## 根因 (修订)

**anti-spam 不是 5s 窗口, 是 14min+ "100% similar"**. 之前我说 5s 错.

broker dm_quote 文案:
```
📋 买 25 KAS 报价:
· 单价 0.034246 USDT/KAS
· 你付: 0.856 USDT (BNB)
· Maker 收款 ...
确认回 YES (5min 内). 取消回 NO.
```

同 offer 同 qty → 同文案. R4 BUY retry 用同一 offer 8efa5740 (Qwen 25 KAS / 0.85 USDT BNB) → 报价文案跟 14min 前 (T-NWT-12 测试时 R4 retry 3) 100% 一致. anti-spam 直接拦.

## NWT T-NWT-12 (RETRY_BACKOFF 6s) 不解此问题

6s backoff 跳的是 **同 sendCommandAsync 内** 短窗口 retry. 14min "100% similar" anti-spam 是**跨 session** dedup. 加 retry backoff 不论多长都不解 (内容一样).

## 真治本

文案加唯一标 (~3 LOC, 改 broker-buy-handler 的 _qDm 调用文案):

```js
const ts = new Date().toISOString().slice(11,19);  // HH:MM:SS
const orderHash = randomUUID().slice(0,4);
_qDm('dm_quote', peerAddr,
  `📋 买 ${qty} KAS 报价 [${ts} #${orderHash}]:\n...`);
```

每次 broker DM 内容含 timestamp + 4 字符 order hash → 永不 100% similar.

或简单些: 文案末尾 append `(询价 #${randomUUID().slice(0,8)})` 即可.
