## Bug #1 (核心 — 必修)

chain-balance.js 的 _solBalance:
```js
const rawAmount = accountInfo.data.subarray(8, 16);       // 错! SPL amount 在 offset 64-72
const balance = Number(BigInt.asUintN(64, rawAmount));    // 错! asUintN 不接受 Uint8Array, 会 throw
```

SPL Token Account 164 字节布局:
  0-32: mint (32B)
  32-64: owner (32B)
  64-72: amount (u64 LE, 8B) ← 这里
  72+: delegate/state 等

**修法 A (干净)**: 用 @solana/spl-token 的 getAccount()
```js
const { getAccount } = await import('@solana/spl-token');
const ata = await getAssociatedTokenAddress(mint, owner, false);
try {
  const acc = await getAccount(connection, ata);
  return { balance: Number(acc.amount) / 10**token.decimals, decimals: token.decimals, tokenAddress: token };
} catch (err) {
  if (err.name === 'TokenAccountNotFoundError') return { balance: 0, decimals: token.decimals, tokenAddress: token };
  throw err;
}
```

**修法 B (手读)**: offset + Buffer 正确读
```js
const buf = Buffer.from(accountInfo.data);
const amount = buf.readBigUInt64LE(64);  // offset 64
return { balance: Number(amount) / 10**decimals, ... };
```

选 A, 简洁不易错. 注: SOL_TOKENS 当前是 mint string map, decimals 需要从别处拿 (USDT SPL decimals=6, USDC=6). 硬编码或查 cross-chain-verify.mjs 拿.
