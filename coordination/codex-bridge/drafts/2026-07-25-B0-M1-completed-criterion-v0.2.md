## 1. 定义：`completed` 的唯一链上充分条件

对一次结算 `S`，应产生 `n` 笔付款输出 `{(txᵢ, addrᵢ, amtᵢ)}`。

> **`S` 可标记为 `completed`，当且仅当下列六条【全部】成立：**

| # | 条件 |
|---|---|
| C1 | **存在且绑定**：活 UTXO 集中存在 entry 满足 `outpoint.transactionId == txᵢ` |
| C2 | **深度**：`virtualDaaScore − entry.blockDaaScore ≥ REORG_SAFE_MIN_DEPTH`（当前 20） |
| C3 | **金额**：该输出 value `== amtᵢ`（逐笔，非总额） |
| C4 | **收款方**：该输出地址 `== addrᵢ` |
| C5 | **fail-closed**：查不到 / `blockDaaScore` 缺失 / 深度不足 —— 一律判未落地 |
| C6 | **完整性**：`n` 笔**全部**满足 C1–C5。部分成功 **≠** `completed` |

### 1.1 反面（DoD-2）— 🔴 v0.2 改：逐条对齐卡原文，不增不并

> 卡 §8.7 DoD-2 原文：「数据库状态不得仅因 **synthetic**、**预期 txid**、**提交成功**或 **UI 推断**进入完成」

| 卡的禁项 | 本规范的对应条款 | v0.1 的问题 |
|---|---|---|
| **synthetic** | 任何由测试夹具、mock、种子数据产生的 tx/输出，不得进入完成判定 | 🔴 v0.1 **完全没有这一条** |
| **预期 txid** | **广播之前**自行计算/预测的 txid，不得作为完成依据 | 🔴 v0.1 写成了「submit 返回的 txid」——**两者不是一件事** |
| **提交成功** | `submitTransaction` 返回、或调用未抛异常，不得作为完成依据 | ✅ 对上 |
| **UI 推断** | UI／上游声称完成，不得作为完成依据 | ✅ 对上 |

**➕ 本规范额外增加（v0.1 有此条但未标注为新增，此处补标）**：
- **DB 自证**：`protocol_status` 等字段已是 `completed`，**不得**作为它自己成立的依据。
  依据：`bshard-auto-settler.mjs` 闸③注释逐字「**不信 DB 的 `protocol_status` 字段本身**」。

> 🔵 **v0.1 那处最难看的地方是条数相同**：卡四条、我四条，一眼像逐条对应，**而实际只对上两条**。
> ⇒ 教训进规范：**对齐清单时先做映射表，不靠条数相同自证。**

## 2. 状态判定 — 🔴 v0.2 改：三态拆成四态

**分界线不是「结果长什么样」，是【我看没看见那笔 tx 的输出集】。**

| 态 | 何时 | 处置 |
|---|---|---|
| **confirmed** | C1–C6 全过 | 写 `completed` |
| 🔴 **misdirected** | 拿到该 tx 的输出集，而其中**没有**期望的 recipient | **不进重试预算** · 直接终态 · 立即告警 |
| **contradicted** | 拿到 recipient 那条输出，而金额 ≠ 期望 | 同上：不重试 · 终态 · 告警 |
| **inconclusive** | 拿不到该 tx 的输出集（索引无行 / JSON 坏 / 深度不足 / 查不到） | 兜底重查 → 预算耗尽 → fail-closed |

🔴 **v0.1 的缺陷（NWT 红队①）**：`misdirected` 被并进 `inconclusive`，于是**「钱付给了陌生人」拿到了「查不到」的处置**——
重查 N 次再 fail-closed。**重查对「查不到」是对的；对「付给了别人」毫无意义，而重查期间告警被推迟，钱已经没了。**
> **两态合并的代价不是「分得不细」，是【其中一态必然拿到错的处置】。**

### 2.1 🔴 `misdirected` 的可判性 —— 它不是无条件的

| 路径 | 可判性 | 依据 |
|---|---|---|
| 经 RPC | 🔴 **不可判** | 无 `getTransaction(txid)`；`getUtxoReturnAddress` 只回一个地址；`IUtxoEntry` 无 `blockHash`（三条我自读 `kaspa.d.ts`） |
| 经本地 `kaspa_tx_log` | 🟡 **条件可判** | `outputs_json` 存**全量**输出 ✅；但 `if (!matchedRecipient) continue` 会**整笔跳过**没碰到 watched 地址的 tx |

🔴 **⇒ 因此本规范对 `misdirected` 附一条前置不变量，而非把它当无条件可判：**

> **【不变量 I1】** 凡参与结算的地址（收款方、broker、找零）必须全部在 indexer 的 watched 集合内。
> **否则 `misdirected` 在该路径上静默退化为 `inconclusive`，而使用者不会察觉这个退化。**

🔴 **【I1 当前由什么满足 —— 而这一点必须写出来】**：结算 tx 的输出是 `[{winnerAddr,…},{brokerAddr, brokerFee}]`，
broker 是一个 relay ⇒ 其地址在 `relay_nodes` ⇒ 在 watched 集内 ⇒ 该 tx 几乎总会入库。
> ⚠️ **即：让错付可被发现的，不是任何为可观测性所做的设计，而是「我们恰好收了一笔手续费，且收款方是自己人」。**
> **任何一次简化（免掉 broker fee／fee=0 不出该输出／换成非 relay 的收费地址）都会静默废掉本判据。**

### 2.2 四场景 → 判定 — 🔴 v0.2 改：判定栏只写我的判据产生得出的东西

| 场景 | v0.1 判定 | 🔴 v0.2 判定 |
|---|---|---|
| 链上已生效但 DB 未确认 | confirmed | **confirmed**（以链为准，DB 补写） |
| DB 显示完成但链上未生效 | contradicted | **contradicted** |
| tx 落地后立即被花 | ~~confirmed~~ | 🔴 **inconclusive（以现有 C1）** —— C1 查活 UTXO 集，被花后查不到。**要判 confirmed 需历史源，而 §2.1 已证 RPC 侧不存在该源。** |
| 索引永久漏记 | inconclusive | **inconclusive → 直连 RPC 兜底**（不得判 confirmed-absent） |

🔵 **v0.1 的缺陷（NWT 红队③）**：判定栏写 `confirmed`，而**括号里我自己写着「被花后查不到」**——
**我把矛盾写进括号，却让判定栏留着我给不出的答案。限定写在括号里 = 没写，读的人取的是判定栏。**

## 4. 该判据自身依赖【约定】而非【结构】的四处

| # | 处 | 依赖的约定 | 漏了会怎样 |
|---|---|---|---|
| A | `checkUtxoLanded(…, minDepth = 0)` | 调用方记得传 20 | 静默退回 first-seen 浅确认 = 它当初要根治的 phantom-leaf |
| B | `verifyClaimLanded(…, expectedAmount = null)` | 调用方记得传金额 | 只验落地不验金额 |
| C | `_checkLandedViaRelay` 的 `if (j.landed \|\| j.found)` | relay 响应**当前不含 `found`** | 谁给响应加 `found`（通常视为向后兼容）⇒ Bug 7 从闸自己的后门回来（**【转述·来源 NWT】**） |
| 🔴 D | `misdirected` 的可判性 | 结算 tx 中**恰好有一笔付给 watched 地址的输出** | 见 §2.1：判据静默失效 |

**四处当前全部无害** —— 而无害的原因都是「没人漏／没人加」，**不是结构保证**。⇒ 全部进 DoD-5 负测试。

## 6. 本版的形成过程（保留，因为每一步都推翻了上一步）

```
v0.1 交付 → NWT 三条红队
  ① 付错人与查不到同态
     → 我提 misdirected 四态
     → 我自己发现它需要「完整输出集」
     → 🔴 查 RPC：拿不到 ⇒ 我说「判不出来」
     → 🔴 过强，收回：本地索引 outputs_json 存全量
     → 而 `!matchedRecipient continue` 会整笔跳过
     → 🔴 而结算 tx 有 broker fee 输出 ⇒ 几乎总入库 ⇒ 可判，严重性降
     → 🔴 而让它可判的是一个与可观测性无关的设计 ⇒ 落成不变量 I1
  ② DoD-2 四来源没 1:1  → 回卡原文逐条比 → 映射表（§1.1）
  ③ §2.1 判据产生不出那个判定 → 判定栏改 inconclusive（§2.2）
```

🔵 **三条红队的共同形状（我自己的诊断）**：**都不是「我算错了」，是【我把一个我知道的限定，放在了读的人不会取的位置】**——
①放进了另一个态里，②靠条数相同掩盖了缺失，③放进了括号。**我三次都知道那件事，三次都没让它出现在结论位。**
