# KANet 加密 DM 信封配方（外部实现者用）

- 面向：想给某个 Kaspa 地址发一条**加密点对点消息**的外部程序
- 范围：**只写构造一条 DM 所需的字节**。不是完整协议规范。
- 状态：设计/文档。对应端点 `POST /api/v1/dm` **尚未落码**。

---

## 0. 一句话

一条 KANet DM 就是**一笔普通的 Kaspa 交易**：输出付给收方地址，payload 字段里放一个约定格式的加密信封。

**你自己签名、自己付费。** KANet 不代签、不代付、不发凭证 —— 你能花掉某个地址的 UTXO，就证明了你是它。

---

## 1. 三步

### ① 加密（只需收方地址，不需要任何秘密）

```
ephemeral = 随机 secp256k1 密钥对
shared    = ECDH(ephemeral.private, 收方pubkey)
key       = HKDF-SHA256(shared, salt=空, info=空, 32 B)
nonce     = 随机 12 B
ct, mac   = ChaCha20-Poly1305(key, nonce).encrypt(明文)      // tag 16 B

密文字节 = nonce(12) ‖ ephemeral.pubkey_compressed(33) ‖ ct(len(明文)) ‖ mac(16)
```

字节布局：

| 偏移 | 长度 | 内容 |
|---|---|---|
| `[0:12]` | 12 | nonce |
| `[12:45]` | 33 | 临时公钥，压缩格式（`0x02`/`0x03` 前缀） |
| `[45:-16]` | = 明文长度 | 密文（ChaCha20 流密码，不膨胀） |
| `[-16:]` | 16 | Poly1305 MAC |

### ② 套信封

```
信封 = "ciph_msg:1:comm:" + <alias> + ":" + base64(密文字节)
```

`alias` 是你自称的短名。**KANet 不校验它** —— 它不是身份，身份是交易签名。

### ③ 转成交易 payload

```
payload = hex( UTF-8( 信封 ) )
```

放进 Kaspa 交易的 payload 字段，交易输出付给**收方地址**。

## 2. 🔴 收方地址 → pubkey：这一格会让你静默失败

加密要用收方的 x-only pubkey，它编码在地址里：

```
地址 = bech32( prefix + [版本字节 0x00] ‖ [32 B x-only pubkey] )
```

🔴 **版本字节与 pubkey 必须先拼成字节串，再对整体做 8→5 位转换。**

不是「版本占一个独立的 5-bit 组 + pubkey 单独 8→5」。后者位对齐错开一格。

**为什么这一格特别危险 —— 它不报错：**

```
错了之后：地址仍然合法 · 加密仍然成功 · 交易仍然上链
        只是你把消息加密给了【另一把 pubkey】
        ⇒ 收方永远读不到，而两边都不会收到任何错误
```

⚠️ 本文档作者在写这份配方时**就是这样错的**，靠往返解密失败才发现。若只照格式表写而不跑一次往返，这一格会原样传下去。

**⇒ 自检方法：** 用你自己造的地址跑一次「加密 → 解密」往返。解不回来，就是这一格。

解析侧的实现（`kasia-relay/src/lib/crypto.mjs` `extractXOnlyPubkeyFromAddress`）是：去掉末 8 位校验和 → `convertBits(5→8)` → **丢掉第一个字节（版本）** → 32 B。你的构造必须是它的严格逆运算。

## 3. 可验证的例子

下面每一样都是用 KANet 仓库自己的代码实际跑出来的。**你可以自己解开它 —— 不需要相信本文档抄对了。**

```
收方私钥（一次性演示用，32 B hex）
  1111111111111111111111111111111111111111111111111111111111111117

⇒ x-only pubkey
  d95267f9abca69063ac564d53f3babe2fc13c4fc9258d8365413d18161e4eb1c

⇒ 地址
  kaspatest:qrv4yele409xjp36c4jd20em4030cy7yljf93kpk2sfarqtpun43cr3x37fqp

明文
  "hello from an external program"   (30 B)
```

交易 payload hex（288 hex 字符）：

```
636970685f6d73673a313a636f6d6d3a6578743a354a35374452354f386138514c36305441326d422b5975463032756c58364c31786d744f314d4e5059434770734f312f432f4d636d33476c4639626d61656c3843706765615a5a703958616d4d315463763930684a674137365976764f457857464e3637613559396d3138586e39337a4568534232757a4d2f513d3d
```

**怎么验：**

1. hex → 字节 → UTF-8，应当以 `ciph_msg:1:comm:ext:` 开头
2. 取最后一个冒号之后的部分，base64 解码
3. 用上面那把私钥按 §1 的逆过程解密
4. 应当得到 `"hello from an external program"`

⚠️ nonce 与临时公钥每次加密都是随机的 ⇒ 你自己加密同一句话会得到**不同的串**，而结构与长度一致。上面这一串是固定的、可被解开的那一份。

---

## 4. 收方节点怎么认出它

只比 payload 的 **hex 前缀**，不做 hex→utf8 转换：

```
COMM 前缀 hex = 636970685f6d73673a313a636f6d6d3a
```

## 5. 配方解决什么、不解决什么

| | |
|---|---|
| ✅ 解决 | 「我构造不出合法的 payload」 |
| 🔴 **不解决** | 「我发不出交易」—— 你仍然需要**自己有一点 KAS** 来付手续费 |

这两件事是分开的。测试网可从 faucet 获取。
