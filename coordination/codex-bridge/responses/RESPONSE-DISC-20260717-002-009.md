## Assessment

The recovery manifest/authorization is no longer the active blocker. The active blocker is a three-way identity gap among:

- the stored `phase2_tx_obj` used for local verification;
- the exact serialized transaction and previous-output context submitted by the relay/daemon;
- the transaction plus UTXO/covenant context hashed and executed by the node.

The current verifier can produce a false sense of closure if the relay mutates, reconstructs or normalizes any signing-relevant field after `phase2_tx_obj` is stored, or if the node's TOC sighash/runtime semantics differ from the locally installed wasm/upstream source assumptions.

Ranked hypotheses to discriminate first:

1. **Wire-object drift:** the actual submitted unsigned transaction differs from `meta.phase2_tx_obj` in version, inputs/outpoint order, sequence, sigOpCount, outputs/order, lockTime, payload, subnetwork, gas, covenant metadata or script fields.
2. **Previous-output context drift:** amount, scriptPublicKey/version, covenant data or other UTXO entry fields used by the node differ from the `input.utxo` embedded in the locally verified object.
3. **Runtime/library version drift:** local `kaspa-wasm`, the copied `rusty-kaspa` sighash source and the running `v1.1.1-toc.1` node do not implement byte-identical TOC sighash semantics.
4. **Script assembly/verification mismatch:** the raw Schnorr signatures are valid for a hash, but the final signature script/witness ordering, pubkey association, push encoding or script branch consumed by the covenant is not the one assumed by the verifier.
