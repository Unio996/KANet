## Independently verified facts

1. `getBlockAtDaa` is intentionally fail-closed after `MAX_WALK` exhaustion. The code walks backward from the current SPC tip, and when the deepest reached block is still newer than `deadlineDaa`, it throws rather than returning a wrong endBlock. The surrounding comments explicitly connect this path to terminal refund behavior. This confirms an active liveness boundary, not merely a theoretical pruning concern.
2. The legacy ZK `checkLanded` path treats presence of `tx_id` in local `kaspa_tx_log` as sufficient and then permits `reconcile` to write `protocol_status='zk_settled'` and `chain_settled:true`. In the reviewed code there is no depth/reorg proof in that check. Bettor's identified verification-before-terminal-state hole is therefore code-supported.
3. RESPONSE-001-001 correctly distinguishes personally verified anchors from broader gathered claims. Claims about the absence of a full restore drill, total evidence inventory, current affected value/user counts and pruning-point margin remain evidence requests until backed by a reproducible command, test artifact or repository path.

## Synthesis

Bettor's disagreement is mostly about ordering language, not the engineering root. `getBlockAtDaa` exhaustion is not a separate competitor to Evidence Continuity and Recovery; it is the highest-urgency manifestation of that same missing capability: a consensus-critical endBlock fact is not durably captured before the reconstruction window closes.

The recommended top priority should therefore be renamed and narrowed to:

> **Settlement Evidence Continuity and Recoverability — lead with endBlock capture and restore proof.**

This should precede further feature expansion, but it should not be treated as one large platform rewrite.

## Proposed implementation order

### Gate 0 — measure before scope

- Produce a read-only pruning-margin report for every non-terminal market: `deadline_daa`, captured endBlock status, oldest required evidence DAA, current pruning-point DAA and remaining margin.
- Run and record a restore drill against a disposable copy: backup `console.db`, restore into an empty environment, run integrity checks and prove at least one representative market can resume without editing canonical production state.
- Record exact scripts, hashes, row counts and failure points. A document claiming that backup exists is not a restore proof.

### Batch 1 — close the active liveness and terminal-state holes

- Persist canonical committee endBlock hash + DAA at first successful derivation, with provenance and idempotent conflict detection. Resume/settle must prefer the captured fact and fail closed on disagreement.
- Add pruning-point proximity monitoring for uncaptured endBlocks and NULL `side_lock_daa` records, using measured margins rather than an uncalibrated constant.
- Replace the local-table-only ZK `checkLanded` decision with the same depth-gated, reorg-aware relay/node verification used by the stronger path before writing `zk_settled` or `chain_settled:true`.

### Batch 2 — make recovery real

- Establish versioned database backup, checksum, retention and automated restore verification.
- Define which evidence is authoritative, reconstructible or permanently unavailable after pruning; do not label inferred state as chain-proven.
- Add a deterministic representative-market replay/resume test from restored state and retained receipts.

## Required acceptance evidence

- A test that simulates `getBlockAtDaa` becoming unavailable after endBlock capture and still reproduces the same canonical endBlock.
- A conflict test proving a mismatched recaptured endBlock fails closed.
- A reorg/depth test proving the legacy ZK path cannot mark `zk_settled` from `kaspa_tx_log` presence alone.
- A restore-drill artifact with database checksum, schema version, integrity result and resumed-market evidence.
- A measured blast-radius report replacing unverified aggregate value/user counts before those figures are used for prioritization or external reporting.

## Decision recommendation

Move `DISC-20260717-001` to `proposed_decision`, with the priority statement above. Implementation still requires normal design ownership, red-team review and explicit authority for any production-state or money-path action. The two immediate evidence requests are unchanged: measured pruning-point margin and a tested restore drill.
