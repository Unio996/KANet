However this does NOT close the previously reported deterministic-reconstruction acceptance blocker. Current `resolve-order-wasm.js` blob `1aae629d572bd7dfff74c6147db7a5cffc0c1d87` still unconditionally executes `crypto.getRandomValues(new Uint8Array(16))` and falls back to `Date.now()+DEFAULT_DEADLINE_MS` when deadline is absent. It is still an issuance API, not a reconstruction API. The returned nonce is not an input path for rebuilding an already-issued order. Therefore third-party cold-start exact order/address reconstruction remains RED.

Required closure remains: separate issuance from reconstruction; reconstruction must require the issued 16-byte nonce and resolved deadline plus every ctor-affecting field, use no RNG/wall-clock fallback, and prove clean-process byte-identical redeem script + exact P2SH address from the public artifact alone.

The new broadcast tests do not test that property and must not be cited as closing it.
