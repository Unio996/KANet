## Independent disposition

1. **F1 prepared-freeze bypass: CONFIRMED MUST / HOLD.** The reported control flow is internally consistent with the previously reviewed driver contract: pending build/broadcast can re-read freeze, while a persisted `prepared` intent is recovered through `resolvePrepared` and same-byte replay. If freeze is not re-read after landed/mempool reconciliation and immediately before replay, `prepare -> freeze -> next-tick replay` bypasses the durable freeze. Fix direction is correct: in `resolvePrepared`, preserve landed/mempool recovery first; before any replay, re-read durable freeze and HOLD with zero broadcast, zero rebuild/re-sign, and retained prepared bytes/expected txid. Regression must cover both first-send-after-prepare and crash-recovery replay.

2. **F2 grace compression: CONFIRMED MUST / HOLD.** Runtime substitution of `GRACE_MIN` for configured `GRACE_MS` changes dispute policy exactly in late-seal conditions. The accepted invariant remains: full configured grace plus close-pipeline margin must fit before the safe cutoff; otherwise freeze/refund. `GRACE_MIN` may validate configuration but must not authorize runtime compression.

3. **F3 fee-candidate asymmetry: NEW MUST.** Genesis/bet broadcast paths reportedly feed raw address UTXOs into `toFeeUtxoCandidates`, whereas settlement applies C1 filtering. This is a safety/availability inconsistency: poisoned/covenant/non-plain candidates can be selected outside settlement even if settlement itself is hardened. Do not solve F4 only inside settlement. Establish one shared fee-candidate eligibility function/policy used by genesis, bet, settlement, split/consolidate where applicable; fail closed on unknown facts/covenant status. Add parity tests proving identical candidate rejection across each funds-signing path.

4. **F4 reservation gap: CONFIRMED MUST, scope widened.** `inflightOutpoints=[]` does not reserve an input selected by a sibling intent in the same scheduler/tick. A tick-local reservation set (or a stronger durable equivalent) must be updated immediately when an input is selected/prepared and consulted by subsequent candidate selection. If genesis/bet can run concurrently against the same relay wallet, the reservation domain must cover them too, not only settlement. Tests must include two ready operations sharing the same best candidate: operation 2 must select another eligible input or HOLD; it must never serialize/broadcast a double-spend candidate.

5. **Refund evidence remains incomplete.** A harness-manufactured `refund_flip` accepted by simnet consensus proves covenant-path validity, not driver reachability or terminal refund execution. It therefore does not close the adverse Oracle arm. Acceptance still requires durable freeze -> zero close broadcast/replay -> driver-selected refund transition -> terminal refund/reclaim evidence under the actual production-shaped driver/schema.

The proposed fee-poison experiment is useful only after deterministic unit/integration parity tests exist; live poisoning should be treated as corroboration, not the primary proof. No production/mainnet funds-path deployment, signing/broadcast, relay funding, migration, restart, or autonomous settlement is authorized by this review.

**Disposition:** F1/F2 confirmed and implementation-required; F3 promoted to MUST; F4 confirmed and broadened to the shared relay-wallet concurrency boundary; adverse refund-driver arm remains OPEN. Production funds-path expansion remains HOLD.
